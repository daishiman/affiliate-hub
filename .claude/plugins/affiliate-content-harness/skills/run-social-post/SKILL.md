# 媒体へ展開する

出来上がるもの: `blog-content/<site>/posts/<campaign>.<medium>.json` 1 件。

## これは翻訳ではない

案件ブリーフの本文を短く切って各媒体へ流すのではない。**同じ主張を、その媒体の
読まれ方でもう一度書く。** 読まれ方は 6 媒体それぞれで違う。

- **blog** — 検索から来て、測った中身を確かめに読む。判断材料を全部置く場
- **x-long** — 流れの中で見出しに引っ掛けて止め、そこから読ませる。
  止めた読者はその場で読み切るので、**1 本で筋が通っている**必要がある
- **x-short** — 流れる速さは x-long と同じだが、枠が 280 字しかない。
  1 投稿 1 主張に絞るぶん、残した 1 つは言い切る
- **instagram** — 画像を見たあとに読む。押せるリンクが無いので、
  本文は**それ単体で完結**していなければならない
- **note** — 腰を据えて読む。ブログが商品を測る場、note が**判断の過程**を書く場
- **facebook** — 先頭 3 行だけが展開前に見える。結論を頭に置き、
  読む相手が実名の知人であることを前提に、誇張しない

同じ文章がこの 6 つで機能することはない。**この一覧は `apply-style-genome` が
「媒体差か文体のブレか」を切り分けるときの出典でもある**（`checkedAgainst`）。
媒体を足すときは、規則を `media-profiles.json` へ足すのと同時にここへも 1 行足す。
書かないと、その媒体に付いた指摘は全部「説明が確かめられない」になる。

一方で、**運ぶ主張は同じでなければならない。** 媒体ごとに書き下ろすと、
X では「38kPa」、Instagram では「40kPa」という状態が起きる。そこを分けるために、
文章は書き直し、主張は `claimRefs` で案件の番号を指す。

## 先に読むもの

1. `blog-content/<site>/campaign-brief.json` — 主張・根拠・導線の正本
2. `references/media-profiles.json` — **その媒体の規則**（長さ・見出し・改行・タグ・リンク可否・表記）
3. `templates/post.<medium>.json` — 手本（5 媒体ぶんある。同じ案件を 5 通りに書いた例なので、
   媒体をまたいで読み比べると「何を書き直し、何を揃えたか」が分かる）
4. `blog-content/<site>/articles/<slug>.json` — 既にブログを書いているなら、その記事

規則は SKILL.md に書いていない。`media-profiles.json` が唯一の正本で、
生成側（この skill）と検品側（`validate-media-post.mjs`）が同じファイルを読む。
片方にだけ書くと、**生成が通して検品が落とす**状態になり、書き手には理由が見えない。

## 全媒体で共通のこと

- **絵文字は使わない。** 装飾は記号ではなく、見出しの言葉そのもので表す
- **見出しは切り捨てない。** 上限を超えたら書き直して収める。切り捨てると核が消える
- **最初に読まれるのは先頭 30 字程度。** そこへ核を置き、残りを予告にする
- **`claimRefs` を必ず埋める。** 空だと、媒体をまたいだ食い違いを機械が見つけられない
- **新しい主張を思いついたら、先に案件ブリーフへ足す。** 順序を逆にすると、
  その主張だけ根拠の検査を通らない

## 媒体ごとに反転すること

| | ブログ記事 | SNS 投稿 |
| --- | --- | --- |
| 広告表記 | 本文に**書かない**（画面が自動で出す） | 本文に**書く**（誰も出してくれない） |
| 見出し | 常に markdown | `headingStyle` による。`none` の媒体では `#` がそのまま文字として出る |
| 改行 | 段落（空行） | `lineBreakRule` による。`context` の媒体は文節と句読点で折る |

`lineBreakRule: "context"` の媒体で折らないと、画面幅によって切れる位置が変わり、
読点の無い塊に見える。1 行 60 字を超えたら折る。

`linkAllowed: false` の媒体（Instagram）に URL を書くと、**押しても何も起きない文字列**が残る。
「リンクはこちら」も同じ理由で書けない。導線はブログ記事へ送る。

`headingStyle: "none"` の媒体では `title` そのものを持たない。管理用の名前のつもりで置くと、
投稿の先頭に出る。名前で呼びたいならファイル名で呼ぶ。

### `disclosureStyle` の 3 値

| 値 | 意味 |
| --- | --- |
| `inline` | 断りを本文の末尾に入れる。`disclosure` と同じ文字列が本文に無いと止まる |
| `linked` | 断りは置き、**詳細だけ**をリンク先へ預ける。リンクが無いと止まる |
| `none` | 導線が無いので不要 |

`linked` は「書かなくてよい」ではない。X 短文の 280 字を惜しんで落とすと、
表示義務そのものが消える。短くするのは構わないが、**「広告」と「アフィリエイト」の
2 語は残す**。片方だけだと、宣伝を含むのか報酬が入るのかを読者が区別できない。

## 書き順

### 1. 運ぶ主張を選ぶ

案件の `claims` から、この媒体で運ぶものを選び `claimRefs` に並べる。
全部運ぶ必要はない。X 短文なら 1〜2 件、note なら全件でもよい。

**選ぶ基準は文字数ではなく、その媒体の読者が何を知りたいか。**
X 短文で「体重帯で順位が逆転する」だけを運ぶなら、それが一番驚く事実だから選ぶ。

### 2. その媒体の形で書く

`media-profiles.json` の `minChars` / `maxChars` に収める。
下限に届かないのは「この媒体でこの投稿を読む理由が無い」状態なので、
測った状況か、外した選択肢を足す。切るのは経緯と前置きから。

### 3. 入りきらないときに何から削るか

上から順に削る。**下へ行くほど、削ると投稿の性質が変わる。**

1. **前置きと経緯** — 「3 年悩んでいました」。削っても失われるものが無い。

   **名前で引かない。テストで引く。** 「前置きと経緯」は例であって条件ではない。
   条件は「削っても失われるものが無い」で、実際に見るのは
   **`persona` のどのフィールドにも答えていないこと**である。
   文頭にあるから、時系列で前だから、という理由でここへ落とさない。
   「夜 10 時に回しても、二度目の連絡は来ていません。」は文頭付近にあるが、
   `jobToBeDone`（夜に回せる状態にしたい）へ答えている唯一の一文なので、ここには入らない。

   **保護対象リストに無いことは、削ってよい理由にならない。** 下限リストは
   閉じた集合ではない。リストに無いものを全部この 1 番へ落とすと、
   守るべきものが名前を持たなかっただけで消える
2. **根拠の出典名** — 「自社検証（2026-07-12）」。ブログ記事に書いてあるなら、そちらへ送れる
3. **測り方の条件** — 「室温 24 度、被験者 1 名、8 時間連続」。ここから先は代償がある。
   削ると数字が「どこかで見た数字」に落ちる。条件を全部削るくらいなら、**数字ごと落として
   定性的に書く**。中途半端に数字だけ残すのが一番悪い。

   **ただしこの項目には、削る前に見る一段がある。** 「条件を全部削るか、数字ごと落とすか」は
   条件が長いときの二択であって、**条件が数語で足りるなら足すほうが先**である
   （「42dB が 36dB に」→「脱水中に階下で測ったら 42dB が 36dB に」は 8 字）。
   数語で両立するものを、二択だと思って落とさない。

   **落とせない数字がある。** その数字が `persona.objection` への回答そのものだった場合
   （「どのくらい下がったのか書いていないレビューが信用できない」に対する dB 値）、
   落とした投稿は objection が名指ししている失敗例そのものになる。
   字数のために落とすと、収まっているだけで疑いに答えていない投稿になる。
   そのときは字数ではなく**媒体の選択のほうを見直す**
4. **幅を持たせた推測（`inference`）** — 「55〜60kg のあいだだと考えています」。
   削ると、断言していない部分が消えて、全体が断言に見える
5. **外した選択肢** — 「2 位以下は比較表に置いています」。削ると、選んだ理由が消える

**字数が足りなくても削らないもの（下限）:**

- **短所、または合わない条件を 1 つ。** これを削ると、褒めるだけの投稿になる。
  `objection`（買う直前に何を疑うか）へ答えていない投稿は、どの媒体でも読まれない

- **`jobToBeDone` への回答を 1 つ。** 「夜 10 時に回しても、二度目の連絡は来ていません。」。
  測定値は `objection`（本当に変わるのか）へ答えるもので、
  `jobToBeDone`（夜に回せる状態にしたい）へは答えていない。
  **両方に答えていない投稿は、数字が正しくても読者の用事を済ませない。**
  6dB 下がったことだけを書いた投稿は、「で、夜に回せるようになったのか」に誰も答えていない
- **結論の条件付け。** 「腰を最優先にするなら」「机の後ろに 68cm 取れるなら」。
  条件の無い結論は誰にも当たらない

- **導線の案内文。** 「測り方はブログに置いています。」。URL を押す理由を作る一文で、
  削ると本文に裸の URL が残る。URL 自体と同じく導線の一部であり、削る順序の 5 項目には
  入っていない。**枠が足りないなら、案内文を削るのではなく URL ごと本文の外へ逃がす**
  （`linkAllowed: false` の媒体と同じ扱いにする）。
  **ただし `disclosureStyle: "linked"` の媒体では逃がせない。** あの方式は広告表記の詳細を
  リンク先へ預けているので、URL を消すと表記の行き先が無くなり、検品が落とす。
  逃がせるのは `disclosureStyle` が `inline` か `none` の媒体だけで、
  `linked` の媒体で枠が足りないなら、次の一文（その媒体へ出すのをやめる）へ進む

この 4 つが入らない字数なら、その媒体へこの案件を出すのをやめる。
280 字に収めるために短所を落とした投稿は、収まっているだけで何も伝えていない。

### 4. 広告表記を入れる

案件が `disclosureRequired: true` なら、`disclosure` を書く。
`disclosureStyle` が `inline` の媒体では、**その文字列を本文にもそのまま入れる**。
JSON にあるだけでは投稿に出ない。

短くするのは構わないが、「広告」と「アフィリエイト」の 2 語は削らない。
片方だけだと、読者は「宣伝を含む」のか「買うと運営に報酬が入る」のかを区別できない。

### 5. 検品する

```bash
P=.claude/plugins/affiliate-content-harness
C=blog-content/<site>/campaign-brief.json

# その媒体の規則
node $P/scripts/validate-media-post.mjs --post <post.json> --campaign $C

# 広告表記
node $P/scripts/validate-affiliate-disclosure.mjs --campaign $C --post <post.json>

# 他媒体との食い違い（2 件以上そろってから）
node $P/scripts/validate-cross-media-consistency.mjs --campaign $C \
  --article blog-content/<site>/articles/<slug>.json --post <post.json>
```

3 本目が一番大事で、一番あとから効く。単体検品はどれだけ通しても食い違いを見つけない。

### 6. 中身を見てもらう

検品は形しか見ない。「その媒体で読まれるか」は `assign-social-post-reviewer` に渡す。

## 終わったら

媒体・字数・運んだ `claimRefs`・導線の有無・表記の入れ方を報告する。
横断検品を回したかどうかも書く。回していないなら、それは食い違いを見ていないということ。
