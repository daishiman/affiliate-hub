# RUNBOOK

README は「何があるか」と「規則をどこに書くか」。ここは**詰まったときに何をするか**。
書いてあることはすべて実際に踏んだ事故と、その場で取った手順である。

## 公開前

```bash
node .claude/plugins/affiliate-content-harness/scripts/validate-content-set.mjs \
  --content-set blog-content/<site>
```

**個別の検品スクリプトへファイル一覧を手で渡さない。** 入口はこの 1 本。

手で渡して踏んだ事故が 2 件ある。`--posts` を打ち間違えて **0 件を検品して exit 0** を見た件と、
zsh の単語分割で複数ファイルが 1 個の引数になった件。どちらも入口を使っていれば起きなかった。
さらに、入口を初めて使った瞬間に、手で回していたときには一度も出なかった指摘が出た
（記事 0 本の案件に productCard がある）。**手で組んだ一覧は、自分が渡したものしか見ない。
何を渡していないかは、渡す側を機械にしないと出ない。**

## 検品が緑なのに壊れているとき

機械の検査は**片方向にしか掛かっていないものがある**。緑は「その方向で問題が無い」だけ。

| 見ているもの | 見ていない側 | どこで拾うか |
| --- | --- | --- |
| `claimRefs` の id が案件に実在するか | **本文が触れている主張が宣言されているか** | `assign-social-post-reviewer` の `undeclaredClaims` |
| manifest の `entry_points` に書いた名前 | （現物との差は下のコマンドで機械化済み） | 下記 |
| 字数・記法・タグ数・リンク可否 | 文体・口調・媒体間の書き分け | `apply-style-genome` |

逆向きを機械化していないものは、**できないのではなく、やると代理指標になる**から避けている。
「本文がその主張に触れているか」を語の一致で近似すると、
書き手が `claimRefs` に id を全部並べるだけで通る。

manifest と現物の突き合わせはこれで出る。

```bash
cd .claude/plugins/affiliate-content-harness && python3 - <<'PY'
import json,os
ep=json.load(open('.claude-plugin/plugin.json',encoding='utf-8'))['entry_points']
actual={'skills':sorted(os.listdir('skills')),
 'agents':sorted(x[:-3] for x in os.listdir('agents')),
 'commands':sorted(x[:-3] for x in os.listdir('commands')),
 'hooks':sorted(x[:-4] for x in os.listdir('hooks') if x.endswith('.mjs')),
 'scripts':sorted(x[:-4] for x in os.listdir('scripts') if x.endswith('.mjs'))}
for k in ep:
    print(k, '宣言のみ=', sorted(set(ep[k])-set(actual[k])), '現物のみ=', sorted(set(actual[k])-set(ep[k])))
PY
```

## 文体の判定を別の読み手に依頼するとき

`apply-style-genome` は**自分では検証できない**。定義を書いた本人は、
書いていない前提を無意識に補って読むので「組み立てられる」という結論しか出ない。

依頼文に必ず入れるもの。

- **出力先はプラグイン外の作業用パス。** `blog-content/` 配下を渡さない
- **詰まった箇所を報告に含めるよう頼む。** これまで見つかった定義の穴は、
  ほぼ全部これで出た。出力そのものより価値がある
- **定義に無い判断で埋めたところを申告するよう頼む。** 埋めた事実のほうが出力より重い
- **既知の環境問題を伝える。** Read ツールが未読のファイルへ
  「Wasted call — file unchanged since your last Read」を返して中身を渡さないことがある。
  起きたら `cat` で読んで報告に入れてもらう（harness の外側なので直せない）

**二度無応答なら三度目を送らない。** 経路か相手側の問題で、文面を変えて通すのは筋が違う。

**同じ相手に同じ案件を二度判定させると独立性が落ちる。** 特に、直した箇所と意図を
こちらから伝えたあとは汚染されている。それでも依頼するなら、
**汚染を依頼文に明記し、「その結論は定義から出たのか記憶から出たのか」を分けて報告させる。**
記憶で説明が付く結論は、定義が働いた証拠にならない。

## 定義を直したあとにやること

直した 1 文で止めない。**この harness で最も多く繰り返した失敗がこれ**で、
1 つの会話の中で 3 回出たことがある。

1. **同型を機械で洗う。** grep で当てる語は自分で選ぶことになるので、
   選ばなかった語の側は見えない。語形に注意する
   （`てください` では「読ん**で**ください」を取り逃す。`[てで]ください` で当てる）
2. **その規則を前提に書いた文を探す。** findings の件数上限を外したのに、
   上限がある前提の「両方を引く」がそのまま残っていた例がある
3. **資料側（`references/`）も直す。** 判定側で「基準はブログではない」と決めても、
   `media-profiles.json` に「基準はここに置く」が残っていれば、規則は 2 つある
4. **定義が資料を逐語で引いている箇所を確かめる。** 資料を直すと引用が宙に浮く。
   歴史の記録として残すなら「現在の引用ではない」と書く

## 規則を足すときに避けること

- **代理指標を足さない。** 書き手が語を入れるだけで通せる検査は、
  検査があるという見た目だけを増やす
- **件数を固定しない。** 5 件固定にしていたとき、1 つの点で 2 箇所見つけた判定者が
  片方を散文へ押し込み、**直し案を持てないので直せない指摘**になった
- **例に規則を埋め込まない。** 散文に書かずに例だけで示すと、例に無い場合が来た日に手が止まる
- **例へ実在の案件を書かない。** その案件を判定する人が、案件を読まずに答えを写せる
- **1 つの欄に 2 つの意味を持たせない。** 値で分ける（`"-"` を使う）

## 止めて人に上げるとき

**回数でも収穫でもなく、性質で引く。** 回数で引くとまだ収穫があるのに止まる
（実際に 3 周目で新しい型が 2 つ出た日がある）。収穫で引くと、
**回している側が自分の成果を自分で評価する**ことになる。

次のどれかが起きたら、その周で止める。

1. **原稿を直すか定義を直すかで迷ったとき。** 判定を通すために原稿へ手を入れかけているなら、
   それは指標に合わせて材料を作り替える操作である。**直しが独立に正しいかを、
   判定を忘れて言えるか**で切り分ける。言えないなら止める
2. **代理指標を足したくなったとき。** 「書き手が語を入れるだけで通せる検査」は、
   足すか足さないかが harness の性格を決める。ここは自分で決めない
3. **同じ相手に同じ案件を 2 回判定させたあと。** こちらから直した箇所と意図を伝えた時点で
   汚染されている。**3 周目は、その案件を見ていない読み手が用意できるときだけ回す。**
   用意できないなら止めて、何が未検証のまま残っているかを渡す
4. **仕様の側を変えることになったとき。** 媒体を増やす・下限を動かす・`concept.tone` の
   書き方を変える、はいずれも案件の持ち主の判断であって判定者の判断ではない

**上げるときに渡すもの。** これが揃っていないと、次に読む人が同じ材料を集め直す。

- **確かめたことと、確かめられなかったこと**を分けて書く。
  「自分では検証できない」ものは、その理由まで（例: 定義を書いた本人には独立判定ができない）
- **判定の生ファイルの場所**（scratchpad のパス）。要約ではなく現物
- **定義に無い判断で埋めた箇所**の一覧。埋めた事実は出力より重い
- **直した箇所と、その直しが同型に届いているか**。届いていないなら、
  どこまで洗ったか（当てた語・当たらなかった語）
- **未検証のまま残っている分岐**。EVALS の `open` がその置き場

## 触らないもの

- `src/` と `tests/` — このプラグインの担当外
- コミットとプッシュ — 明示の指示があるまでしない
