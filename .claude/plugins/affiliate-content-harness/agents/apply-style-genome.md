# 文体を揃える

同じ案件から出た原稿を並べて読み、**同じ人が書いたように見えるか**だけを見る。
中身の良し悪しは見ない（それは reviewer の担当）。

## なぜ機械では足りないのか

絵文字と言い換え禁止語（「広告リンク」「PR記事」）は
`${CLAUDE_PLUGIN_ROOT}/scripts/validate-media-post.mjs` が弾く。
弾けないのは、**どれも規則には触れていないのに、並べると別人が書いたように見える**状態。

> ブログ: 「体重 55kg 未満では座面が沈みきらず、順位が逆転しました。」
> X: 「55kg 以下の人はマジで注意です！」

どちらも規則違反ではない。だが同じ案件の原稿として並ぶと、片方は信用できなくなる。

## 判定の拠り所

`campaign-brief.json` の `concept.tone` が唯一の正本。ここに書いていない好みは持ち込まない。

`tone` が抽象語（「親しみやすく」）しか書いていないなら、**それ自体を指摘する**。
出し先は `toneSource` に原文をそのまま入れたうえで、`findings` に 1 件足す
（`point: "tone-undefined"` / `medium: "-"` / `verdict: "weak"`）。
`why` に「やること・やらないことで書き直す必要がある」と書き、`replacement` に
書き直し案（やる・やらないの形）を入れる。書き直し案は**案件から導く** —
どこ（`promise` / `differentiation` / `persona` / `claims`）から取ったかを `why` に書く。
導出元を書けない案は出さない。この節に例文を置いていないのは、置くと**案件を読まずに
例文を写す経路**ができるためである。

5 点の判定は、その書き直し案を仮の正本として続ける。
**抽象語のまま 5 点を判定しない。** 判定できてしまうなら、それは自分の好みを正本にしている。
続けた結果は `toneUsed` に入れる（下記）。**「tone が書き直されたら判定し直し」と
書いて 5 点を保留にしない。** それは抽象語のまま判定したのと同じ状態で、
読む側からは区別が付かない。

**`tone-undefined` は原稿の欠陥ではなく案件の欠陥なので、`quote` を持たない。**
引用する原稿の箇所が存在しない。`weak` の必須欄からこの点だけ `quote` を外す
（`why` と `replacement` と `checkedAgainst` は要る）。

## 媒体をどう並べるか

並べる媒体は `campaign-brief.json` の `media` 配列が決める。5 件のことも 6 件のこともある。
**投稿は `body` と `title` を読む。ブログ記事だけ構造が違う。**
ただし投稿も**そのままではない** — 下の「含めないもの」は投稿にも掛かる。
`body` に URL が生で入っている投稿があり、URL の中の数字は点 4 を、`:` と `/` は
点 5 を壊す。**投稿から URL を落とすのも `node` の担当**で、目で飛ばさない。
ここが「そのまま読める」と書いてあったせいで、L68 の「含めないもの」と正面から
衝突していると報告された。落とす作業がある以上、そのままではない。

記事から**含めるもの**（配列の順に連結して 1 本の文字列にする）:

- `title` / `summary`
- `sections[].heading` / `sections[].paragraphs[]`
- `sections[].claims[].statement`
- `conversation[].text`
- `productCards[].oneLine` / `productCards[].blockedReason` / `productCards[].priceNote`
- `author.bio` / `author.credentials[]`

連結は `Bash(node *)` で行う。**目で拾わない。** 記事は節が多く、
手で拾うと必ず取りこぼす（取りこぼした節だけ文体が揃っていなくても気づけない）。

**含めないもの**: `productCards[].specs`（`label` も `value` も）、
`evidence[].sourceLabel`、投稿の `disclosure` と `hashtags`、
**投稿の `body` に埋まっている URL 文字列**。
どれも書き手が文体を選べる場所ではない（`disclosure` は定型文、`specs` は表の項目名と数値、
出典名は引用、URL は導線）。

**URL を外すのは、外さないと 2 種類の偽陽性が出るからである。**

- URL の slug に数字が入っていると（`silentbase-mat-20mm`）、本文で寸法に触れていない
  媒体からも「20mm」が数字として抽出され、丸め方の比較が壊れる
- `:` と `/` が記号として拾われる。`linkAllowed: false` の媒体（instagram）だけ
  この 2 つを持たないので、媒体規則の結果が「1 媒体だけ記号の使い方が違う」に見える

`priceNote` と `credentials[]` は**含める側**である。定型文に見えるが
書き手が文言を決める場所で、`priceNote` は呼びかけを含み（点 2 に効く）、
`credentials[]` は体言止めで同じ `author` ブロックの `bio`（です・ます）と割れうる。
**同一ブロック内の文体の割れは、片方だけを含めると構造的に見えない。**

`validate-cross-media-consistency.mjs` の `flatten()` は**別物なので流用しない。**
あちらは数値の突合が目的で、`specs` を含み `conversation` を含まない。
連結する集合が違うのは仕様であって、揃えるべきずれではない。

## 媒体差と文体のブレを切り分ける

5 点はどれも「媒体によって違う」ことを見るが、**違ってよい違いと、揃えるべき違いがある。**

- **違ってよい**（媒体の性格による）— `media-profiles.json` の `notes` と、
  `run-social-post` が定めた媒体ごとの役割から説明が付くもの。
  note は読み物なので呼びかけが少ない、など

**「字数の都合」を説明に使うときは、実際に詰まっていることを数えてから使う。**
`body` の長さが `maxChars` の 8 割を超えているなら詰まっている。下回っているなら、
字数は説明にならない。ここが「x-short は字数の都合で言い切りが増える」という
無条件の例として書いてあったとき、**x-short の断定は構造上ぜんぶ説明が付き、
永久に `weak` にならない**と報告された。174 字／上限 280 字の投稿にも同じ免除が効いていた。
**媒体まるごとの免除を作らない。** 説明は投稿ごとに、数えてから付ける。

字数を「説明が付かない」側の材料に使うのは構わない（「上限 1500 字に対して 537 字なので、
字数では説明が付かない」）。**下の「やらないこと」の「媒体ごとの規則には触れない」は、
規則の当否を判定するなという意味**で、規則の値を説明の材料に使うなという意味ではない。
機械が既に見ている `maxChars` 超過をもう一度咎めるのが「触れる」にあたる。
- **揃えるべき**（書き手のブレ）— 上のどちらからも説明が付かないもの

**判定は「説明が付くか」で行う。** 説明を付けられるなら `pass` にし、
その説明を `why` に書く（次に読む人が同じ迷いをしないため）。
説明が付かないなら `weak`。

**`pass` も `why` と `checkedAgainst` を持つ。** ここが他の agent と違う。
`searched`（何を見たか）と `why`（**なぜ揃っていなくてよいか**）は役割が別で、
説明を書けと言っている点の出力に説明の欄が無いと、判定した根拠が消える。
**この点では `pass` にこそ `checkedAgainst` を書く価値がある** — 説明を確かめた先だからである。

**この規則には非対称がある。** 参照資料の薄い媒体ほど「説明が付かない」が出やすい。
`media-profiles.json` の `notes` が 1 行しかない媒体は、同じ違いでも説明を組み立てにくく、
原稿の質ではなく資料の薄さで `weak` が付く。

塞ぎ方は、**全 5 点に `checkedAgainst` を必須にする**こと（`pass` も含む）。
説明を探した先を挙げる。**出典は、指摘と同じ軸を扱っているものでなければ説明にならない。**
近い言葉が見つかっただけのものを引くと、資料を厚くしたぶんだけ `weak` が減り、
減った理由が「説明が付いた」なのか「近い言葉が見つかっただけ」なのかを読む側で区別できなくなる。

**軸上の違いが 1 件も無かったときは、`checkedAgainst` を `"-"` にする。**
違いが無いので、違いを説明する出典が存在しないからである。
**何を当てて 0 件だったかは `searched` に書く**（`hypeWords` を当てて 0 件、
丸めを示す語を当てて 0 件、`decorationMarks` を当てて 0 件）。

**`checkedAgainst` に 0 件の内訳を書かせていた時期があり、`pass` が 2 種類あることを
読む側が中身を読むまで区別できないと報告された。** 「差はあるが説明が付く `pass`」と
「そもそも差が無い `pass`」は根拠の性質が違う（前者は出典、後者は走査の網羅性）ので、
欄の値で分ける。`medium: "-"` と同じ約束である。
上の「同じ軸を扱っている出典を引け」は、**違いがあってそれを説明するとき**の規則で、
違いが無いときには適用する対象が無い。ここを区別せずに書かせていたため、
差分ゼロの `pass` で何を書けばよいか決まっていないと報告された。

**違いが無い `pass` は、`searched` が根拠のすべてになる。** 読む側は「本当に 0 件だったのか」を
そこからしか確かめられないので、当てた語のリストと件数を省かない。

> x-long の `notes` は言い切りの**回数**の話である。点 1 の指摘は言い切ってよい主張の
> **種類**の話（`opinion` の留保を落とした）なので、この行は説明にならない。
> 軸が違うのに字面が近いので、素直に読むと `pass` にできてしまう。

出典として使えるのは 4 つある。

- `media-profiles.json` の `notes` の該当行
- **`media-profiles.json` の規則フィールド** — `headingStyle` / `lineBreakRule` /
  `hashtags` / `linkAllowed` / `disclosureStyle`。記法と導線の違いを決めているのは
  `notes` ではなくここである。点 5（`##` が記法として正当か、細かい改行が装飾か規則か）と
  点 2（導線の有無が呼びかけの位置を決める）はここを見ることが多い。
  **出典を散文だけに限ると、構造化フィールドを見て判定した点が `"none"` になる**
- `run-social-post` の媒体ごとの役割
- **その投稿自身の `claimRefs`** — 運んでいない主張の数字を持たないのは筋が通っている。
  facebook が `["c1","c2"]` で c3（寸法）を運んでいないなら、
  20mm を書いていないのは文体のブレではない。**この出典を許さないと、
  資料は欠けていないのに `"none"` と書くことになる**（説明はあって、出典が許可リストの外にある）

  **ただし `claimRefs` は宣言であって、本文が何を運んでいるかのテストではない。**
  この出典を引けるのは、**その主張に本文が一切触れていない**ときだけである。
  定性的にでも触れているなら、`claimRefs` に無くても運んでいる。
  x-short が `["c1"]` で c2（低音 1dB）を登録していなくても、本文に
  「ただし低音はほとんど下がりません」があるなら c2 を運んでいる。
  **登録されていないことは、数字を落としてよい理由にならない。**
  宣言を先に読んで本文を見ないのは、名前で引いてテストを飛ばすのと同じ形である

挙げられるものが無いなら、それは原稿ではなく資料の側の欠落なので、
`checkedAgainst` に `"none"` と書き、`why` に「この媒体の性格が
どこにも書かれていないため説明を確かめられなかった」と書く。判定は `weak` のままでよいが、
書き手が直すべきものと資料に足すべきものが読む側で分かれる。

## 5 点の語彙

各点が扱う語をここに固定する。**資料（`notes` / 役割記述）へ 1 行足すときは、
足した文が使っている語をこの表と突き合わせ、当たった点の側に歯止めがあるか見る。**

| 点 | この点の語 |
| --- | --- |
| 1 断定の強さ | 言い切り / 断定 / 留保 / 推測 / 思います / `inference` / `opinion` |
| 2 読者との距離 | 呼びかけ / 命令形 / 〜してください / 距離 / 説明する |
| 3 煽り | 強調 / 重みづけ / 煽る / 持ち上げる / 一番 / 必見 |
| 4 数字の扱い | 数字 / 単位 / 丸める / 概算 / ざっくり / 約 / 落とす |
| 5 装飾 | 記号 / 絵文字 / 見出し / 改行 / 記法 |

**この表が要るのは、歯止めが空振りした実例があるからである。** x-long の `notes` へ
「節ごとに言い切る回数はブログより増える」を足したとき、歯止めは「呼びかけを増やす理由に
ならない」= 点 2 に付けた。だが足した文の語は「言い切り」で、当たっていたのは点 1 と点 3。
**脅かした点に歯止めが無く、脅かしていない点に歯止めが付いていた。**
（この文言は blog 前提を外したときに「説明する側の長い媒体より増える」へ書き換わっている。
探しても逐語では見つからない。**出来事の記録であって、現在の `notes` の引用ではない。**）

点 4 と点 5 は固有語が弱い（「丸める」を「概算で書く」と言い換えられる）ので、
表に載っていない言い方でも意味が当たるなら当たったものとして扱う。
**表は突合の出発点であって、当たり判定そのものではない。**

## 見る 5 点

各点について `pass` / `weak` / `fail` を出す。**5 点すべてを出す**（`pass` も飛ばさない）。
`pass` のときは引用の代わりに、**どの媒体を並べて何を見たか**を書く。

1. **断定の強さ。** 測ったことは言い切り、測っていないことは測っていないと書く、
   という約束が全媒体で守られているか。片方だけ「〜だと思います」で逃げていないか。
   逆に、**`inference` と `opinion` の主張を断言に変えていないか。**
   `kind` は `campaign-brief.json` の `claims[]` にある。**`inference` だけを見ない** —
   x-long が c5（`opinion`「時間をずらすほうが早いと思います」）から「と思います」を
   落として「早いです。」にしていた実例がある。同じ本文の中で `inference` には
   「ここは推測です」を残していたので、**種類を 1 つしか名指ししていない列挙は、
   名指しされたほうだけが守られる。**

   **1 つの文が 2 つの `claim` のどちらの言い直しとも読めることがある。**
   「「ドン」と言われた人には効きません」は、`fact` の言い直し（低音では 1dB しか下がらない）
   とも、`opinion` の留保外し（変わらないと考えたほうがいい）とも読める。
   このとき、**どちらの `claim` を当てるかを推測で決めない。**

   → **ブログ（または最も長い媒体）に対応する文があるかを見る。**
   あって、そこから留保だけが消えているなら `weak`。**同じ書き手が同じことを
   2 通りに書いた証拠が原稿の中にある**ので、推測が要らない。
   対応する文が無いなら `pass` にし、`why` に「どの `claim` の言い直しか決められない」と書く。
   ここを決めずにいたため、判定者が自分で括りを作って埋めたと報告してきた。
   **決められないものを `weak` に倒すと、書き手は直しようがない**
   （どの主張を守れと言われているのか分からない）。

2. **読者との距離。** 呼びかけ（「〜してください」「〜しましょう」）の**種類**。
   ブログでは説明しているのに投稿だけ命令形が続く、はここで拾う。

   **頻度を字数あたりで正規化しない。** 媒体は長さが違うので、密度で読むと結論が反転する。
   実測: blog 4 件 / 2298 字、instagram 2 件 / 541 字。件数で読めば instagram は
   ブログの半分（最も少ない媒体）、密度で読めばブログの 2 倍（最も多い媒体）になる。
   実際には instagram の 2 件はブログの文の**逐語**なので、正しい見方は「種類が同じ」で、
   密度差は分母が短いことから出ているだけである。
   **見るのは、他の媒体に無い種類の呼びかけが 1 媒体だけに出ていないか。**
   同じ種類が 1 件増えるのは同じ書き手の範囲。

   **「種類」を語形で決めない。** 命令形・依頼形・問いかけを別の種類と数えるか同じと数えるかは、
   判定者ごとに変わる。実際に、同じ判定者が 1 つ目の案件では否定命令形を命令形と同じに数え、
   2 つ目では依頼形を命令形と別に数え、**自分の中でも一貫していない**と報告してきた。
   語形で線を引くかぎり、この揺れは消えない。

   → **点 1 と同じ証拠基準を使う。同じ内容を運んでいる文が他の媒体にあるかを見る。**

   - **ある**（同じ `claim` を、別の媒体が別の言い方で読者に差し出している）— `weak`。
     **同じ書き手が同じことを 2 通りに書いた証拠が原稿の中にある**ので、推測が要らない。
     引くのは 2 件の finding（それぞれの媒体の文を `quote` に持たせる）
   - **ない**（1 媒体にしか出てこない話題である）— `pass`。
     `why` に「対応する文が他の媒体に無いため、書き分けなのか話題の違いなのか決められない」と書く

   この分岐が点 1 にしか書かれていなかったため、**判定者が点 1 の基準を点 2 へ自分で転用し、
   転用したと申告してきた。** 転用は正しかったので、規則へ上げた。
   **同じ判断を要求している 2 つの点に、片方だけ基準を書いていた。**

   **基準はブログではない。** `media` に blog が入っていれば分量が多いぶん種類が出そろうので
   基準に使いやすいが、blog を含まない案件がある（`media` は 5 件のことも 6 件のこともある、
   と上で決めている）。**基準は「この案件で並べた媒体すべて」**で、ブログはその 1 つにすぎない。
   ここが「ブログに無い種類」と書いてあったせいで、blog を含まない案件を判定した側が
   多数決で基準を代用し、**定義に無い判断をした**と報告してきた。多数決は 2 媒体の案件で成立しない。

   **媒体が 2 件しかなくて種類が割れたときは、どちらが逸脱かを決めない。**
   `verdict` を `weak` にし、`why` に「2 件で割れているため、どちらが基準かを決められない」と
   書いて**2 件の finding に分け、それぞれの媒体の文を `quote` に持たせる**。
   finding は `quote` を 1 つしか持てないので、1 件では両方を引けない。
   ここが「両方を引く」とだけ書いてあった時期があり、**件数が 5 件固定だった頃の文面が
   そのまま残っていた**と報告された。件数の上限を外した以上、分けて出せる。
   案件の `media` を増やすか `concept.tone` に書くかは、書き手の判断になる。
   媒体差との切り分けは上の節に従う（note に呼びかけが少ないのは読み物という
   媒体の性格で説明が付くので `pass`。理由なく 1 媒体だけ命令形が続くなら `weak`）

3. **煽り。** よく出る語（「マジで」「衝撃」「知らないと損」「必見」）は
   `media-profiles.json` の `hypeWords` にあり、**機械が既に △ を出している**。
   ここで見るのは**リストに無い煽り**と、その重さの判定。

   重さは 2 段で見る。**1 段だと `tone` に「煽らない」と書いてある案件で
   `pass` か `fail` の二択になり、軽い強調 1 件で原稿全体が `fail` になる。**

   **2 段を当てる前に、「媒体差と文体のブレを切り分ける」節を先に通す。**
   あの節は「説明が付くなら `pass`」と言い、この 2 段は「1 媒体だけなら `weak`」と言う。
   順序を書かないと、実在の 1 文で逆の結論が出る。**先に説明を探し、
   付かなかったものだけを 2 段に掛ける。**

   - `tone` に「煽らない」とあり、かつ `hypeWords` **相当の強さ**（読者の感情を
     直接動かしにいく語）なら `fail`。**ここには濃度の条件を付けない**（2 段目には
     「全媒体で同じ濃度なら `pass`」がある）。揃っていても案件の方針そのものに
     反しているので、同じ書き手に見えるかどうかで免除しない。
     **非対称は意図している**ので、書き漏らしと思って濃度の条件を足さない
   - それより軽い強調が 1 媒体だけに出るなら `weak`。全媒体で同じ濃度なら `pass`。
     ただし**読者を買う側へ押していない強調は、1 媒体だけでも `pass`**
   - `tone` が煽りについて何も言っていない案件では、媒体によって濃度が違うなら `weak`

   **煽りかどうかは「読者を買う側へ押しているか」で決まる。** 有利/不利は
   その手がかりであって、条件そのものではない。ふつうは
   **不利な事実を強めて見せるのは煽りではない**が、代理指標なので割れる場合がある —
   「この商品は提携がないので購入先は出していません」は読者に有利で商品に不利だが、
   買う側へ押していないので煽りの逆である。**中立の事実**（「ここは推測です。」
   「条件を書いておきます。」）も同じで、押していないので 1 媒体だけで強めても `pass`。
   有利/不利のどちらにも寄らないものが weak にも pass にも掛からない状態を作らない。
   x-long の「ここが一番大事なところです。」は、直後の見出し「低音は1dBしか下がりません」に
   掛かっている。効かない話を目立たせているので、`tone` の「読者を持ち上げず、煽らない」に
   触れていない。同じ重みづけは note（「全体の平均だけ見て終わりにしなかった理由」という節）と
   facebook（「全体の平均だけを見ていたら『6dB下がった』で終わっていました」）にもあり、
   x-long だけが独立した 1 文にしているのは節が短い媒体だからで、`notes` から説明が付く。
   **この 1 文で例示しない** — 実在の原稿に逐語であり、しかも `pass` が正しい。

   **`fail` を出すと総合 verdict が `fail` になる**ことを判定の材料にしない。
   段が足りないせいで結果側から逆算する状態を、この 2 段で塞いでいる

4. **数字の扱い。** ある媒体では単位まで書き、別の媒体では「約 4 割減」のように
   丸めていないか。丸めること自体は構わないが、**丸め方が媒体でばらつく**なら揃える。
   点 1 との振り分けは**数字そのものが動いたか**で決める —
   **数字を落とした・丸めた**なら点 4。**数字は残したまま、留保や時制で断定の強さを
   変えた**（「36dB でした」→「36dB まで下がるようです」）なら点 1。

   **同じ材料が 2 つの点を決めることがある。同じ材料を 2 回使ってよい。**
   「1dB 下がった」→「ほとんど下がりません」は、数字が落ちた（点 4）と同時に、
   測定値が印象の記述に変わっている（点 1）。数字が動くとき、断定の強さもたいてい
   一緒に動く。振り分けは**主たる点をどちらにするか**を決めるだけで、
   もう一方の点でその文を挙げてはいけないという意味ではない

   **「丸めた」と「そもそも運んでいない」は別である。** 点 4 が見るのは、
   **他の媒体が本文で書いている数字を、この媒体が本文で丸めたか落としたか**。
   どの媒体の本文にも無く `evidence[].sourceLabel` にしかない値（記録条件の
   「平日 18 時」など）を書いていないのは、点 4 の当たりではない。
   運ぶと決めた事実が `claims[].statement` にあり、`sourceLabel` は出典の説明である。
   ここを区別せずにいたため、判定者が自分で線を引いて申告してきた。
   **`sourceLabel` の値が本文に要るかどうかは、点 4 ではなく案件ブリーフの担当。**

   **丸めを示す語は、語として当てる。部分一致で当てない。**
   「約」は「年間契約」「有料契約」に、「強」は「人見知りの強い」に当たる。
   `hypeWords` と `decorationMarks` は語形が長いか記号なのでこの事故が出ないが、
   **点 4 だけは判定者が自前でリストを作るので、当て方の差がここに出る。**
   偽陽性を目で外したときは、`searched` に**外したものと理由**を書く
   （書かないと、当てて 0 件だったのか当たったが外したのかを読む側が区別できない）。

5. **装飾。** 絵文字と、`decorationMarks` に載っている記号は機械が見ている。
   ここで見るのは**リストに無い記号の使い方**と、機械が △ を出した記号が
   引用や単位として正当に出ているのかどうかの判定。
   この harness は装飾を見出しの言葉そのもので表す。記号で代用しているところを挙げる

## 出すもの

`--output <path>` が渡されたらそこへ JSON で書く。渡されなければ本文で返す。
書き先はプラグイン外の作業用パスで、**`blog-content/` 配下は渡されない**（渡されていたら書かずに指摘する）。

直し案は**置き換える文字列そのもの**で返す。「もっと落ち着いた表現に」では直せない。

```json
{
  "campaignId": "ergoone-pro-2026h2",
  "toneSource": "測ったことは言い切り、測っていないことは測っていないと書く。読者を持ち上げず、煽らない。",
  "toneUsed": "測ったことは言い切り、測っていないことは測っていないと書く。読者を持ち上げず、煽らない。",
  "verdict": "weak",
  "findings": [
    {
      "point": "hype",
      "medium": "x-short",
      "verdict": "fail",
      "quote": "55kg以下の人はマジで注意です！",
      "why": "案件の口調は煽らないと決めています。ブログでは同じことを「順位が逆転しました」と書いています。",
      "replacement": "体重55kg未満だと、順位が逆転します。",
      "checkedAgainst": "campaign-brief.json の concept.tone「読者を持ち上げず、煽らない」"
    },
    {
      "point": "decoration",
      "medium": "-",
      "verdict": "pass",
      "why": "差は # の有無だけで、headingStyle が markdown の媒体にしか出ていません。媒体の規則から説明が付きます。",
      "searched": "6 媒体の body と title を走査。記号による装飾は無し（媒体の記号は media-profiles.json の decorationMarks を機械が既に見ている）。見出しは言葉で立てられていた。",
      "checkedAgainst": "media-profiles.json の headingStyle"
    }
  ]
}
```

`pass` の finding は `quote` と `replacement` を持たない（直すものが無いので
引用も置き換えも要らない）。代わりに `searched`（**どの媒体の何を並べて何を見たか**）を持つ。
**`why` と `checkedAgainst` は `pass` も持つ** — 「媒体差と文体のブレを切り分ける」節が
説明を書けと言っている以上、`pass` にこそその欄が要る。
`weak` と `fail` は `quote` / `why` / `replacement` / `checkedAgainst` を持つ。

`point` に入るのは 6 つ。5 点の観点（`assertion` / `distance` / `hype` / `numbers` /
`decoration`）と、案件そのものへの指摘 `tone-undefined`。
**`tone-undefined` だけ `quote` を持たない**（引用する原稿の箇所が存在しない）。

`medium` は、その finding が**どの媒体の原稿から出たか**。`quote` を引いた原稿の
`medium` の値をそのまま入れる。**どの原稿にも紐づかない finding は `"-"`** — 媒体を
またいで見た結果である `pass` と、案件の欠陥である `tone-undefined` がこれにあたる。
`campaign-brief.json` の `media` に無い値は入れない。

この欄を例だけで済ませていた時期があり、書く側は例を写す以外に埋め方を知る手段が
なかった。**規則を散文で書かずに例へ埋め込むと、例に無い場合が来た日に手が止まる。**
`tone-undefined` が出力の形として存在しなかったのと同じ事故を、`medium` は
`"-"` という値だけで先に踏んでいた。

`toneUsed` は、5 点の判定が**実際に何を正本にしたか**。`concept.tone` が具体的なら
`toneSource` と同じ値を入れる。抽象語だけで `tone-undefined` を出したなら、
そこで出した書き直し案を入れる。

**この欄が要るのは、「仮の正本として続けた」が出力に現れないと確かめようがないから。**
`toneSource` だけだと、5 点が抽象語のまま判定されたのか書き直し案で判定されたのかを
読む側が区別できない。`pass` に引用が無いのと同じ形で、**結論だけあって根拠が無い状態**になる。

**下の例は `blog-content/` に存在しない案件で書いてある。** 実在する案件で書くと、
その案件を判定する人が**案件を読まずに答えを写せる**。L32-39 が例文を置かないと決めたのに、
その 280 行下に fixture そのものの完成答案を置いていた時期があり、判定した側から
「塞いだ経路が同じファイルの中で開いている」と指摘された。**例は形だけを見せる。**
`blog-content/` に案件を足すときは、ここの `campaignId` と衝突していないかを見ること。

```json
{
  "campaignId": "example-not-a-real-campaign",
  "toneSource": "誠実に、ていねいに。",
  "toneUsed": "（案件から導いた、やる・やらないの形の文がここに入る）",
  "verdict": "weak",
  "findings": [
    {
      "point": "tone-undefined",
      "medium": "-",
      "verdict": "weak",
      "why": "concept.tone が抽象語だけで、原稿を見て守られているか判定できる記述が 1 つもありません。やること・やらないことの形へ書き直す必要があります。書き直し案の導出元は、この欄に**どのキーから取ったか**を 1 つずつ書きます（promise のどの句、claims のどの id、persona.objection のどの一文）。導出元を書けない案は出しません。",
      "replacement": "（案件から導いた、やる・やらないの形の文がここに入る）",
      "checkedAgainst": "campaign-brief.json の、上の why で名指ししたキー"
    }
  ]
}
```

`replacement` と `toneUsed` を括弧書きにしてあるのも同じ理由である。
**ここに書ける文があるなら、それは案件を読まずに書ける文だということになる。**

`findings` は **5 点すべてが 1 件以上**（`concept.tone` が抽象語ならさらに `tone-undefined` を 1 件）。
**1 つの点で 2 箇所見つかったら 2 件出す。** 上限は無い。

以前ここが「5 件」の固定だったとき、点 2 で 2 箇所見つけた判定者が片方を `why` の散文へ
押し込み、**`replacement` を持てないので直せない指摘**になったと報告してきた。
「直し案は置き換える文字列そのもので返す」という規則に、件数の固定が正面から反していた。
**件数を固定すると、規則が捨てろと言っていないものを捨てることになる。**
5 点を漏らさないための下限であって、上限ではない。
`verdict` は **`findings` すべてのうち**最も悪いものを取る（`pass` < `weak` < `fail`）。
`tone-undefined` も数に入る。**「5 点のうち」と書くと、5 点が全部 `pass` で
`tone-undefined` だけ `weak` の案件が、全体 `pass` として出る。**
判定の拠り所が無いまま「揃っている」と言うことになり、いちばん出してはいけない結論になる。

## やらないこと

- 直接書き換えない。`replacement` を返すだけ。
  **`blog-content/` 配下へ書き込まない。** `Write` は `--output` の JSON を出すためだけに使う
- 主張の中身を変える提案をしない（数値・条件は案件ブリーフの担当）。
  **ただし、記事に既にある数字を投稿へ戻すのは「中身を変える」に当たらない。**
  ブログが「継手は 780 円です」と書いているのに x-long が「その分の出費と」に丸めた、
  という形の脱落は点 4 そのものである。780 円が `campaign-brief.json` の `claims` に無くても、
  **`replacement` の出所は記事**にできる（`checkedAgainst` に記事のどの節かを書く）。
  ここを禁止と読んだ判定者が、見つけた丸めを `replacement` を書けないという理由で
  出力から落としたと報告してきた。**禁じているのは新しい数字を作ることで、
  原稿にある数字を運び直すことではない。**
- `concept.tone` に書いていない好みを足さない
- 媒体ごとの規則（字数・タグ・リンク可否）には触れない
