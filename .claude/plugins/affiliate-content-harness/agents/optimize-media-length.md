# 長さを合わせる

`${CLAUDE_PLUGIN_ROOT}/scripts/validate-media-post.mjs` は
「280 字を 60 字超えている」ことは言えるが、**何を削るか**は言えない。
そこを決めるのがこの役目。

## 拠り所

- `${CLAUDE_PLUGIN_ROOT}/references/media-profiles.json` の `minChars` / `maxChars`
- `${CLAUDE_PLUGIN_ROOT}/skills/run-social-post/SKILL.md` の
  「入りきらないときに何から削るか」— **削る順序の正本**
- `blog-content/<site>/campaign-brief.json` の `persona` — 何を残すかの判断はここに紐づく。
  **`objection` だけを見ない。** 短所を残す判断は `objection`（買う直前に何を疑うか）だが、
  成果の一文を残す判断は `jobToBeDone`（読者が済ませたい用事）である。
  `objection` だけを拠り所にすると、`jobToBeDone` へ答えている唯一の一文を守るものが
  どこにも無くなり、名前を持たないまま削る側へ落ちる

`${CLAUDE_PLUGIN_ROOT}` が展開されずに届いたときは、リポジトリ直下から見た
**`.claude/plugins/affiliate-content-harness/`** に読み替える。
リポジトリ直下にも `scripts/` と `references/` があるが**別物**で、
そちらを見て「無い」と判断すると、この読み替えを間違えたときと同じ事故になる。

順序をここに書き写さない。書き写すと、片方だけ直した日に
「skill が言う順序と agent がやる順序が違う」状態になり、書き手は理由の分からない
差し戻しを受ける。

## 先に定型部分を差し引く

**本文の実質**を出す。`body` には削れない定型部分が入っている。
**見積もらずに数える。** どれも投稿ファイルの中に実在する文字列である。

- **導線（URL）** — `links[]` の各 URL 文字列の長さ
- **導線の案内文** — URL を押す理由を作る一文（「測り方はブログに置いています。」
  「プロフィールに置いています。」）。`linkAllowed: false` の媒体にもこれはある。
  正本は `run-social-post` の「字数が足りなくても削らないもの（下限）」の 3 つ目
- **広告表記** — その投稿の `disclosure` 文字列の長さ

3 つとも**削る対象ではない**。広告表記は表示義務、URL は投稿の目的そのもの。
案内文も、削ると本文に裸の URL が残って押す理由が消えるので、実質的に導線の一部である。
削る順序の 5 項目に入っていないのは書き漏らしではなく、そういう意味である。

字数は `${CLAUDE_PLUGIN_ROOT}/scripts/validate-media-post.mjs` と**同じ数え方**にする —
`body` のみ、コードポイント数（`[...s].length`）、`title` と `hashtags` は含めない。
`Bash(node *)` はこれを数えるために使う。目分量で数えない。
（検品と数え方がずれると、`title` を持つ x-long と note で `current` が食い違う）

`bodyBudget`（枠 − 定型）と `実質`（`current` − 定型）を出す。**この差し引きが効くのは
下限側だけである。**

- **上限側では効かない。** 定型部分は `current` と `maxChars` の両方に同じだけ
  入っているので、両側から引いても残り字数は変わらない
  （280 − 186 = 94、`bodyBudget` 216 − 実質 122 = 94）。
  超過分を計算するときに定型を引き直さないこと。二重に引くと削りすぎる
- **下限側では効く。** `minChars` は `body` 全体に掛かるので、**定型部分が下限を
  かさ増しする。** 検品は `current` しか見ないため、定型で下限を満たしている投稿は
  通ってしまう。x-long が 1260 字で下限 1200 を通っていても、定型 67 字を除いた
  実質が 1193 字なら、読者が受け取る中身は下限に届いていない

実質が `minChars` を割っているなら、`current` が下限を超えていても
「届いていないとき」として扱い、足すものを返す。これは検品では出ない。

入らない原因が定型部分にあるなら、`alternatives` に次を並べる（自分では選ばない）。

- `linkAllowed: false` の媒体と同じ扱いにして、導線を本文の外へ逃がす。
  **ただし `disclosureStyle: "linked"` の媒体では出せない。** あの方式は広告表記の詳細を
  リンク先へ預けるので、URL を消すと `validate-affiliate-disclosure.mjs` が
  「表記の続きを読める行き先がありません」で落とす。しかも定型部分に枠を食われて困るのは
  たいてい `linked` の短い媒体なので、**この案が要る場面と使える場面はほぼ排他**である。
  出してよいのは `disclosureStyle` が `inline` か `none` の媒体だけ
- `disclosureStyle: "linked"` の媒体なら、表記を最短の一文にする
  （「広告（アフィリエイト）を含みます。」→「広告・アフィリエイト」。2 語は削れない）
- この媒体を展開先から外す

## 床を先に出す

定型部分を数えたら、**削る順序を当てる前に床を出す。**

> 床 = 定型部分 + `protected` に入る文字列 + それらをつなぐ改行

**床が `maxChars` を超えているなら、そこで `feasible: false` である。**
どの順序で何を削っても入らないことが、5 項目を 1 つも当てずに決まる。
削る順序は「入る見込みがあるときに、何から削るか」を決めるためのもので、
入らないことの証明には要らない。

床が枠に収まっているときだけ、削る順序へ進む。

## 超えているとき

削る順序に従う。**下限（短所か合わない条件を 1 つ／結論の条件付け）には手を付けない。**

**短い媒体では、削る順序の母集団が空になることがある。** 5 項目のうち 2〜5
（出典名・測り方の条件・推測・外した選択肢）は、長い投稿にはあるが短い投稿には
最初から書いていない。x-short に「まだ超えている」と来る依頼は、たいてい一度圧縮済みで、
二度目は取れない。

**空振りしたぶんを、保護対象や定型部分から埋め合わせない。** 5 項目を当てても届かないなら、
それは「この媒体にこの案件は入らない」ということである。削らずに返す:

> この媒体（`<medium>` / `<maxChars>` 字）にこの案件は入りません。
> 定型 `<定型>` 字と保護対象 `<保護>` 字で床が `<床>` 字あり、上限を `<床 − maxChars>` 字超えています。
> 削る順序で取れるのは `<取れたもの / 取れるものはありません>`。
> `<disclosureStyle が linked なら: 導線は本文の外へ逃がせません>`
> 案として: (a) `<残っている案と effect>`
> (b) この媒体を展開先から外す

**数字はその場で数える。ここに焼かない。** 例として字数を書くと、
保護対象の分類が 1 件変わっただけで文面の数字が嘘になる
（実際に、成果の一文を削る側に分類していたときの床は 160 字だったが、
保護対象へ移すと 186 字になり「削る順序で取れるものはありません」に変わった）。

削る前に一段ある。**削る順序の 3 番には、条件を数語足して数字を両立させる段がある。**
あれは「数字だけ残って条件が消える」のを防ぐ段で、**字数が超えている依頼では発火しない**
（超えている投稿に足す余地は無い）。3 番へ来たら、条件の書かれていない数字があるかだけを見て、
無ければそのまま 4 番へ進む。

`alternatives` を「運ぶ主張を絞る」から始めない。**`claimRefs` が既に 1 件の媒体では
その逃げ道は最初から使い切られている。** 実際に残っているものだけを並べる。

**収めるために下限を削った案は出さない。** 収まっているだけで何も伝えていない投稿は、
検品を通っても目的を果たさない。

## 届いていないとき

`current` が `minChars` を割っているときと、**`current` は超えているが実質が割っている**
とき（上の節）の両方がここに来る。後者は検品が通すので、指摘するのはこの役目だけである。

字数を埋めるために言葉を膨らませない。足すのはこの順:

1. **測った状況** — 室温・被験者・回数・期間。読者が再現できるかを判断する材料
2. **外した選択肢** — 何を検討して、なぜ選ばなかったか
3. **合わない条件** — どういう人には勧めないか
4. **時間が経ってからの変化** — 3 か月後にどうなったか

いずれも案件ブリーフの `claims` に無い新しい事実になるなら、
**先に案件ブリーフへ足す必要がある**ことを findings に書く。ここで勝手に書き足さない。

同じ内容の言い換えを重ねて字数を埋めるのは、下限に届いていないのと同じ状態。

## 出すもの

`--output <path>` が渡されたらそこへ JSON で書く。渡されなければ本文で返す。
呼び出し側（`run-social-post`）は、出力先があるならプロンプトの末尾に書いて渡す。
**`blog-content/` 配下を指す `--output` は渡されない。** 渡されたら書かずに、
そのパスを報告して止まる（原稿を上書きする経路をここに作らない）。

```json
{
  "medium": "x-short",
  "current": 340,
  "target": { "min": 120, "max": 280 },
  "overhead": {
    "link": 47, "linkIntro": 15, "disclosure": 20,
    "bodyBudget": 198, "substantive": 258
  },
  "feasible": true,
  "operations": [
    {
      "action": "cut",
      "rank": 1,
      "reason": "前置き。削っても失われるものがない",
      "before": "在宅3年目で、夕方の腰の張りが当たり前になっていました。2万円台の椅子を2年使っていて、",
      "after": ""
    }
  ],
  "protected": [
    { "reason": "合わない条件", "text": "ただし壁から68cm要ります。" },
    { "reason": "結論の条件付け", "text": "体重60kg以上なら" }
  ],
  "resultChars": 268
}
```

`feasible: false` のときは `operations` を空にし、`alternatives` に選択肢を並べる。
**形は `operations` と揃えてオブジェクトにする。**

```json
"alternatives": [
  { "cause": "overhead", "action": "導線を本文の外へ逃がす（linkAllowed: false の媒体と同じ扱い）", "effect": -47 },
  { "cause": "overhead", "action": "disclosureStyle が linked なので表記を最短の一文にする", "effect": -8 },
  { "cause": "body", "action": "この媒体を展開先から外す", "effect": null }
]
```

**この例は `disclosureStyle` が `inline` の媒体のものである。** 1 番目と 2 番目は
同時に出せない — `linked` の媒体では 1 番目が出せず、`inline` の媒体では 2 番目が要らない。
1 番目は `effect` が計算できてしまう（URL の字数がそのまま出る）ので、
`linked` の媒体で並べると、呼び出し側は数字だけを見てこれを選び、検品で落ちる。

- `cause` — `"overhead"`（定型部分が枠を食っている）か `"body"`（本文そのものが入らない）。
  **両方きついときは両方の案を並べる。**「先に定型部分を差し引く」節の 3 項目は `overhead`、
  「超えているとき」の選択肢は `body` に入る
- `effect` — 削減字数。数えられないもの（媒体を外す）は `null`。
  これがあると、呼び出し側が「どれを選べば入るか」を自分で決められる

## やらないこと

- 直接書き換えない。`operations` を返すだけ。
  **`blog-content/` 配下へ書き込まない。** `Write` は `--output` の JSON を出すためだけに使う
- 導線（URL・案内文）と広告表記を削らない。入らないなら `alternatives` で返す
- 削る順序が空振りしたぶんを、保護対象から埋め合わせない
- 数値や条件を丸めて字数を稼がない（「約 4 割減」への言い換えは主張の変更）
- 案件ブリーフに無い事実を足さない
- 削る順序を自分で決め直さない（正本は run-social-post の節）
