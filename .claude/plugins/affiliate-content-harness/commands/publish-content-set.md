# 公開前にまとめて確かめる

引数: `$ARGUMENTS`（`blog-content/<site>` のような content-set path）

## このコマンドの役目

各成果物は書いたときに単体検品を通っている。**それでも通り抜けるものが 2 つある。**

1. **媒体間の食い違い** — ブログに「38kPa」、Instagram に「40kPa」。
   単体ではどちらも正しく、どちらの検品も通る。並べたときにしか出ない
2. **広告表記の抜け** — 媒体によって「本文に書く／書いてはいけない」が反転する。
   ブログは画面が自動で出し、SNS は自分で書く。移し替えるときに落ちる

どちらも公開後に読者だけが気づく。だからここで止める。

## やること

### 1. content set を指定する

```bash
S=blog-content/<site>
```

`$S` には `campaign-brief.json` と `site.json`、任意の `articles/*.json`、
`posts/*.json` を置く。ファイル一覧と案件の `media` の突き合わせは次の入口が行う。

### 2. 5 本の検品を同じ入口から回す

```bash
P=.claude/plugins/affiliate-content-harness
node $P/scripts/validate-content-set.mjs --content-set "$S"
```

入口はファイルをローカル列挙し、案件で予定した媒体の不足・予定外の媒体・同一媒体の
重複を先に出してから、5 本をすべて回す。個別スクリプトを手で束ね直さない。
手組みすると、glob や配列の誤りで「0 件を見て通過」が再発する。

### 3. 文体を揃える

`apply-style-genome` agent に全成果物を渡す。
規則には触れていないのに、並べると別人が書いたように見える箇所を拾う。
返ってくる `replacement` を当てるかどうかは人が決める。

### 4. 報告する

止めるもの・気になるものを、**成果物ごとではなく理由ごと**にまとめる。
同じ原因で 3 媒体が落ちているなら、直すのは案件ブリーフ 1 箇所であることが多い。

| 出すもの | 中身 |
| --- | --- |
| 揃った媒体 | 案件の `media` に対して、どれが書けているか |
| 止めるもの | 検品 5 本の `×` を、直す場所ごとにまとめる |
| 残した `△` | 残すと決めた理由 |
| 直す起点 | 案件ブリーフを直すのか、個別の成果物を直すのか |

## 直さない

このコマンドは確かめるだけ。直すのは `run-campaign-brief` / `run-blog-article` /
`run-social-post` の担当。

理由がある。案件ブリーフ 1 箇所の間違いで 6 媒体が落ちているとき、
ここで 6 本を個別に直すと**案件は間違ったまま残る**。次の媒体を書いたときに同じ間違いが出る。
