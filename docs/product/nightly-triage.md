# 深い門（3 段）が落ちたときにやること

規範は `docs/spec/11-CI-CD・品質ゲート仕様.md` §8。段の定義は
`quality-gates.config.mjs` の `TIERS` が正本。

3 段は **マージを止めない**。止めないことにした理由と、
止めない代わりに必ずやることを、この 1 枚に書いておく。

**2026-08-18 に定例（毎晩の自動実行）を廃止した。** 3 段はいま
**人が打ったときだけ**走る。打つ場面は `docs/spec/11-CI-CD・品質ゲート仕様.md` §8-2
の表に定めてあり、必ず含めるのは**本番へ公開すると判断する日**である
（`docs/product/open-doors.md` を見る回と同じ回）。
この 1 枚は「打ったら落ちた」ときの手順であって、頻度の話はしない。

---

## 1. なぜ 3 段の赤でマージを止めないのか

止めると、手が止まる人が出る。手が止まる状態が数回続くと、
必ず「この検査を外す」判断に流れる。**外された検査は、落ちる検査より悪い。**
あると思われているのに無いからで、誰も見ていない緑と同じになる。

だから 3 段は「止めない代わりに、必ず記録する」設計にしてある。
記録されない赤は、次に打ったときも同じように落ちて、やがて背景になる。
**背景になった赤は、無いのと同じである。**

止めるのは 1 段（push）と 2 段（PR）だけ。ここは 5 分・15 分で終わり、
落ちたその場で直せる範囲しか入れていない。

---

## 2. 手順

打った `deep` ワークフローが赤になったら、次の順でやる。**当日中に 4 まで進める。**

### 1. 何が落ちたかを 1 行にする

ログの最後だけを見ない。ステップ名（`3 段のテスト` / `段の指定漏れ` /
`全体ミューテーション` など）と、**落ちたテストの名前**まで取る。

```bash
gh run list --workflow=nightly.yml -L 5
gh run view <run-id> --log-failed
```

### 2. 種類を判定する

| 症状 | 種類 | やること |
|---|---|---|
| 手元で同じコマンドを走らせると再現する | **本物** | 3 へ |
| 走らせるたびに結果が変わる（同じコードで緑にも赤にもなる） | **不安定** | 3 へ（種類は「不安定」で起票する） |
| 外部サービスの応答・ネットワークで落ちた | **環境** | 4 へ（起票はする。再発したら本物として扱う） |

**「たまたまだと思う」で閉じない。** 判定は手元での再現で決める。

```bash
pnpm run test -- <落ちたファイル>     # 3 回走らせて、3 回とも同じ結果か見る
```

### 3. 残課題として起票する

**機械からは書かない。** bd への書き込みは正規経路（`bd-bridge.py`）だけを使う
決まりで、CI から自動起票すると経路を迂回することになる。だから人が書く。

書くのは次の 4 点だけでよい。長く書くと起票そのものが面倒になって、やらなくなる。

- 落ちたステップ名と、落ちたテスト名
- 種類（本物 / 不安定 / 環境）
- 手元で再現するか（したコマンドをそのまま）
- 実行へのリンク（`gh run view <run-id> --web` の URL）

優先度の目安は次のとおり。

| 種類 | 優先度 | 理由 |
|---|---|---|
| 本物（利用者に見える壊れ） | P1 | 3 段で見つかっただけで、壊れているのは本番と同じコード |
| 本物（利用者には見えない） | P2 | |
| 不安定 | P2 | 放置すると 1 段・2 段にも波及し、「赤を無視する」習慣を作る |
| 環境 | P3 | ただし**同じ環境要因で 3 回落ちたら P2 に上げる**。それはもう環境ではない |

### 4. 直すまでの間、赤を放置しない

その日のうちに直せないものは、起票した番号を**次の夜のログに残す形にする**
（該当テストを消す・skip する・閾値を下げる、はいずれも禁止）。

やってよいのは**実行する場所を変える**ことだけである。1 段・2 段で落ちていて
すぐ直せないものは、`quality-gates.config.mjs` の `TIERS` を通して 3 段へ移す。
移す判断は戻せるが、消す判断は戻せない。

---

## 3. やってはいけないこと

| 禁止 | 何が起きるか |
|---|---|
| 落ちたテストを消す・`.skip` する | 検査が無くなったことが、誰にも見えない形で残る |
| 閾値を下げて緑にする | 悪化に気づく手段そのものを捨てている |
| 期待値を実装に合わせて書き換える | テストが実装の写しになり、何も確かめなくなる |
| 「たまたま」で閉じる | 不安定なテストが増え、全部の赤が無視されるようになる |
| 3 日以上、赤のまま起票しない | 赤が背景になる。ここが最も戻しにくい |

---

## 4. 週に 1 回みること

- 直近 7 回の `deep` の結果（`gh run list --workflow=nightly.yml -L 7`）
- 同じテストが 2 回以上落ちていないか（落ちていれば不安定として扱う）
- 3 段へ移したまま戻していないものが溜まっていないか（`quality-gates.config.mjs` の `TIERS`）
