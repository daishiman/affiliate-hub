# クリックの欠測：いま数えられているもの／数えられていないもの

最終更新: 2026-08-18

「リンククリック数」が画面に出ているとき、**その数字が全体の何を含んでいて何を落としているか**を 1 か所に書く。
数字そのものは `/admin/analytics` に出るが、数字だけを見ると欠けている分は見えない。
出ている数字が全体の一部でしかないことに気づけないのが、この領域でいちばん危ない状態である。

正本の関係: 実装状態は `traceability.md` の REQ-E13、直す順番は `backlog.md` 57 / 58。
このファイルは**何が測れていて何が測れていないか**だけを書く。

---

## 1. クリックを数える経路は 2 つある

| 経路 | 記録に残る印 | 誰が数えるか | 何が要るか |
| --- | --- | --- | --- |
| 転送の入口 | `recordedVia: "redirect"` | サーバ（`/go/<合言葉>`） | そのリンクに**合言葉が発行されている**こと |
| 画面 | `recordedVia: "browser"` | 読者のブラウザ | JavaScript が動くこと |

**同じクリックを 2 度数えない。** 転送の入口を通るリンクは画面側では数えない。
判定は「部品が印を付けたか」ではなく、アンカーの**行き先が実際に `/go/` かどうか**で行う。
印は付け忘れられるが、行き先は嘘をつかない。

どちらで数えたかは記録に残るので、この決まりが破れたときは
`recordedVia` の内訳を見れば数字に出る。

## 2. 解消した範囲

**合言葉が発行されているリンクのクリックは、どのリンクか分かる形で記録される。**

- 転送の入口 `/go/<合言葉>` はサーバ側で数えるので、読者のブラウザの設定に左右されない
- 記録には記事の道・ブログ・リンク ID・置き場所が入るので、**どの記事のどの位置のリンクが押されたか**まで分かる
- 記録できなくても転送は止めない（読者は買いに行こうとしている）。落とした分は下の「未解消」に現れる
- 転送先が `https` でないものは合言葉を出さない。押されても転送しないので、クリック数にも混ざらない

## 3. 未解消の範囲

### 3-1. 合言葉が発行されていないリンク（いまは**全部**がこれ）

合言葉が無いリンクは、読者へ ASP の URL を直に出す。読者は普通に買えるし、
画面のどこにも異常は出ない。クリックは画面側の経路でしか数えられない。

**2026-08-18 時点で、実運用のリンクはすべてこの状態である。**
公開の手続き（`usecases/site/publish-article.ts` の `buildArticle`）が
順位表も商品カードも作らないため、公開された記事に成果リンクが 1 件も載らない
（`backlog.md` 58）。発行の口は繋がっているが、その手前に流し込むものが無い。

何件残っているかは `/admin/analytics` に出る。**0 件になるまで、突合できるクリック計測は完成していない。**

### 3-2. 画面の経路でしか数えられないクリックの取りこぼし

画面の経路は、次の場合に数えられない。いずれも**読者側の事情**なので、こちらから減らせない。

- JavaScript が動いていない
- 送信そのものが遮られている（拡張機能・企業のネットワーク）
- 押した直後にページを離れ、送信が間に合わない

**この取りこぼしの量は測れない。** 数えられなかったクリックは、記録のどこにも痕跡が残らないためである。
「クリック数が実数より少ない」ことは分かるが、どれだけ少ないかは分からない。
合言葉が発行されればサーバ側で数えるので、この取りこぼしは経路ごと消える。

### 3-3. ASP 側の成果との突合

押されたことは数えられても、**それが売れたかどうか**は ASP 側の記録が要る。
成果の取込は今もスタブである（`stub-ledger.md` の `asp:*`）。

## 4. この画面の数字を読むときの決まり

- 「未計測」は「まだ数えられていない」であって **0 ではない**
- 未発行の件数が 0 でない間、リンククリック数は**全体の一部**である
- 収益の数字は順位やおすすめの決定に使えない（用途ごとに使える数字を分けている）
