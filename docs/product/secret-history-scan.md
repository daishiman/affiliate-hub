# 秘密の値の履歴走査（1 度きりの実測）

最終実施: **2026-08-21** / 結果: **当たり 0 件**

## この記録が何のためにあるか

`tests/architecture/secrets-not-in-repo.test.ts` は **「これから入るのを止める」門**であり、
見ているのは **いま git が追跡しているファイルだけ**である。
一度コミットされた値は作業ツリーから消しても履歴に残るので、
**あの検査が緑でも「過去に漏らしていない」ことにはならない。**

両方が「秘密が入っていない」という同じ言葉で語られるため、
書いておかないと片方の緑がもう片方の証拠として読まれる。
ここは **過去側を 1 度実測した事実**だけを持つ。

記録が無いと、次に同じ疑問が出たときに同じ走査をやり直すことになる。
**当たり 0 件でも書く**のはそのためである。

## 走査の手順

```bash
node scripts/secret-history-scan.mjs
```

- 判定の形は `tests/architecture/secrets-not-in-repo.test.ts` の `SECRET_PATTERNS` と
  `KNOWN_NOT_SECRET` を **そのまま読み出して**使う（写して持たない）。
  写すと物差しが 2 つになり、片方だけ緩む。検査ファイルは読むだけで書き換えない。
- 差分（`git log -p`）ではなく **`git rev-list --objects --all` の実体**を読む。
  差分はマージの本文を既定で出さないので、マージだけで入った内容を落とす。
- 走査の前に、合成した見本に当たることを確かめてから始める。
  **0 件は探す側が壊れていても出る**ので、当たらないなら走査自体を始めない。
- **毎回の門にはしない。** 履歴は追記しかされないので、門にしても
  昨日と同じものを読み直すだけで、時間だけ増えて分かることは増えない。

### 既知の 3 件について

3 件はすべて **同じ 1 つの値**で、指紋 `b16856bcebccbbe5`——
`.claude/plugins/dev-graph/tests/test_validate_repo_config.py` の中で
「設定に token の置き場を新設できない」ことを確かめるために使われている **架空の値**である。
既存の検査の `KNOWN_NOT_SECRET` に同じ指紋で登録済みで、こちらの発行物ではない。
**作り直しの対象ではない。**

### 補助の掃き出し

正本の物差しに無い発行元（`github_pat_` / `AIza` / `xai-` / `sk-` の短い接頭辞 /
Cloudflare の API トークンの形）も当てたが、**0 件**だった。
これらを正本へ混ぜていないのは、混ぜると
「入口の門では通るが履歴の走査では当たる」形を黙って作ることになるためである。
広げるなら入口の検査の側で広げる。

### 高エントロピーの並びについて

32 文字以上の羅列は 125,970 件、うちシャノンエントロピーが 4.4 以上のものは 9,699 件あった。
**これらは当たり扱いにしていない。** 出どころの分からない長い羅列は、
ロックファイルの整合値・git の識別子・base64 の断片と **形の上で区別できない**。
当たりにすると一覧が育ち、やがて誰も読まなくなる。
**件数の分布だけを出し、判断は人に残す**——これは既存の検査が
「出どころの分からない 32 文字の羅列はわざと通す」としているのと同じ考え方である。

## 当たりが有ったときにやること（今回は該当なし）

1. **先に値を作り直す。** 履歴の書き換えより先。
   書き換えても、それまでに clone した人の手元には残っている。
2. 鍵の作り直しは **利用者ご本人の作業**である。エージェントは
   「どの発行元の鍵を作り直すか」だけを伝える。
3. **記録に値そのものを書かない。** 記録が新しい漏れになる。
   種別・オブジェクト・経路・行・指紋の先頭 16 桁までに留める。
