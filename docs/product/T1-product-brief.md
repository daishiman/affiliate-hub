# T1 — ブログ閲覧・運営UIの一体化

## 利用者の意図

読者はトップ、カテゴリー、検索、記事のどこから開いても、同じ案内と探し方で次の記事へ進める。運営者は「作る→承認する→公開する→訂正する→必要なら非表示にする」を1つの記事管理導線で完了できる。

## 対象ジャーニー

1. 読者がホームの新着・テーマ・検索から記事を見つける。
2. 記事でタイトル、更新日、広告表記、目次、書き手、本文、比較、商品導線を順に読む。
3. 運営者が「新しい記事」から既存の生成・承認・配信フローへ進む。
4. 公開後は公開済み一覧で検索し、理由付きで訂正する。
5. 公開を止めるときは物理削除せず非表示にし、操作理由と本文を残す。

## 成功条件

- すべての公開ルートが共通`SiteShell`を通り、ヘッダー・検索・ナビ・サイドバー・フッターが分岐しない。
- 公開済み記事は一覧・編集・非表示化の全経路で`workspaceId`による境界を持つ。
- 非表示記事は新着、カテゴリー、検索、人物、直接URLから消え、見本記事へ逆戻りしない。
- 375 / 768 / 1280 / 1600pxで横スクロールせず、タップ対象は44px以上、キーボードフォーカスが見える。

## 非目標

参考サイトの文章、画像、固有名、ロゴ、色値は移さない。本差分で公開ゲートを省略した直接新規作成、物理削除、DB全体の再設計は行わない。
