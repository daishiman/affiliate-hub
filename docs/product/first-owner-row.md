# 運営者の最初の 1 行を入れる

管理画面から担当者を招けるようになりました（`/admin/settings`）。
ただし招待できるのは **すでに担当者として入っている人** だけです。
つまり「いちばん最初の 1 人」だけは画面から作れません。ここはその 1 行を入れる手順です。

作業は 5 分ほど、1 つの作業場所につき 1 回だけです。

---

## なぜ画面から作れないようにしてあるのか

「最初にログインした人を運営者にする」という作りにすれば、この手順は要りません。
実際そうしている道具は多くあります。**それでもここでは入れていません。**

理由は 1 つで、その特例は**入口が開いたあとも残る**からです。
一度でも「行が 0 件なら通す」という道を作ると、後から誰かが表を空にしたとき、
あるいは新しい作業場所が増えたときに、その瞬間だけ**誰でも運営者になれる窓**が開きます。
窓が開いたことは画面のどこにも出ません。

この窓を作らないために、入ってよい人は必ず**入る前に行がある**という形にしてあります。
最初の 1 行だけは、手で入れます。

---

## 入口は 2 段です

運営者の行を入れても、それだけでは入れません。入口は 2 つに分かれています。

1. **名簿** — `AUTH_ALLOWED_EMAILS`（Cloudflare の環境変数）。
   「Google の確認を通してよいアドレスか」を決めます。
2. **担当者の行** — この文書で入れるもの。
   「どの作業場所の、何の役か」を決めます。

**両方に載っていないと入れません。** 片方だけ通しても通行証は出ないので、
「登録したのに入れない」ときは、まずもう片方を確かめてください。

---

## 手順

### 1. 自分のアドレスを名簿に入れる

Cloudflare のダッシュボードで、この Worker の環境変数 `AUTH_ALLOWED_EMAILS` に
Google でログインするアドレスを入れます（複数ある場合はカンマ区切り）。

> 値はブラウザから入れてください。コマンドの引数にすると、実行履歴に残ります。

### 2. 担当者の行を入れる

`wrangler` から 1 行だけ INSERT します。`--remote` を付けると本番の D1 に入ります
（手元で試すときは付けずに実行してください）。

```sh
pnpm wrangler d1 execute affiliate-hub-db --remote --command "
INSERT INTO memberships (
  id, workspace_id, user_id, invited_email, roles, scoped_brand_ids,
  display_name, invited_at, accepted_at, revoked_at
) VALUES (
  'mb_owner_001',
  'ws_sample',
  NULL,
  'あなたのアドレス@example.com',
  '[\"owner\"]',
  '[]',
  'あなたの名前',
  unixepoch(),
  NULL,
  NULL
);
"
```

置き換えるのは 4 か所です。

| 欄 | 入れるもの |
| --- | --- |
| `workspace_id` | 作業場所の識別子。`ws_sample` のままにしてください。作業場所そのものの保存先はまだ見本データで、ブランドと広告表記が**この識別子で**入っています。別の値にすると、ログインはできてもブランドが 1 つも出ません |
| `invited_email` | Google でログインするアドレス。**必ず小文字で**入れてください |
| `display_name` | 一覧と操作の記録に出る名前 |
| `id` | 何でも構いませんが `mb_` で始めてください |

`user_id` は **NULL のまま**にします。ここを自分で埋めないでください。
埋めるのは初回ログインの側で、Google が返した利用者と行を結び付けるのはそのときです。
先に適当な値を入れると、その行は**誰のものでもないまま残り**、あなたは別の行が要ることになります。

`roles` は JSON の配列です。運営者は `["owner"]` の 1 つだけで、他の役割と併せられません
（運営者は全部できるので、併せる意味がありません）。

### 3. ログインする

`/signin` から Google でログインします。ここで初めて `user_id` と `accepted_at` が埋まり、
参加が成立します。`/admin/settings` の担当者の欄に自分の行が出ていれば完了です。

### 4. 以降は画面から

2 人目からは `/admin/settings` の「担当者を招く」から出せます。
招いた相手も、名簿（手順 1）に載せる必要があることは変わりません。

---

## うまくいかないとき

| 症状 | 見るところ |
| --- | --- |
| ログインすると「担当ではありません」と出る | `invited_email` が小文字か。`workspace_id` が他の行と揃っているか |
| ログインの画面まで行けない | `AUTH_ALLOWED_EMAILS` にそのアドレスが入っているか |
| 「すでに行があります」と断られる | 同じアドレスの行が既にあります。画面の一覧からその行の役割を変えてください |

行を消して入れ直すのは避けてください。担当者の行は、その人が過去に承認した記録の
持ち主でもあります。消すと記録の側が誰のものか分からなくなります。
外したいときは画面から「担当から外す」を使ってください（行は残り、外した日が入ります）。
