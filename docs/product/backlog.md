## 追跡の正本

**作業単位の正本は Beads (`bd`) である。** このファイルは人が読むための要約であり、
状態が食い違う場合は Beads と dev-graph (`.dev-graph/state/graph.json`) を正とする。

`.claude/plugins/dev-graph/scripts/bd-bridge.py` を経由する決まりになっている

リポジトリ直下に `scripts/bd-bridge.py` が無いことをもって「存在しない」と判断しない）。
**この見張りを回避する形での起票は行わない。**
見張りは「dev-graph に登録された作業だけが Beads へ写る」という決まりの実装であり、
迂回すると、どちらにも無い作業がこのファイルの中だけで増えていく。

したがって手順は次の順に固定する。

1. `upsert-node.py` で dev-graph に節点を作る（`--dry-run` で書き込み 0 件を確かめてから本実行）
2. `bd-bridge.py --op create --graph-node-id <節点>` で Beads へ写す
3. 依存関係を `--op dep-add` で足す
4. 済んでいるものを `--op close` で閉じる
5. このファイルの `状態` 欄を Beads に合わせる（**このファイルから先に書き換えない**）

### 残り15機能を今まとめて計画しない理由

分解済みの16機能のうち、実行タスクまで落とし込んだのは `feat-auth-workspace` の1件だけ。残りは意図的に「計画前」で止めてある。

- 1機能ずつ縦に作り切るほうが、途中で作り直す量が少ない
