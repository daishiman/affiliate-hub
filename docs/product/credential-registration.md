# 合言葉（鍵）の登録手順

**この作業はご本人が行ってください。** 私（AI）は代行しません。
鍵の値をこちらへ渡すと、渡した時点でファイルや実行履歴に残り、
消したつもりでも残り続けます。**値そのものは受け取りません。**
「登録が終わりました」の一言だけいただければ、続きを進められます。

登録するのは 2 組です。用途がまったく違うので、別々に説明します。

- **A. 公開の合言葉**（Cloudflare）— アプリをみんなが使える場所へ出すために要る
- **B. 生成 AI の合言葉** — 記事の下書きを AI に書かせるために要る

A と B は独立しています。片方だけ先に登録しても構いません。

---

## A. 公開の合言葉（Cloudflare の口座番号と鍵）

### これが無いと何が起きているか

いま、アプリを公開する操作は私の手元から実行しています。
手元からの実行は**その場の作業中のファイルをそのまま公開してしまう**ため、
「まだ保存していない書きかけ」が本番に出る余地が残ります。

この 2 つを登録すると、公開は「確認済みのものをまとめる操作」からのみ
自動で走るようになり、その余地が仕組みとして消えます。

### 登録する場所

GitHub のこのリポジトリ → **Settings** → **Secrets and variables** → **Actions**
→ **New repository secret**

### 登録するもの（名前は下の表のとおり、1 文字も変えずに）

| 名前 | 中身 | どこで手に入るか |
| --- | --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | 口座番号（これ自体は秘密ではありません） | Cloudflare の管理画面 → Workers & Pages → 画面右側に表示されています |
| `CLOUDFLARE_API_TOKEN` | 公開する権限を持つ鍵 | 下の手順で新しく発行します |

### 鍵の発行手順

1. Cloudflare の管理画面にログイン
2. 右上のアイコン → **My Profile** → **API Tokens** → **Create Token**
3. テンプレートの一覧から **「Edit Cloudflare Workers」** を選ぶ
4. 表示された鍵を、その場で GitHub 側へ貼り付ける（**この画面を閉じると二度と表示されません**）

**「Global API Key」は使わないでください。** あれは口座の全権を持つ鍵で、
公開だけに用途を絞れません。万一漏れたときに、口座ごと作り直すことになります。
上の手順で作った鍵なら、**その鍵 1 本だけを無効にして作り直せます。**

### 登録できたことの確かめ方

GitHub の **Actions** の画面から `migrate.yml` を手動で 1 回実行し、
最後まで緑になることを見てください。落ちる場合は、
その画面に出ているメッセージだけをお知らせいただければ調べます
（**鍵の値は貼らないでください**）。

## B. 生成 AI の合言葉

### 先にお伝えしておくこと（重要）

**鍵を登録しただけでは、まだ記事は生成されません。**
正直に書きます。いま足りないものは 3 つあり、鍵はそのうちの 1 つです。

| # | 足りないもの | 誰が決める・やる | 状態 |
| --- | --- | --- | --- |
| 1 | **どこの生成 AI を使うか**を決める | ご本人（費用と、文章を預けてよい相手かの判断） | 未定 |
| 2 | 決めた提供元へ**実際に問い合わせる処理**を書く | 私 | 未着手（いまは 4 社ぶんとも「まだ繋がっていません」と答える仮の実装） |
| 3 | 鍵を登録する | ご本人 | 未登録 |

順番は **1 → 2 → 3** です。1 が決まらないと 2 が書けません。
先に 3 だけ済ませても動きませんが、**登録しておいて損はありません**
（2 が終わった時点ですぐ試せます）。

なお、費用の上限を先に入れる作りにしてあります。
問い合わせる前に見積もり、上限を超える依頼は**呼ばずに止めます**。
使ってから請求で気づく、という順番にはなりません。

### 1. 提供元を決めるための材料

いま費用の概算に使っている単価です（円。トークン 100 万個あたり）。
トークンは AI が文章を数える単位で、日本語ではおおよそ 1 トークン = 1.5 文字です。
実際の請求額ではなく、提供元どうしを比べるための数字として見てください。

| 提供元 | 読ませる（渡す文章） | 書かせる（返ってくる文章） | 備考 |
| --- | --- | --- | --- |
| Anthropic | 2,250 | 11,250 | いまの仮の設定はここ |
| OpenAI | 1,800 | 9,000 | |
| Google Gemini | 1,900 | 9,500 | |
| Cloudflare Workers AI | 100 | 100 | 安いが、長文記事の品質は要検証 |

判断材料は費用だけではありません。**商品の説明文や下書きをその会社に預けてよいか**、
という点も同じくらい効きます。決めかねる場合は、そうお伝えください。
比較のための材料をもう少し集めます。

### 2 と 3. 鍵の発行と登録

提供元が決まったら、その会社の管理画面で API キーを発行します。
発行したら、**ご自身のターミナルで**次のコマンドを実行してください。

```
pnpm exec wrangler secret put SECRET_LLM__ANTHROPIC__API_KEY
```

- 実行すると入力を求められるので、**そこに鍵を貼り付けます。**
  コマンドの後ろに鍵を書かないでください（実行履歴に残ります）。
- 名前の `ANTHROPIC` の部分は、選んだ提供元に合わせて変わります。
  決まった時点で、正しい名前をお知らせします。

| 提供元 | 登録する名前 |
| --- | --- |
| Anthropic | `SECRET_LLM__ANTHROPIC__API_KEY` |
| OpenAI | `SECRET_LLM__OPENAI__API_KEY` |
| Google Gemini | `SECRET_LLM__GOOGLE_GEMINI__API_KEY` |
| Cloudflare Workers AI | `SECRET_LLM__WORKERS_AI__ACCOUNT_TOKEN` |

## やらないでいただきたいこと

- 鍵をチャットに貼る（私に渡す）
- 鍵をリポジトリの中のファイルに書く
- 鍵をコマンドの引数として打つ（`wrangler secret put NAME 値` の形。履歴に残ります）
- スクリーンショットに鍵が写った状態で共有する

うっかり渡してしまった場合は、**その鍵を失効させて作り直してください。**
「消したので大丈夫」とは考えないでください。責めるつもりはまったく無く、
作り直すのが唯一の確実な対処です。

## 技術的な補足（開発者向け）

- 参照キーの形式は `<種別>/<接続ID>/<用途>`。環境変数名への写像は
  `src/infrastructure/platform/secret-resolver.ts` の `refToEnvName()`。
  秘密の値に触れてよいのはこのファイルだけ。
- 提供元の切り替えは `src/infrastructure/llm/llm-setup.ts` の `ACTIVE_PROVIDER` 1 行。
- **未接続の箇所が 2 つある**（B の表の #2 の実体）:
  1. `src/infrastructure/llm/llm-provider-registry.ts` の `FACTORIES` は
     4 社ぶんとも `createStubLlm` を返す。呼ばれると失敗を返す
     （固定文を返さないのは、生成していない記事が「生成済み」として残る事故を避けるため）。
  2. `src/infrastructure/composition.ts` の `createLlmPorts()` が引数なしで呼ばれており、
     Worker の env が渡っていない。このままだと登録済みの鍵も解決できない。
     提供元の実装を書くときに、env を通すところまで併せて直す。
- 正本のタスク: `tasks/task-deploy-credentials-registration.md`（A）/
  `tasks/task-llm-provider-connection.md`（B）
