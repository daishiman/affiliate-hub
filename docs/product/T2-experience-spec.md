# T2 — ブログUI/UX仕様

## 参考から抽象化した構造

参考正本は`https://makuring.jp/`、カテゴリー起点は`https://makuring.jp/pc/`、記事構造は`https://makuring.jp/pc/best-laptop-video-editing/`である。移植したのは「ブランドと検索の上部」「カテゴリーナビ」「本文5 : サイド2」「方針を持つフッター」「記事内の意思決定順序」だけである。

## 公開画面

- ヘッダー: テキストロゴ、1文の対象説明、キーワード検索、横並びナビ。ロゴは必ずホームへ戻る。
- ホーム: 検索で始められるヒーロー、新着記事、名前と1文説明のカテゴリー索引。画像アセットの証拠が無いため、装飾画像は作らない。
- 一覧・検索: タイトル、1文結論、更新日、書き手を1列で比較する。0件は状態と次の行動を表示する。
- 記事: パンくず→タイトル/日付→結論→広告開示→目次→書き手→対話→本文→比較/順位→商品→更新履歴。
- サイドバー: 記事はsticky目次、全画面で検索、カテゴリーのみのナビ、運営方針導線。トップ/検索をカテゴリーに混ぜない。
- フッター: サイト説明、方針・法務・問い合わせ、広告注記、同意、明るさ、著作権表示。

## 管理画面

- 記事一覧の共通ヘッダーから「新しい記事」と「公開済み記事」へ常時移動できる。
- 新規画面は「素材→原稿→承認/公開」の3ステップを示し、既存の商品、生成マトリクス、配信へ導く。
- 公開済み一覧はキーワードと公開状態で絞る。PCは列の比較、SPは各値にラベルを持つカードに組み替える。
- 編集はタイトル、結論、書き手、節と訂正理由を扱う。複数入力は600msで端末下書きに保存し、復元と破棄を明示する。
- 非表示は理由を必須とし、「削除しない」ことを操作近くに書く。非表示中の訂正は非表示のままである。

## レスポンシブとa11y

375pxでは本文1列、目次は本文内、サイドバーは読了後に積む。768pxは同じ1列で余白を広げる。1280/1600pxは幅上限72remで止め、本文+サイドバーにする。すべての検索入力は一意な`id`とラベル、フォーカス可視化、44px以上の操作面を持つ。
