## A. 直した（目で確かめてほしい）

### UX-01 画面の中身が縦に間延びする ★済

- **症状**: `/signin` で、見出し・説明文・警告の箱・ボタン・注記の**すべての間隔が同じだけ大きく開く**。
  警告の箱は中身が上半分だけで、下半分が空のまま伸びる。
- **原因**: `.siteShell` は `min-height: 100vh` の縦 flex、`.siteMain` は `flex: 1` の grid。
  中身が短いと `.siteMain` が画面の高さまで伸びる。grid の `align-content` の初期値は
  `stretch` で、行がすべて `auto` のときは**余った高さを全部の行へ均等に配ぶんする**。
  結果、`gap: var(--space-6)` に書いた値が効かなくなる。
- **根拠**: 同じ形の対処が `admin.module.css:186` / `patterns.module.css:315` /
  `ui.module.css:482` に既に 3 箇所ある。**`site.module.css` にだけ無かった。**
- **直した所**: `site.module.css` の `.siteMain` に `align-content: start`。
- **効く範囲**: `PublicShell` を使う 3 画面（`/`、`/signin`、`s/[site]/not-found`）と
  `SiteShell` を使う読者向け 21 画面。**中身が少ない画面ほど直りが大きい**（ログイン・
  0 件の一覧・エラー・404）。
- **残り**: 機械で見ていない。「中身が短い画面で `gap` が効いているか」を測る検査が要る（UX-11）。

### UX-02 本文の中のリンクが、地の文と見分けられない ★済

- **直した所**: `tokens/semantic.css` の `:where(a[href])` と `:where(a[href]):hover`。
- **決めたこと**（変えるときは UX-12 の検査も一緒に変える）:
  - **下線を常に出す。**`:hover` のときだけ出す形は採らない。hover は
    ポインタで触れる人にしか届かず、キーボードだけの人・拡大している人・
    タッチの人には押せる所が最後まで分からない。
  - 線の太さを `--border-width-default` で固定する。既定は書体まかせで
    小さい文字だと消えかける。この値はハイコントラスト時に太くなるので、
    **下線もそこで一緒に太くなる。**
  - `text-underline-offset: var(--space-1)` で線を字から離す。
    **日本語のための 1 行**で、既定の位置だと「う」「え」「氵」の足に食い込む。
  - 色は `--color-action-default`（継承にしない）。`.linkNote` の中でも沈まない。
  - `:hover` は色と線の太さだけを変える。「いま指している所」を伝える役に徹する。
- **効く範囲**: どの規則にも当たらない素のリンク全部。`:where()` は詳細度 0 なので、
  `.siteNav a` / `.cardTitle a` の**意図した**下線外しはそのまま勝つ。

### UX-08 ①の 4 件 ★済

- `.stubLabel`（`patterns.module.css`）と `.rankBadge`（`admin.module.css`）に
  `border` を追加。**強制配色のときだけの対処にしない**——`.stubLabel` の兄弟
  `.factBadge*` 3 つは素から border を持っており、揃えるほうが素直。
- `.buttonPrimary` / `.buttonQuiet:hover` は `@media (forced-colors: active)` を
  `ui.module.css` に新設（**このプロジェクト初の `forced-colors` 記述**）。
  基底 `.button` の `border: ... solid transparent` は強制配色でも
  **`transparent` のまま保たれる**ので、色を明示して初めて枠が出る。

  - 私は「基底 `.button` が `min-height` を持つから `quiet` でも的は足りる」とだけ見て

  - `/signin` のこのボタンには隣が無い。`quiet` に戻すと**症状が再発する**。

### UX-04 ログインしていないときの枠に、足元が無い ★済

- **場所**: `site-shell.tsx` の `PublicShell`
- **症状**: `SiteShell` は `.siteFooter` を出すが、`PublicShell` は `header` と `main` だけ。

- **実測**: 製品としての方針ページは **1 枚も無い**。`privacy` / `terms` / `contact` /
  `advertising-policy` などは全部 `s/[site]/…` の下、つまり**ブログごと**にしか無い
  （`src/app` のルート 54 枚を数えた）。`UI_COPY` にも運営者・問い合わせ・
  プライバシーに当たる文言は無い。
- **決めたこと**: 足元は置く。ただし**出すのは広告の断り 1 文だけ**
  （`UI_COPY.disclosure.footerNote`）。`chrome.footer`（方針リンク）・同意の帯・
  読みやすさの切り替えは、どれも「ブログを読み始めてから」のもので、
  ブログが決まっていないこの枠には出せない。**行き先の無いリンクを作らないために、

- **読みやすさの切り替え（`AppearancePicker`）を置くかどうか**: **置かない。**

    どちらの人も、この画面で困らない。

    これが 6 箇所になる。通り過ぎる 3 画面のために払う値段ではない。
  - **置かない理由は doc コメントに書いた**（UX-05 で「付け忘れではない」を書いたのと
    同じ形。後から「揃っていない」と見えて足されるのを止めるため）。
  - `ConsentBanner` も置かない。計測の同意はブログごとの話で、

### UX-05 ログイン前の画面に配色が当たらない ★済（直すところは無かった）

**この節の当初の見立ては 2 つとも誤りだった。**（2026-08-21 実測で訂正）

- **誤り①「明暗も無視される」** → `data-color-mode` は枠ではなく **`<html>`** に載っている
  （`app/layout.tsx` が全ルート共通で `appearanceAttributes(appearance)` を展開）。
  `semantic.css:173,177` は素の属性セレクタなので値は子孫へ継承される。
  **`SiteShell` と `PublicShell` で明暗の扱いは違わない。どちらも持たない。**
  眩しい画面にはならない。
- **誤り②「製品の既定色になる」** → `readAppearance()` は `siteDefault === undefined` の
  ときその人の cookie を読む。入口ページに出るのは**その人自身が選んだ配色**であり、
  `SiteShell` の側がそれをブログのブランドで**上書きしている**という関係。

結論（ログイン前はブランド色を当てないのが正しい）は変わらないが、**理由が逆だった。**
「既定色に落ちる」ではなく「その人の選択がそのまま残る」。

- **やったこと**: `PublicShell` の doc コメントに 4 点を明記（付け忘れではない／
  `chrome` を受け取る口ごと持たない／では何色で出るのか／
  **枠が明暗を持ち始めたら、持たない側の画面だけ選択が効かなくなる**）。
  振る舞いは 1 文字も変えていない。
- **検査**: `tests/ui/public-shell-appearance.test.tsx`（5 件）。
  壊して赤を 3 通り実測。加えて `chrome?: SiteChrome` を足すと
  `@ts-expect-error` が `TS2578` で落ちる——**型検査を見張りとして使っている。**
- **見ていないもの**: 実際に色が変わることは見ていない（jsdom は CSS を読まない）。

### UX-06 ログインの画面が、箱になっていない ★済

- **症状**: 幅いっぱいの中に、本文幅（`--prose-max-width`）の文が左端から並ぶだけ。
  「ここで操作を完結させる画面」に見えない。
- **作ったもの**: `templates/site-shell.tsx` の `FocusedTask` と
  `site.module.css` の `.focusedTask`。**画面側には 1 行も書いていない**
  （`signin/page.tsx` は `<FocusedTask>` で包んだだけ）。
- **決めたこと**:
  - **箱の見た目は共通部品の `.card` をそのまま使う。**`.focusedTask` が持つのは
    置き方（`margin-inline: auto`）と幅の上限と中の間隔だけ。枠・背景・角・影を
    ここに書き直すと、同じ箱が 2 通りの定義を持ち、片方だけ直る日が来る。
  - **影だけで浮かせない。**`.card` は `box-shadow` と `border` を両方持っている。
    強制配色（Windows のハイコントラスト）では影が落ちるので、
    影しか無い箱は境目ごと消える（UX-08 と同じ話）。
  - 幅は `--readable-max-width`（本文幅より狭い）。ここに入るのは読み物ではなく
    **短い説明と操作**で、行が長いと「読む画面」に見えてしまう。
  - **縦中央にはしない。**`.siteMain` は `align-content: start`（UX-01 で直した所）
    なので行は中身の高さのまま上に詰められ、余った高さは**行の外**に残る。
    grid 項目の `margin-block: auto` が吸えるのは自分の行の中の余りだけなので、
    `.siteMain` を触らずに縦中央は作れない。触れば UX-01 の戻しになるので、
    **横中央で止めた。**
- **効く範囲**: いまは `/signin` の 1 枚だけ。想定しているのは今後の
  「招待を受ける」「設定が済むまでの案内」で、**1 枚のための型ではない**という
  前提で `templates/` に置いてある。
- **残り**: 機械で見ていない（UX-04 と同じ理由。結べる要件行が無い）。
  2 枚目の画面が来たときに、`FocusedTask` を通さず画面側で箱を作らないこと。

### UX-07 折り返しの指定が、画面数に対して薄い ★済（`min-width` 側の穴も塞いだ）

**↑ 2026-08-21 夜。この節も済んでいた。**下の「壊しても赤にならない（見張りが無い）」は
**もう外れている**——`tests/ui/flex-row-shape.test.ts` に
**「直したものが、一覧に戻ってきていない」という専用の it が既にある。**
`.header` から `flex-wrap: wrap` を消して実測、赤になることを確認（復元して sha256 一致）。

**ただし対照実験で、見張られているのは半分だけだと分かった:**

| 消したとき | 赤になるか |
|---|---|
| `flex-wrap: wrap` | **○**（`flex-row-shape` の専用 it） |
| **`min-width: 0`** | ~~**×**（`tests/ui` + `tests/architecture` 2016 件で赤が 1 件も増えない）~~ → **○**（2026-08-21 夜に塞いだ） |

**穴を塞いだ。**`flex-row-shape.test.ts` に
`describe("縮められるようにしてある規則は、理由つきで数えられている")` を足した。
`.breadcrumb` から `min-width: 0` を消して実測、赤になることを確認
（復元して sha256 `e65f6de…` 一致）。

- **上の `EXEMPT` とは向きが逆である。**あちらは「折り返さない**例外**の一覧」で
  載っていないものが在ると赤。こちらは「縮められるようにしてある規則の一覧」で、
  **載っているものが無くなると赤**。同じ「両方向で見る」形だが良し悪しが反対。
- **判定していないもの**: 「`min-width: 0` を持つべきなのに持っていない子」は
  見ていない。**見られない。**どの規則が flex の子として使われるかは CSS に
  書かれていない——親子の関係は JSX 側にしかない
  （`surface-outline-count.test.ts` の `.inputAuto` と同じ壁）。
  守っているのは「**いま在るものが消えないこと**」だけ。

**そして、この節の「3 つ組に `flex-wrap` + `min-width`」という書き方自体が誤りだった。**
`min-width: 0` が要るのは flex の**子**であって、`.header` は**親**なので持っていない。
~~実際に持っているのは `.breadcrumb` / `.headerActions` / `.main` の 3 つ。~~
**↑ この訂正も外れていた。**当時の実測では `min-width: 0` は `src` 全体で **2 件**
（`.main` / `.breadcrumb`）だけで、**`.headerActions` は持っていなかった。**
訂正の 1 行目（親と子の非対称）は正しく、2 行目（実際に持っている 3 つ）が誤り。
**訂正を書くときも、書いた側の実測は要る。**
**一続きに書いたことで、この非対称が潰れていた。**

### UX-16 「表」と呼ばれていたものの半分は、表ではなかった ★済

### 置換跡が 1 箇所残っていた

`admin/improvement/page.tsx` ——行の注記は `StackedRow` の `note` が持っているのに、
固定文（「適用には承認が要ります」）の `<span>` が中身の側に残り、
**各行に同じ文が n 回並んでいた**。一覧の外へ 1 回だけ出す形に直した。
**同じ文が n 回並ぶと、読む人は文ではなく模様として飛ばす**——n 回言うほど伝わらなくなる。

### 数の記録を 1 つ直した

役A は記録の 36 ではなく **35** だった（`note.tsx` の doc が 36 と書いていた）。
**1 件の差でも、次に数える人が「1 件どこかへ消えた」と探し始める。**

### 事故と回復

### 4xx / 5xx は `fetch` にとって成功である

約束は果たされたので例外が飛ばず、`window` の `error` にも来ない。
**包まないかぎり、画面が「保存できません」と出している最中でも控えは空のまま**
——`failedRequests: []` が直書きされていた本当の理由はこれである。
そこが一番手掛かりの要る場面なのに、そこだけ何も残らない形になっていた。

`src/presentation/ui/patterns/page-diagnostics.ts` が `window.fetch` を包み、
`error` / `unhandledrejection` / 捕捉段の `click` を聞く。上限 8 件で古いほうから捨てる
——**読まれない情報は、無い情報と同じ**だからである。

### 押した瞬間に撮る（transient activation）

ブラウザは `getDisplayMedia` を「**押した勢いが残っているあいだ**」しか許さない。
`setOpen(true)` → dialog マウント → `useEffect` では勢いが切れ、
**利用者には何も起きなかったように見える**。だから撮影は launcher の `onClick` から始め、
約束（`Promise`）を state で dialog へ渡す。

**許可の窓は消せない。**ページが自分自身を無断で撮ることはできない。
**これは実装の手抜きではなく安全の側の決まりで、迂回する手立ては用意しない。**
（`preferCurrentTab` は Chromium だけが見る。他は黙って無視するので付けても壊れない。）

**撮れなかったときに案内を出さない。**押しただけで断りの文が出ると、
写しを付けるつもりの無い人にまで「失敗した」と読める。撮り直しを本人が押したときは出す。

### 渡してよいものだけを控える

- **URL からクエリを落とす。**`?token=…` や `?email=…` の形で秘密が混ざりうる。
  落とすと「どのクエリで失敗したか」は分からなくなるが、
  **分からないことと、漏らすことは釣り合わない。**
- **`http(s)` 以外を弾く。**`new URL` は `javascript:` も `data:` も**解釈に成功する**
  （実測: `origin` は文字列の `"null"`、`pathname` は `alert(1)`）。素直に繋ぐと
  `nullalert(1)` という意味のない行が並ぶ。**解釈できたことは、渡してよいことではない。**
- **入力欄を押しても呼び名を取らない。**値を伏せ字にするのではなく、**行そのものを作らない**
  ——伏せ字は「何かが在った」ことを伝えてしまい、
  **次に「中身も要る」と言われたときに断る理由が無くなる。**
