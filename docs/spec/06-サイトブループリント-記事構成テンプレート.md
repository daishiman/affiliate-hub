## 1. Site Blueprint とは

Site Blueprint は、**1つのサイトの構造・方針・記事雛形をパラメータの集合として固定した再利用可能な設計図**である。プラットフォーム層 §16.2 のブログ作成ウィザード13ステップの出力がこの Blueprint であり、Site Builder はこれを入力にサイトを生成する。

```text
ウィザード13ステップ → SiteBlueprint（パラメータ集合） → Site 生成
                                    ↓
                        ArticleTemplate（記事タイプ別の構成雛形）
                                    ↓
                        ContentPackage → ContentVariant → Publication
```

## 2. SiteBlueprint のパラメータ定義

ウィザード13ステップとの対応を明示する。

```yaml
site_blueprint:
  blueprint_id: string                # 一意ID
  version: string                     # 変更時にインクリメント
  # --- ウィザード step 1: ブログの目的 ---
  purpose:
    primary_goal: enum[収益化, 認知獲得, 見込み客獲得, 情報提供]
    north_star_metric: string         # プラットフォーム層 §27.1
  # --- step 2: ジャンル ---
  genre:
    category_path: string[]           # 例: ["PC", "ノートPC", "クリエイター向け"]
    product_scope: string             # 扱う商品の範囲定義
  # --- step 3: 読者 ---
  audience:
    audience_persona_ids: string[]    # プラットフォーム層 §14
    primary_search_intent: enum[比較検討, 情報収集, 購入直前, 問題解決]
    knowledge_level: enum[初心者, 中級, 上級]
  # --- step 4: 書き手 ---
  author:
    author_persona_ids: string[]      # プラットフォーム層 §13
    fact_boundary_policy: ref         # §13.3。バリアントで変えない事実の定義
    editorial_team: { editor: bool, supervisor: bool }
  # --- step 5: 収益モデル ---
  monetization:
    model: enum[アフィリエイト, 広告, 自社商品, 複合]
    asp_ids: string[]
    disclosure_policy_id: string      # Disclosure の正本
  # --- step 6: ブログパターン ---
  pattern: enum[専門レビュー型, 比較研究所型, 初心者案内型, 個人ブランド型,
                商品発見型, サービス申込み型, ツール型, メディア編集部型,
                ストーリー型, データベース型]   # §16.1
  # --- step 7: カテゴリー ---
  taxonomy:
    categories: [{ slug, name, parent_slug, description }]
    max_depth: int                    # 既定 2
  # --- step 8: 記事タイプ ---
  article_types:
    enabled: enum[ranking, review, comparison, howto][]
    default_template_ids: { ranking: string, review: string, ... }
  # --- step 9: デザイン ---
  design:
    mode: enum[A, B, C]               # jp-web-design の Mode
    color_contract: { primary, accent, surface_scale }
    logo: { present: bool, asset_id: string|null }
    theme: enum[auto, light, dark]
  # --- step 10: ドメイン ---
  domain:
    hostname: string
    canonical_base: string
    robots_policy: enum[index, noindex]
  # --- step 11: 広告・編集ポリシー ---
  policy:
    ad_disclosure_placement: enum[記事冒頭, H1直下, 両方]
    link_rel: ["sponsored", "nofollow"]     # ブログ層 §17.2
    ai_usage_policy_page: bool
    correction_policy_page: bool
    ranking_inputs_allowed: string[]        # ブログ層 §17.4 allowed
    ranking_inputs_prohibited: string[]     # 報酬額は必ずここ（§19.4）
  # --- step 12: 初期コンテンツ計画 ---
  initial_content_plan:
    pillar_articles: [{ article_type, working_title, target_keyword, audience_persona_id }]
    cluster_articles: [{ ... }]
    publish_order: string[]
  # --- step 13: 生成 ---
  generation:
    generation_prompt_version: string       # §07 のプロンプト版
    ranking_model_id: string                # サイト固有。他サイトと共有しない（§16.6）
    differentiation_axes: string[]          # 10軸のうち、このサイトで差別化する軸
```

### 2-1. 検証規則

| ID | 規則 | 失敗時 |
| --- | --- | --- |
| BP-01 | `ranking_model_id` が他サイトの Blueprint と重複しない | BLOCK（§16.6 言い換え記事の防止） |
| BP-02 | `ranking_inputs_prohibited` に報酬関連フィールドが全件含まれる | BLOCK（§19.4） |
| BP-03 | `audience_persona_ids` が1件以上 | BLOCK |
| BP-04 | `disclosure_policy_id` が実在する Disclosure を指す | BLOCK |
| BP-05 | `differentiation_axes` が3軸以上 | WARN |
| BP-06 | `pattern` に対して `article_types` が整合（例: ツール型でランキングのみは不整合） | WARN |

## 3. ArticleTemplate（記事構成テンプレート）

### 3-1. 汎用構造（すべての記事タイプ共通の外枠）

プラットフォーム層 §16.4 とブログ層 §8 を統合した確定順序。`required` は省略不可、`conditional` は条件つき。

| # | セクションID | 名称 | 区分 | 条件 |
| --- | --- | --- | --- | --- |
| 1 | `breadcrumb` | パンくず | required | — |
| 2 | `ad_disclosure` | 広告・アフィリエイト表示 | required | アフィリエイトリンクがある場合は必須。Blueprint の `ad_disclosure_placement` に従う |
| 3 | `h1` | H1 | required | — |
| 4 | `one_line_conclusion` | 一文の結論 | required | — |
| 5 | `dates` | 公開日・更新日・検証日 | required | 検証日は TestRun がある場合 |
| 6 | `byline` | 著者・編集者・監修者 | required | 監修者は `editorial_team.supervisor` が true の場合 |
| 7 | `target_reader` | 対象読者 | required | — |
| 8 | `fit_for` | 向いている人 | required | — |
| 9 | `not_fit_for` | 向いていない人 | required | — |
| 10 | `pros` | 主要なメリット | required | — |
| 11 | `cons` | 主要なデメリット | required | — |
| 12 | `quick_compare` | 簡易比較 | conditional | 比較対象が2件以上 |
| 13 | `toc` | 目次 | required | H2 が4個以上 |
| 14 | `selection_or_method` | 選び方または評価方法 | required | — |
| 15 | `body` | 根拠付き本文 | required | — |
| 16 | `measurements` | 実測・体験・引用 | conditional | TestRun または使用感がある場合 |
| 17 | `conversation` | 会話ブロック | conditional | Blueprint の pattern が初心者案内型・個人ブランド型・ストーリー型で推奨 |
| 18 | `alternatives` | 代替候補 | required | — |
| 19 | `faq` | FAQ | required | — |
| 20 | `final_conclusion` | 最終結論 | required | — |
| 21 | `retailers` | 販売店の選択肢 | conditional | Offer が1件以上 |
| 22 | `sources` | 出典 | required | — |
| 23 | `changelog` | 更新履歴 | required | 2回目以降の更新から |
| 24 | `correction` | 訂正報告 | required | 訂正導線は常設 |
| 25 | `author_bio` | 著者情報 | required | — |

### 3-2. 記事タイプ別の差し込み

`body`（#15）の内部構造だけがタイプごとに変わる。外枠は共通。

| 記事タイプ | body 内部の順序（ブログ層 §9） |
| --- | --- |
| ranking | 用途別ベスト → 比較表 → 評価基準 → 検証条件 → ランキング → 各商品カード → 選外商品 → 方法論 |
| review | 総合評価 → 基本情報 → 入手方法 → 検証条件 → 外観 → 操作 → 性能実測 → 長期使用 → 競合比較 → 注意点 |
| comparison | Aが向く人 → Bが向く人 → 差分表 → 価格差 → 性能差 → 使いやすさ → 弱点 → 用途別結論 |
| howto | 完了後の状態 → 必要時間 → 必要費用 → 事前準備 → 全手順 → 各ステップ成功状態 → エラー対処 → 次の行動 |

### 3-3. ArticleTemplate のパラメータ

```yaml
article_template:
  template_id: string
  article_type: enum[ranking, review, comparison, howto]
  blueprint_id: string                    # 所属 Blueprint
  sections:
    - section_id: string                  # 上表のID
      enabled: bool
      order: int
      heading_pattern: string             # 見出しの型。例: "{用途}なら{商品名}"
      min_words: int
      max_words: int
      required_fact_types: string[]       # 例: ["measured"] → 実測なしでは埋められない
      required_entities: string[]         # 例: ["TestRun", "Evidence"]
      cta: enum[none, internal_link, purchase_link]
  conversation_policy:                    # ブログ層 §11
    enabled: bool
    max_consecutive: 2
    char_range: [40, 120]
    speakers: [ReaderQuestion, GuideAnswer, ReviewerNote, ExpertCaution]
  quality_gates: [QC-01, ..., QC-17]      # §05 §7
```

### 3-4. 検証規則

| ID | 規則 | 失敗時 |
| --- | --- | --- |
| AT-01 | `required` セクションが `enabled: false` になっていない | BLOCK |
| AT-02 | `order` が汎用構造の順序と矛盾しない（前後入れ替え不可の対は #3<#4, #4<#20） | BLOCK |
| AT-03 | `required_fact_types` を満たす素材がない場合、そのセクションは生成せず「未検証」と表示する | BLOCK（空セクションの黙殺を防ぐ） |
| AT-04 | `cta: purchase_link` のセクションより前に `cons` が存在する | BLOCK（§05 §1-9） |
| AT-05 | 同一 Blueprint 内で `template_id` が記事タイプごとに1つ以上 | BLOCK |

## 4. ウィザード（§16.2）との接続

| ウィザード step | 収集する入力 | 書き込む Blueprint フィールド | 既定値（推測して先に埋める） |
| --- | --- | --- | --- |
| 1 ブログの目的 | 目的の選択 | `purpose.*` | 収益化 |
| 2 ジャンル | カテゴリ検索 | `genre.*` | 直近の AffiliateSource から推定 |
| 3 読者 | 読者ペルソナ選択／新規作成 | `audience.*` | ジャンルの代表ペルソナ |
| 4 書き手 | 書き手ペルソナ選択 | `author.*` | Workspace 既定ペルソナ |
| 5 収益モデル | ASP 選択 | `monetization.*` | 受信箱に登録済みの ASP |
| 6 ブログパターン | 10種から選択 | `pattern` | ジャンル×目的から推奨1件を選択済みで提示 |
| 7 カテゴリー | 自動生成の編集 | `taxonomy.*` | ジャンルから3〜5カテゴリを自動生成 |
| 8 記事タイプ | 有効化する型 | `article_types.*` | pattern に対応する既定セット |
| 9 デザイン | Mode/色/ロゴ | `design.*` | Mode A（Graphite × Amber / auto） |
| 10 ドメイン | ホスト名 | `domain.*` | `{slug}.workers.dev` |
| 11 広告・編集ポリシー | 表記位置・rel | `policy.*` | 記事冒頭 + `rel="sponsored"` |
| 12 初期コンテンツ計画 | 記事案の確認 | `initial_content_plan.*` | ピラー1本＋クラスタ5本を自動提案 |
| 13 生成 | 実行 | `generation.*` | — |

### 4-1. ウィザードの操作規律

- **各ステップは既定値を埋めた状態で提示する。** 空欄から始めない（成果物先行）。
- 戻る操作でそれ以降の入力を破棄しない。
- ステップ6でパターンを変えたとき、ステップ8の記事タイプ既定値だけを更新し、利用者が明示的に編集した値は保持する。
- ステップ13の直前に、生成される記事一覧と各記事の必須素材の充足状況（TestRun / Evidence の有無）を表示する。素材不足の記事は「素材不足のため下書きのみ生成」と明示する。**黙って空の記事を作らない。**

## 5. 導出テンプレート例: 「動画編集向けノートPC」ランキング（ASM-001 の適用結果）

参考記事が取得できなかったため、§3-1 と §3-2 の ranking 型から機械的に導出した構成を、実装の初期値として採用する。

```yaml
template_id: tpl-ranking-laptop-video-editing
article_type: ranking
sections:
  - { section_id: breadcrumb, order: 1 }
  - { section_id: ad_disclosure, order: 2, heading_pattern: "本記事にはアフィリエイトリンクを含みます" }
  - { section_id: h1, order: 3, heading_pattern: "{用途}向け{カテゴリ}おすすめ{件数}選（{年}年{月}月版）" }
  - { section_id: one_line_conclusion, order: 4, max_words: 60 }
  - { section_id: dates, order: 5 }
  - { section_id: byline, order: 6 }
  - { section_id: target_reader, order: 7 }
  - { section_id: fit_for, order: 8 }
  - { section_id: not_fit_for, order: 9 }
  - { section_id: pros, order: 10 }
  - { section_id: cons, order: 11 }
  - { section_id: quick_compare, order: 12, required_entities: [Product, Offer] }
  - { section_id: toc, order: 13 }
  - { section_id: selection_or_method, order: 14, required_entities: [RankingModel] }
  - section_id: body
    order: 15
    sub_sections:
      - { id: use_case_best, heading_pattern: "{用途}なら{商品名}", min_words: 40 }
      - { id: comparison_table, required_entities: [Product, TestRun] }
      - { id: criteria, required_entities: [RankingModel] }
      - { id: test_conditions, required_entities: [TestRun], required_fact_types: [measured] }
      - { id: ranking, min_words: 300, max_words: 600 }
      - { id: product_cards, required_entities: [Product, Offer, TestRun], cta: purchase_link }
      - { id: excluded, min_words: 60 }
      - { id: methodology }
  - { section_id: measurements, order: 16, required_fact_types: [measured] }
  - { section_id: conversation, order: 17, enabled: false }
  - { section_id: alternatives, order: 18 }
  - { section_id: faq, order: 19 }
  - { section_id: final_conclusion, order: 20, cta: purchase_link }
  - { section_id: retailers, order: 21, required_entities: [Offer] }
  - { section_id: sources, order: 22, required_entities: [Evidence] }
  - { section_id: changelog, order: 23 }
  - { section_id: correction, order: 24 }
  - { section_id: author_bio, order: 25 }
```
