# 近道契約 (P02)

feature: `feat-site-scoped-authoring-ia` / phase: P02 / 受入: A8

## 1. なぜ要るか

所属替えで 5 画面が `/admin/sites/[site]/...` へ移る。
移った先はサイドバーの `ブログ` 群の中の、さらに 1 本のブログの下にある。
そのままだと、これまで 1 クリックで開けていた読者像が、
「ブログを選ぶ → 読者像」の 2 クリックになる。

A8 は「よく使う画面への到達クリック数が畳む前以下」を要求する。
**畳む前以下**なので、増えた分は戻さなければならない。

## 2. 近道の実体 — 旧入口をそのまま近道にする

**サイドバーに新しい帯を足さない。** 既にある一段目の入口
(`/admin/personas` / `/admin/writing` / `/admin/content`) を消さずに残し、
その行き先を転送の殻にする。押すと `legacyAdminRedirect` が走って
そのときのブログの `/admin/sites/<slug>/...` へ着く。

| サイドバーの項目 | href | 着く先 |
|---|---|---|
| 書き手 | `/admin/personas` | `/admin/sites/<slug>/authors` |
| 書き方の決め事 | `/admin/writing` | `/admin/sites/<slug>/writing` |
| 記事 | `/admin/content` | `/admin/sites/<slug>/articles` |

**サイドバーに出るのはこの 3 つだけである。**
`ADMIN_NAV` (`src/presentation/ui/templates/app-shell.tsx`) の射影条件は
`route.nav !== null && route.label !== null` で、`child()` は `nav: null` を固定する。
`/admin/personas/audiences` (読者像) は `personas` の子なので、
**畳む前からサイドバーには出ていない**。読者像を近道の表に入れない理由はこれである
(`design-review.md` F-02b)。

転送そのものは読者像の旧 URL にも掛かる (`redirect-contract.md` §3 の 7 件)。
サイドバーに出ていないことと、旧 URL を転送することは別の話である。
ブックマークや外部リンクから来る人は旧 URL を踏む。

**別の解決規則を書かないための形である。** 近道用に `resolveSiteSlug` を
もう一度呼ぶ設計にすると、サイドバーを描いた時刻と押した時刻の間に
cookie が変わったとき、ラベルの下の URL と実際に開くブログが食い違う。
href を旧 URL のままにしておけば、解決は**押した瞬間に 1 回だけ**起きる。

### 2.1 なぜ独立した「近道帯」を描かないか

当初案はサイドバー最上部に近道帯を 1 本置く形だった。これを採らない理由が 2 つある。

1. `src/app/admin/layout.tsx` は `AppShell` を描いていない。`AppShell` は各
   `page.tsx` が個別に描く。layout に第 2 のナビを足すと、`AppShell` の
   サイドバーと二重に出る。
2. 近道帯を足すと、同じ画面への入口がサイドバーに 2 つ並ぶ
   (帯の「読者像」と、群の下の「読者像」)。A6 の「ラベルから中身が言い当てられる」は
   入口が一意であることに支えられている。

旧入口を残す形なら、入口の数は変わらず、ラベルも変わらず、クリック数も変わらない。
変わるのは押した後に着く場所だけである。

## 3. ブログが決まらないとき

`resolveSiteSlug` が `null` を返したら、転送先は `/admin/sites` (A3)。
サイドバーの見た目は変わらない。

「読者像」を押してブログ選択が出ることになるが、これは
**ブログが 1 本も無い状態でだけ起きる**。そのときブログ選択は
「まず 1 本作る」以外にやることが無い画面であり、着いた先の画面自身が
なぜここに来たかを言う。静的なリンクのラベルと行き先が常時食い違う状態
(A6 と衝突する) とは別物である。

## 4. 近道は入口を増やさない

旧入口は `ADMIN_NAV_GROUPS` の 5 群の下にそのまま残る (A5 の 5 群を汚さない)。
新しい群も新しい `UNGROUPED_NAV_HREFS` も足さない。

## 5. 到達クリック数の数え方 (A8 の判定式)

サイドバーの根から目的の画面のリンクを押すまでの回数。
群見出しは折りたたみではなく常時展開なので、群を開く操作は数えない。
転送は利用者の操作を要さないので 0 回として数える。

**数える対象は `ADMIN_NAV` の射影であって、手で書いた表ではない。**
手で数えると、子ルートをサイドバー項目と取り違える (実際に一度そうなった: `design-review.md` F-02b)。

| 画面 | 畳む前 | 畳んだ後 | 経路 |
|---|---|---|---|
| 書き手 | 1 | 1 | 旧入口「書き手」→ 転送 |
| 書き方の決め事 | 1 | 1 | 旧入口 → 転送 |
| 記事 | 1 | 1 | 旧入口 → 転送 |
| 読者像 | 2 | 2 | 畳む前: 書き手と読者像 → 読者像 / 畳んだ後: ブログ → 読者像 |
| その他の既存画面 | n | n | 群の下の項目 (畳んでいない) |

判定は `route-inventory.json` の全ルートについて 後 ≤ 前 であること。

## 6. 検証

- 単体: 近道の 3 入口 (`personas` / `writing` / `content`) が
  `ADMIN_ROUTE_METADATA` の `nav` を保っている (サイドバーから消えていない)
- 単体: その 3 入口の href が転送表 `LEGACY_SITE_SCOPED_ROUTES` の鍵に含まれる
- 単体: 全ルートの到達クリック数が 後 ≤ 前
