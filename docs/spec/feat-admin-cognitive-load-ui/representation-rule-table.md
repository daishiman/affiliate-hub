# 情報表現ルール

| 表現 | 選ぶ問い | 必須要素 | 選ばない条件 |
|---|---|---|---|
| summary | いま何が重要か | 指標名、現在値、意味、次の操作 | 詳細を全部並べたいだけ |
| graph | 時間・割合・分布にどんな傾向があるか | 単位、期間、点ごとの値、テキスト要約 | 1 点だけ、正確な値の比較だけ |
| comparison | 候補の差から何を選ぶか | 比較軸、候補名、差、決定導線 | 行の単純検索・保守 |
| table | 複数件を同じ列で探す・並べるか | caption、列見出し、行見出し、sticky header | 1 件の属性、1 列だけの列挙 |
| card | 1 件の主張や入力単位を把握するか | 主張 1、主情報 1、補助 4 以下、主操作 1 | 表と同じ属性のカード反復 |
| board | 手当てが要る件をどれから手当てするか | caption、tone、理由、次の 1 手のラベル、値が出せない理由 | 手当ての要否が無く、ただ引くだけ |
| list | どこへ行くか・どの順に進むか | 項目名、行き先、順序に意味があるか | 列が 2 つ以上要る |
| timeline | いつの予定か | caption、日付、見出し、手当てが要る理由 | 日付が並びの意味を持たない |

## 決定順

1. **手当てが要る件を選び出す画面なら board。** 各件に理由と次の 1 手を付ける。
2. 日付の並びの上に予定を置くなら timeline。
3. 時系列・分布なら graph。正確値は同じ場所の表または要約で補う。
4. 2 件以上を軸で選ぶなら comparison。
5. 多数件を同じ列で探す・引くなら table。
6. 行き先または段階を順に並べるだけなら list。
7. 1 件の判断・入力なら card。
8. 画面冒頭の現在地と優先順位は summary。要約だけで仕事が終わるなら他を足さない。

## table を既定にしない

**1 の判定を飛ばすと、ほぼ全ての画面が 5 に落ちます。** 同種の行が並ぶ画面は
どれも「同じ列で引ける」ため、table の条件だけは常に真になるからです。

2026-08-31 の再判定で、あるべき表現は board 20 / table 24 / card 32 /
list 5 / graph 3 / comparison 1 / timeline 1 でした。それまでの台帳は
table 44 で、差の大半は**画面の目的が「◯◯を確認する」と書かれていた**ことに
由来します。目的が「確認する」なら最適な表現は必ず table になります。

したがって表現を決める前に、`PRIMARY_TASK_BY_ROUTE_ID`
(`src/presentation/admin/admin-screen-task-manifest.ts`) の**具体的な動詞**を読むこと。
「見つける」「選ぶ」「決める」「対処する」なら 1 に該当します。
