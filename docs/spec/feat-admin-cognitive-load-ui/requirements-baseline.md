# 管理画面 認知負荷低減 要求ベースライン

## 1. 目的

運営者が各画面を開いてから「何を見る画面か」「いま何が重要か」「次に何をすればよいか」を迷わず判断できる状態を、全 86 管理画面で保証する。表やカードは目的ではなく、比較・把握・入力という仕事に応じて選ぶ。

## 2. スコープ

- `src/app/admin/**/page.tsx` の 86 画面と、全画面へ届く管理シェル・共通表示部品。
- 情報表現: `summary` / `graph` / `comparison` / `table` / `card`。
- 375 / 768 / 1280 / 1600px、200% zoom、キーボード操作、明暗・強制配色。
- 認証、権限、既存 API、書き込み、副作用の非退行。

## 3. 利用者の判断順

1. ページ名と 1 文の目的を読む。
2. 要約で現在地、異常、優先順位を把握する。
3. 主操作を 1 つ選ぶ。
4. 必要なときだけ比較表・グラフ・詳細開示へ進む。
5. 終了または中断時に戻り先が分かる。

## 4. 必須要件と受け入れ条件

1. 86 画面を台帳化し、目的、主操作、権限、保持情報、削減情報、表現方式、6 状態を決定済みにする。
2. 各画面は目的に応じて主表現を 1 つ宣言し、表現方式に未決を残さない。
3. 表は表示中つねに列見出しを保ち、横スクロールが必要な表は主キー列も固定する。
4. カードは主張 1、主情報 1、補助情報 4 以下、主操作 1 を既定上限とする。
5. 管理ホームから API、endpoint、tool 名、内部実装情報を除き、必要な利用者には設定・道具画面への目的ベースの導線を残す。
6. サイドバーのアイコンと文字の間隔をセマンティック token へ集約し、折りたたみ時も `aria-label` 相当の文字を DOM に残す。
7. 詳細・履歴・内部情報は既定で閉じ、件数と開示内容を `summary` に書く。
8. 公開・削除・外部リンク差し替えは影響プレビューと確認を必須にし、その他の変更は取り消しまたは直前値への復元を用意する。
9. ideal / empty / loading / partial / error / slow の 6 状態を扱う。error は「起きたこと・守られたもの・次の行動」を本文で示す。
10. 仮・確定・上位 n 件などの状態は可視文字とアクセシブルな名前で示し、色だけに依存しない。
11. 375 / 768 / 1280 / 1600px と 200% zoom で、ページ全体の二次元スクロール、フォーカス消失、操作不能を起こさない。
12. 認証・権限、API、書き込み、副作用の契約を変更せず、既存の非退行テストを維持する。

## 5. 非目標

- 新しい業務機能、集計方式、永続化形式、権限の追加・変更。
- API 名や内部構造を管理ホームへ説明すること。
- 見栄えのためだけの装飾グラフ、意味のない KPI、架空データ。
- 公開面のデザイン変更。

## 6. 品質ゲート

- 型検査、lint、unit/integration/acceptance/e2e、production build。
- route 台帳と実ファイルの一対一照合、表・カード・開示契約の静的検査。
- 実ブラウザで代表導線、4 viewport、200% zoom、keyboard/focus、6 状態を確認。
- 認証/API/書き込み境界の既存試験を再実行し、今回差分による失敗 0 件。

## 7. 対応関係

画面単位の決定は [`screen-information-ledger.md`](./screen-information-ledger.md)、表示契約は同ディレクトリの各 contract、検証結果は P06 以降の report を正本とする。
