# 6 状態マトリクス

| 状態 | 表示すること | 次の行動 |
|---|---|---|
| ideal | 本文そのもの。共通の状態サマリを重ねて表示しない (→ 理想時サマリ抑止) | 本文から必要な操作を選ぶ |
| empty | 0 件である理由、異常ではないこと | 最初の 1 件を作る、または戻る |
| loading | 読み込み対象と処理中ラベル | 待つ。focus は動かさない |
| partial | 取得できた範囲、欠けた範囲、安全に使える情報 | 再取得または取得済み範囲で進む |
| error | 起きたこと、守られたもの、次の行動 | 再試行、設定確認、戻る |
| slow | 通常より時間が掛かる処理、継続中であること | 待ち続ける、キャンセル、後で戻る |

状態名は可視文字と accessible name に含め、色だけで区別しない。

全86 routeの6状態すべてを `ADMIN_SCREEN_STATE_CONTRACTS` で、route固有の `event`、確定済みで安全に残せる `safeData`、次の1手 `nextAction` へ結線する。`AdminShell` は実render対象の状態部品から状態を判定し、`AppShell` は全状態を監視用の `data-screen-state-*` へ結ぶ。通常の `ideal` は本文と重複する状態説明を見せず (理想時サマリ抑止)、空・読み込み中・部分・エラー・低速のときだけ、状態名・確定している情報・次にできることを本文先頭へ示す。抑止するのは汎用シャーシが足す共通サマリだけで、業務指標そのものである回復バンドは 0 でも残す (ゼロ保持バンド)。両者の区別は後述「『消す』と『0 で残す』を分ける 2 概念」に従う。`ErrorView` も単独利用時に事象・守られた情報・次の行動を必ず本文へ出す。loading/errorは `src/app/admin/loading.tsx` と `src/app/admin/error.tsx` が無言の空白と復帰不能を防ぐ。

判断に使う数字は `DecisionStatus` の3枝で示す。

| 判断状態 | 可視label | 意味 |
| --- | --- | --- |
| provisional | 暫定 | 観測を続け、まだ確定扱いしない |
| final | 確定 | 確認済みで、この期間の判断に使える |
| insufficient-n | 母数不足 | 必要件数に達しておらず、結論を出さない |

## 「消す」と「0 で残す」を分ける 2 概念

`ideal` の共通サマリは消し、業務の回復バンドは 0 でも残す。**この 2 つは別概念であり、互いの反例ではない。**どちらも「0 件なのに扱いが逆」に見えるため、一方を根拠に他方を崩す誤読が起きた。名前と適用層をここで固定する。規範定義は `system-spec/ui-ux.md` の「状態表示の 2 概念」と同一である。

| 概念 | 対象 | 規則 | 効く層 |
|---|---|---|---|
| 理想時サマリ抑止 | 全画面へ一律に足される共通の画面状態サマリ (状態名・確定している情報・次にできること) | `ideal` のとき**描かない** | 汎用シャーシ (`AdminShell` / `AppShell`) |
| ゼロ保持バンド | 業務ドメインの回復バンド。指標の値そのものが運用情報であるもの | 値が 0 でも枠を**残し**、「対応は要らない」と明言する | その画面に固有の業務指標 |

**どちらを適用するかは、次の一問で決まる。**

> その表示は、**本文の言い換え**か、**本文そのもの**か。

- 本文の言い換え (汎用シャーシが足した状態説明) → 理想時サマリ抑止。`ideal` では消す。重ねても走査量が増えるだけで、判断は 1 つも進まない。
- 本文そのもの (業務指標。値が 0 であること自体が読み手の判断材料) → ゼロ保持バンド。0 でも残す。枠が消えると走査位置が版ごとに動き、開くたびに探し直しになる。

ゼロ保持バンドは、**「0 件で片付いている」と「そもそも数えられていない」を取り違えさせない**ためでもある。数えられないものを 0 と書かない規律は変えない。`unavailable` (いま数えられません) と 0 件 (数えて 0 だった) は別の表示であり、後者へ寄せない。

**この 2 概念は回復手引きの要件を弱めない。**空・エラー・権限不足・縮退・非理想の各状態は、いずれも「起きたこと」「安全に使える情報」「次の 1 手」を本文へ出す。抑止するのは `ideal` のときの重複サマリだけである。ゼロ保持バンドの 0 件表示も「対応は要らない」を明言する点で、次の 1 手を伝える要件を満たす。
