## 0. 先に — P02 / P03 の誤りを 2 件正す

本 phase は受入条件の**原文**（`features/feat-blog-ui-builder.context.json` の
`acceptance` 配列）を正本として照合した。**2 件の誤りが見つかった。**

### 0.1 【重大】A3 の Q4 決着は受入文に反する

**受入 A3 の原文:**

> 公開面で**ヘッダー・サイドバー・フッター**がスクロール中も常時表示され、
> 狭幅ではサイドバーが折りたたまれる

`component-contract.md` §2.2 は Q4 を
「**ヘッダーのみ sticky。フッターは sticky にしない**」と決着させ、
`design-review.md` 観点 3.3 はこれを「妥当」と判定した。

**どちらも誤りである。** 受入文は 3 領域を名指ししている。

§2.2 が挙げた 3 つの理由（フッターの操作はスクロール中に不要／
375px で本文が 2 段分削れる／既存設定が footer に sticky を持たない）は
**それ自体は成立する**。しかし成立する理由があることと、
受入文を設計 phase が書き換えてよいことは別である。

受入を変えるなら、それは**要求の変更**であり、
`features/feat-blog-ui-builder.context.json` の側を直す手続きが要る。
設計文書に「採用しない」と書いて済ませると、
**実装しなかったものが合格したことになる。**

**本 phase の扱い:**

| | |
|---|---|
| テスト | **受入文どおり 3 領域すべてを検査する**（T-A3-1〜3） |
| 現状 | フッターのテストは実装前に**失敗する**。それが正しい状態 |
| 1.4.10 との衝突 | 実在する。**フッターの高さを狭幅で最小化する**ことで両立させる（T-A3-5 が可読領域を数値で見る） |
| 要求変更の判断 | 📋 利用者に差し戻す。設計 phase では決めない |

### 0.2 受入番号のずれ

`theme-contract.md` と `component-contract.md` は
**A8 を「配色を変えても部品は変わらない」として参照している**が、
原文の A8 は「**D1 に永続化され、再読み込み後も保持される**」である。

「配色を変えても部品は変わらない」は受入条件のどれにも対応しない
（実装上の良い性質ではあるが、受入ではない）。

本文書の対応表は**原文の番号**に従う。
P02 文書内の A8 参照は読み替えること（P02 の書き換えは本 phase の scope_out）。

## 2. テストの書き方の制約

本 task の「保守性制約」に従う。

| # | 禁止 | 代わりに |
|---|---|---|
| M1 | pixel 位置への依存 | 可視ラベル・アクセシブル名 |
| M2 | DOM 構造への依存（`div > div:nth-child(2)`） | role・ラベル・テキスト |
| M3 | 実装の内部名への依存 | 返却データの属性・レスポンスステータス |

**例外**: T-A3-5（可読領域 560px 以上）は数値の検査だが、
これは**レイアウトの代償を測る 1 本**であって
「この要素がこの座標にある」ではない。M1 に反しない。
