## 0. この文書の位置づけ

P10 は実装しない。P01〜P09 が作ったものを通しで見て、
**受入 14 件それぞれについて「満たした」と言えるかを判定し、言えないものを名指しする**。

判定の記号は 3 段階である。

- 🟢 **充足** — 受入の文言が要求していることを、証跡で確かめた
- 🟡 **限定付き充足** — 検査は緑だが、受入の文言と検査の対象がずれている。
  「テストが通った」は「要求を満たした」と同じではない
- 🔴 **未充足** — 読者または運営者に見える形で欠けている

🟡 を 🟢 に混ぜないことが、この文書のいちばんの仕事である。
混ぜると「14 件中 13 件充足」と書けてしまい、**ずれの存在が消える**。

## 2. 🔴 A4 — 固定ページが読者に出ない（最大の残件）

### 何が起きているか

`/s/home-office-desk/` に対して固定ページ 8 種を実際に叩いた結果:

```
/profile               404
/sitemap               404
/site-policy           404
/privacy-policy        404
/commercial-transaction 404
/contact               404
/review-guidelines     404
/company               404
```

方針ページ 4 本（`/ai-policy` `/methodology` `/editorial-policy` `/advertising-policy`）
も 404。一方で `/operator` `/privacy` `/terms` `/tokushoho` は 200 を返す。

**同じ「運営者情報」に URL が 2 本あり、片方（`/operator`）だけ 200 で、
もう片方（`/profile`）は 404 である。**

### 原因は 2 つ重なっている

1. **実装** — `site-document-repository.ts` の `KEY_TO_KIND` が
   9 鍵のうち 4 鍵しか対応表を持たない。残り 5 鍵は `NOT_IMPLEMENTED` で断られる
2. **データ** — サンプルの公開投影に固定ページが 1 枚も入っていない

さらに永続層に 3 件の不具合が同居している（P08 §3 で証跡付きに記録）。

| # | 不具合 | 影響 |
| --- | --- | --- |
| 1 | `save()` が `status` を書かない | 新規は `draft` のまま。`[fixedPage]` 経路に永遠に出ない |
| 2 | `findSiteDocument()` が `deletedAt` を見ない | 削除した固定ページが名前付きルートに残り続ける |
| 3 | `findSiteDocument()` が `workspaceId` で絞らない | **別の作業場所の固定ページが読者に出る恐れ** |

**#3 は情報の越境であり、この 3 件の中で最も重い。**
`legal_page` の schema は「1 本のクエリが単体で作業場所に絞れること」を要求し
（`tests/architecture/tenant-scoped-schema.test.ts`）、索引もそう張ってあるのに、
この 1 本だけがそれを使っていない。

### なぜ P08 で直さなかったか

P08 の write scope は `src/app/admin/sites/` 配下と `migration-report.md` で、
不具合の根は `src/infrastructure/persistence/d1/` と `src/domain/blogops/fixed-page.ts`
にある。scope の外を黙って直すのではなく、証跡を残して申し送った。

### 何が要るか

**部分修正では閉じない。** 語彙が 2 系統（`SiteDocumentKey` 9 種 /
`FixedPageKind` 8 種、同じ `legal_page` 表）に割れており、
どちらを正本にするか、名前付きルートと `[fixedPage]` のどちらを canonical にするかを
**同時に決める設計判断**が要る。案 A / 案 B は P08 §3 に書いた。

canonical を決めないまま片方を足すと、同じ内容に URL が 2 本ある状態が固定される。
これは検索エンジンから見て重複コンテンツで、A10〜A13 の成果を削る。

## 3. 🟡 4 件 — 検査は緑だが受入の文言とずれている

### A3 sticky 常時表示

**ずれ**: 受入は「常時表示」と書いているが、この言葉が何を指すか定まっていない。
画面外にはみ出したときに縮むのか、隠れるのか、押し出すのかで挙動が変わる。

**事実**: `tests/acceptance/feat-blog-ui-builder/sticky-layout.test.ts` を含む
6 ファイル 54 件は全合格。Playwright の重なり検査も 77 件 → 0 件になった。

**残るもの**: CSS sticky には非対称性がある。`inset-block-start: 0` は下へ押し出されないが、
`inset-block-end: 0` は上へ引き上げられ、**空けた場所を返さない**。
狭い画面でこれが出たとき「常時表示できている」と言えるかは、文言次第で答えが変わる。

**要ること**: P13 で受入文言を「どの幅で、何が、どう見えていれば合格か」まで下ろす。
実装ではなく言葉の問題である。

### A5 表現ブロック

**ずれ**: 単体テストはブロックの型と変換を検査しているが、
**公開記事に実際に載った状態の実測が無い**。

### A12 SEO 標準ブロック

**ずれ**: 実測でブロックの存在は確認したが、
「標準」の中身（どのブロックが必須か）が受入の文言から一意に読めない。

### A14 出典レジストリ

**ずれ**: 画面と単体テストは緑。ただし `guideline_references` の 90 日判定は
境界値テストで押さえられているものの、**期限切れの出典が実際に画面から消えるところ**の
実測が無い。

## 5. P08・P09 で新たに見えたこと

### 5.1 配色の二重表示を解消した（P08）

`/admin/sites/[site]` は `site_blueprint.theme` の値を「このブログの配色」として
出していたが、P05 以降その値は読者に効いていなかった。
**同じブログの配色について 2 つの管理画面が別の値を出しうる状態**だったのを、
実効値（`publicBlogAppearance()`）の 1 経路に寄せた。

あわせて、P05 で追加されたのに入口が無かった `/appearance` と `/placements` への
導線を足した。住所を知っている人だけが開ける画面は、無いのとほぼ同じである。

### 5.2 視覚回帰の見本が古い（P09、本 package 起因ではない）

`pnpm run visual` が 5 枚中 5 枚で差分。陽性対照は OK なので検査は健全で、
原因は見本の最終更新（`a07a9e0` / 08-28）以降に `src/presentation/ui` が
2 回変わった（`0ed9e2b` / `e97e5bc`、いずれも 08-30、main 済み）まま
撮り直されていないこと。撮影対象の 3 部品は本 package の変更に含まれない。

### 5.3 E2E に 39 件の既存失敗がある

P07 で `source-registries.ts` の回帰を直した結果、spec が初めて走り、
**溜まっていた 39 件が見えるようになった**（439 passed / 39 failed）。
内訳は画面数宣言のずれ 1 件（`toHaveLength(87)` だが実際 115）、
固定ページ 404 が 20 件、管理画面 3 枚が 18 件。
20 件は A4 と同じ根であり、A4 を直せば連動して減る。

### 5.4 不具合を Beads に個別起票できない

このリポジトリでは Beads の課題は dev-graph の node の投影で、
node は feature package に属し **1 package ちょうど 13 個**である。
「拾った不具合を 1 件だけ足す」場所が設計上ない。
迂回して素の `bd create` を叩けば通るが、Beads と dev-graph の状態が黙って食い違う。

したがって残課題は**成果物の文書を経路として P13 へ渡している**（§7）。
