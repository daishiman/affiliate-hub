## 何が残っていたか

`data-floating-overlay` を退避（capture-exclusion.ts）と重なり監査
（tests/e2e/app-routes.spec.ts）が共有する形は P05〜P07 で既に成立しており、
名乗り漏れは tests/ui/floating-overlay-declaration.test.ts が機械で数えていた。

残っていたのは**使う側の単数前提**である。

  tests/e2e/app-routes.spec.ts:192 (変更前)
    const overlay = document.querySelector("[data-floating-overlay]");

`querySelector` は DOM 順の先頭 1 つしか返さない。ところが名乗る側は既に
2 箇所ある（feedback-button.tsx:299 の launcher と :590 の送信 UI）。
退避の側は最初から複数を前提にしているのに、監査の側だけが 1 つを見ていた。

**この食い違いは落ちない。**2 つ目が増えた日、検査は赤くならず
*測る対象が減る*だけである。緑のまま黙る形の壊れ方なので、直した。

## 変更 1: 重なり監査を複数の帯に対応させた

tests/e2e/app-routes.spec.ts の `coveredControls`

  - 名乗っていて可視で、幅と高さを持つ要素を**すべて**集める
  - 帯ごとに個別に判定し、1 つでも取り残す帯があれば取り残されているとする

帯を合成して 1 つの外接矩形にする案は採らなかった。右下と左上に浮遊要素が
ある画面で「画面全体が帯」になり、無関係な操作まで有罪になるためである。

現在の名乗りは launcher 1 つだけ（送信 UI は開くまで DOM に無い）なので、
この変更で判定結果は変わらない。変わるのは**2 つ目が増えた日**である。

## 変更 2: 名乗りすぎの側も数えるようにした

tests/ui/floating-overlay-declaration.test.ts に
「席を持って追従するだけの要素（sticky）は名乗らない」を追加した。

既存の検査は「浮いているのに名乗らない」を数える。逆向き——
「浮いていないのに名乗る」——は落ちずに意味が薄まるので、同じ検査で塞ぐ。

position: sticky を浮遊としない理由も本文に書いた。sticky は流れの中に席を
持ち、追従ヘッダー・表の見出し・目次がそれで、写しに写ってよいし重なり監査でも
席の分の場所を占めている。名乗らせると写しからヘッダーが消え、監査は本物の
重なりを見逃す。この線引きは書いておかないと次に触る人には見えない。

## coveredControls の指摘 3 件について

赤の中に、本 phase が触った `coveredControls` の指摘が 3 画面ある:

  <a> 直す / <textarea> reason ×4 / <button>「…」を担当から外す

これは「本文の下余白が足りず、一番下まで送っても浮いたボタンの帯から
出せない操作」の実在の指摘で、直す場所は `.content` の `padding-bottom`
（ui.module.css）である。名乗る要素が 1 つしかない現状では変更前の単数版と
同一の計算になるため、P08 の変更が新たに生んだ赤ではない。
