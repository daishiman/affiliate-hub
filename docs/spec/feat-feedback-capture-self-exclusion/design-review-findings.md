# 設計レビュー — 三つの失敗様式に対する遮断根拠

**phase**: P03 / SYS-FB-CAPTURE-EXCLUSION-P03

## F1: 隠し忘れ（名乗っていない要素が写る）

- **遮断**: 層 1（写しが決まるまで描かない）が初回を覆う。層 2 の名乗り漏れは
  `tests/ui/floating-overlay-declaration.test.ts` が `position: fixed` の側から数えて拾う。
- **残る穴**: `position: fixed` を CSS module に書かず、インラインスタイルや
  他の重なり方（`sticky`・`transform` による浮き）で浮かせた要素は検査に現れない。
  **既知の限界として記録する**（P10 の残課題へ引き継ぐ）。

## F2: 戻し忘れ（隠れたまま残る）

- **遮断**: `hideFloatingOverlays()` は復元手続きを返り値にし、呼ぶ側は `finally` で囲む。
  「隠す」と「戻す」を別の関数として外へ出すと、例外の出た経路だけが戻し忘れ、
  **画面から操作が消えたまま残る**。
- **並行 lease**: `Document` 単位で `activeCount` を共有し、最初の lease が撮影前の値を
  記録する。開始順・逆順のどちらで解放しても退避を維持し、最後の `release` だけが
  元の値へ復元する。
- **二重呼出し**: 各 lease の `restored` フラグで同じ `release` を 2 回数えず、
  他の active lease が立てた印を消さない。
- **検査**: 「撮り終わったら、退避は必ず解ける」「戻す手続きを 2 回呼んでも…」
  「撮影が入れ子でも…」の 3 件。

## F3: 待ちが解けない（押したのに何も起きない）

- **遮断**: `openWhenShotSettles` が解決・棄却・45 秒上限の三方から `open()` を
  1 回だけ呼ぶ。非対応は `canCapture()` が同期で見分け、同じ tick で開く。
- **残る穴**: 45 秒は人が画面を選ぶ時間の見積りで、根拠は経験値である。
  短くすると選択中に UI が開いて写り込み、長くすると放置時の待ちが伸びる。
  **どちらが痛いかは運用で決める**（P12 の運用手順に記載）。

## 判定

三様式とも、機械が検査できる形で遮断されている。
残課題 2 件（`position: fixed` 以外の浮き方 / 上限値の根拠）は
**この feature の外へ持ち出さず、限界として明記する**方針とする。
