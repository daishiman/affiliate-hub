# 共通部品の契約: feat-uiux-overhaul

- graph node: `SYS-UIUX-OVERHAUL-P02`
- 正本: `src/presentation/ui/` (`primitives` / `patterns` / `templates` / `tokens`)
- 既存の作法: `src/presentation/ui/README.md` — 本書はこれを置き換えず、**足りていないものを足す**

## 決めること

1. 3 段階層の責務境界と、新しい部品をどの段に置くかの判断規則 (A6)
2. 重複実装 0 件を機械検査できる形での「重複」の定義 (A6)
3. カード間隔・文章量のトークン規則 (A8)
4. 本 feature で新設する部品の一覧と責務

## 既にあるもの (変更しない前提)

依存の向きは **primitives ← patterns ← templates の一方向**。画面は `@/presentation/ui` からのみ読む。部品は表示だけを行い、データ取得と業務判断を持たない。

`README.md` の「決めてある作法」6 件 (空欄は未入力 / 自動計算値は初期値 / Enter は次の欄へ / 任意に印 / 主操作は 1 画面 1 つ / 実行中は自分で押せなくする) と「4 つの状態と理由表示」は本 feature でも不変とする。

**理由の必須化 (`EmptyView.body`, `ErrorView.body`, `Callout.reason` が型で必須) は本 feature の A10 と衝突しない。** A10 が減らすのは「常時表示の説明文」であって、「操作できない理由」ではない。理由は状態が成立したときだけ出る。

## どの段に置くか

判断は **「仕様を知っているか」** の一点で決める。

| 段 | 仕様を知っているか | 例 | 置いてよいもの |
|---|---|---|---|
| primitives | **知らない** | `Button`, `Field`, `Callout` | どのシステムに移しても意味が通る土台 |
| patterns | **知っている** | `RankingTable`, `DisclosureNotice`, `ApprovalFlow` | この事業の決めごとを形にしたもの |
| templates | 画面の骨格を知っている | `AppShell`, `Page`, `Card` | 並べ方・余白・ナビゲーション |

迷ったときの試し方: **その部品を別事業のリポジトリへコピーして意味が通るなら primitives、通らないなら patterns。** 「広告表記を本文冒頭に置く」は他所では意味が変わるので patterns。「押せる四角」はどこでも同じなので primitives。

**patterns から patterns を読んでよい。** 一方向の制約は段をまたぐときだけに課す。同段内で禁止すると、同じ組み合わせが 2 か所に写る。

## 重複の定義 (A6 の判定規則)

受入条件は「同等 UI の重複実装が 0 件」を要求する。**機械が数えられる形**にする。

### 重複と数えるもの

`src/app/**/*.tsx` の中で、次の両方を満たす塊。

1. **同じ役割の要素を 3 つ以上、同じ並びで持つ** — 役割は JSX のタグ名と、`className` が指す CSS module のクラス名で判定する
2. **その塊が 2 か所以上に現れる** — 完全一致でなくてよい。文字列リテラルと変数参照を伏せた形で一致すれば重複と数える

### 重複と数えないもの

- 1 か所にしかない構造 (将来 2 か所目が来るまで引き上げない)
- `@/presentation/ui` の部品を呼んでいる箇所 (それが共通化の結果)
- `src/presentation/ui/**` 自身の内部 (部品の実装は重複判定の対象外)

### 引き上げ先

重複が見つかったとき、**どの段へ引き上げるかは上記の「仕様を知っているか」で決める**。判断が割れる場合は patterns に置く — primitives に事業の決めごとが混ざる方が、patterns が少し太るより害が大きい。

引き上げの実行は P08 が所有する。本書は判定規則だけを固定する。

## 間隔の規則 (A8-1)

現状は `--space-3` / `--space-4` / `--space-5` が混在し、カードごとに余白が違う。**用途ごとに 1 つへ固定する。**

| 用途 | トークン | 値の意味 |
|---|---|---|
| カード内の余白 (padding) | `--space-5` | 中身と縁の距離。全カードで同一 |
| カード間の間隔 (gap) | `--space-4` | カード同士の距離。カード内より狭くする |
| カード内の要素間 (gap) | `--space-3` | 見出しと本文、行と行 |
| 密に並べる要素間 (gap) | `--space-2` | ボタン列、バッジ列、ラベルと値 |
| 節と節の間隔 | `--space-6` | 話題が変わる境目 |

**カード内 (`--space-5`) がカード間 (`--space-4`) より広い**のは意図的。狭いと、カードの中身同士が隣のカードと近く見えて、どこまでが 1 枚か分からなくなる。

`--space-1` と `--space-7`, `--space-8` は上記以外の個別用途に残す。`ui.module.css` 以外の場所で `padding` / `gap` に生値を書かない。

## 文章量の規則 (A8-2)

| 対象 | 上限 | 現状 |
|---|---|---|
| 画面説明文 (`Page.lead`) | **40 字** | 超過 21 画面 / 32 |
| 常時表示の注意書き (`Callout`) | **1 画面 2 個** | 超過 14 画面 |
| 折りたたみの見出し | 20 字 | — |
| 空・失敗の本文 (`EmptyView.body` 等) | 上限なし | 状態が成立したときだけ出るため |

上限を超えるときは、**画面側に超える理由を書く**。理由の無い超過は違反として数える。`/admin/ui-catalog` は見本帳として除外する (`information-priority-map.json` の `exempt_from`)。

`lead` の 40 字は型では止められない (実行時の文字数)。P09 の機械検査で数える。

## 新設する部品

### templates

| 部品 | 責務 | 使う画面 |
|---|---|---|
| `RecordForm` | 作成・編集フォームの骨格。保存・やめるの配置、実行中の抑止、戻り先の保持 | 新設の作成・編集 7 画面 |
| `RecordList` | 一覧の骨格。絞り込み・行・空・失敗・新規作成の入口 | 一覧 4 画面 |
| `IndexPage` | 索引画面の骨格。子画面への行き先を並べるだけ | `/admin/settings`, `/admin/generation` |
| `Section` | 折りたたみ可能な節。初期の開閉を指定できる | 参照専用画面すべて |

`Section` は既存の `patterns/disclosure.tsx` とは別物。あちらは**広告表記** (`DisclosureNotice`) で、事業の決めごと。`Section` は開閉の仕組みだけを持つので templates に置く。名前が紛らわしいので、実装時に `disclosure.tsx` へコメントで両者の別を書く。

### patterns

| 部品 | 責務 | 受入条件 |
|---|---|---|
| `DeleteConfirm` | 削除の確認。何が消えるか・戻せるかを出す。関連が残っていれば件数を出して止める | A2 |
| `ChannelStatusList` | 記事の配信先ごとの状態。失敗理由を併記する | A3 |
| `ChannelBadge` | 配信先 1 つの表示。ラベル・アイコン・投稿方式を能力表から引く | A3, A4 |
| `ConceptMatrixLauncher` | 商品から複数ブログ × 切り口を選んで生成を始める | A5 |

`ChannelBadge` と `ChannelStatusList` は **`ChannelKind` で分岐しない**。表示に要る値はすべて能力表から受け取る。詳細は `sns-provider-contract.md`。

### primitives

| 部品 | 責務 |
|---|---|
| `Icon` | Lucide の単色ストロークアイコン 1 つ。`IconName` で引き、16/20px・同一線幅で描く。読み上げには名前を渡さない (隣の文字が持つ) |

`Icon` が primitives なのは、絵柄そのものは事業の決めごとを持たないため。**どのアイコンをどの項目に割り当てるか**は `ADMIN_ROUTE_METADATA` が持つ。
Unicode 絵文字・手製 SVG・画面からの Lucide 直接 import は使わない。ページやセクションの
タイトルは文字を主役とし、識別や操作を速めないアイコンを一律には付けない。

### app-shell の変更 (A9)

管理route metadataのナビ要素型を変える。

- `icon` を**必須**フィールドとして追加する。未設定は型検査で止まる
- 各ナビ項目が `group` を持ち、`ADMIN_NAV` と `ADMIN_NAV_GROUPS` は同じ `ADMIN_ROUTE_METADATA` から導出する
- 折りたたみ状態と、子画面にいるときの親の現在地判定を `AppShell` が持つ

導出への反転は、`groupedNav()` の入出力を変えずに行える。画面側は触らない。

## 検査できる形

P09 が次を機械検査する。本書はその入力を与える。

| 条件 | 検査対象 | 判定 |
|---|---|---|
| A6 | `src/app/**/*.tsx` | 上記「重複の定義」に一致する塊が 0 件 |
