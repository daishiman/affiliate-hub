# 画面の規則（feat-uiux-overhaul / P12）

作成日: 2026-08-22

## この文書の位置

[`component-contract.md`](./component-contract.md) は**着手前に決めた約束**で、
本書は**実装後にいま実際に成立している規則**である。両者は役割が違う。

| 文書 | 何が書いてあるか | ずれたときどちらが正しいか |
|---|---|---|
| `component-contract.md` | P02 の時点でこう作ると決めたこと | — |
| **本書** | 現在の実装で成立している値と、破ったときに止まる場所 | **本書**（実測が正本） |

契約と実装がずれている箇所は、隠さず §3 と §6 に書いた。

規則の目的は美観ではない。**渡さなくてよい情報を渡さないこと**であり、
そのために「どこまでが 1 枚か」「今どこにいるか」を目で分かる状態に保つ。

---

## 1. 間隔

### 値

| 用途 | トークン | 実物 |
|---|---|---|
| カード内の余白（padding） | `--space-5` | `ui.module.css` の `.card` |
| 画面の縦の間隔（gap） | `--space-4` | `.page` |
| 見出しと説明文の間 | `--space-2` | `.pageHead` |
| 節と節の間 | `--space-6` | — |

**カード内（`--space-5`）がカード間（`--space-4`）より広い。** 逆にすると、
カードの中身が隣のカードと近く見えて、どこまでが 1 枚か分からなくなる。
近接の原則そのもので、狭い方が「同じ群」に読める。

### 守り方

- `padding` / `gap` に**生の数値を書かない**。`px` も `rem` も禁止。
  1 か所でも混ざると、そこだけ規則の外側になり、次に触る人がそれを真似る。
- 縦の間隔は `.page` が 1 か所で持つ。画面ごとに `margin` を足さない。
- 指の当たり判定の値（`--tap-target-min`）を**行送りに流用しない**。
  押せる大きさと読みやすい行間は別の量で、片方を動かすともう片方が壊れる。

### 分類の境目

サイドバーの分類の境目は、**線と余白の両方**で作る。線だけだと弱く、
余白だけだと分類の存在が伝わらない。線を引くのは
`.navGroup + .navGroup`（隣り合わせの規則）ただ 1 つで、
**分類が 6 つなら線は 5 本**になる。各分類に線を付けると先頭にも線が出て、
「その上に何かある」と読めてしまう。

## 2. 文章量

### 上限

| 対象 | 上限 | 例外 |
|---|---|---|
| 画面の説明文（`Page.lead`） | **40 字** | なし（見本帳も守る） |
| 常時表示の注意書き（`<Callout>`） | **1 画面 2 個** | `/admin/ui-catalog` のみ |

### 実測（2026-08-22）

```
npx vitest run tests/ui/uiux-spacing-and-copy.test.ts
→ 111 passed
```

49 画面すべてが上限内。**超過 0 件。**

### 今の値は、表に書かない（解決済み・`ah-1kz`）

`information-priority-map.json` には `current_totals` という節があり、
`screens_over_lead_limit: 21` / `screens_over_callout_limit: 14` を持っていた。
`measured_at` は「P07 (2026-08-22)」。**この 2 つは実測ではなく**、
`baseline_totals`（P01 / 32 画面時点）の写しがそのまま残ったものだった。

ずれても誰も気づかなかった理由は、その値を**読んでいるコードが 1 行も無かった**こと。
参照はすべて文書側で、文書は自分が引用した数が古いかどうかを知らない。

2026-08-22 に `current_totals` を丸ごと削除し、代わりに
`current_measurement`（数を持たず、測る検査の在り処だけを書く節）を置いた。
表が手書きの集計値を持ち直したら
`uiux-spacing-and-copy.test.ts` の「表が手書きの『今の値』を持たない」が赤くなる。
節の**名前ではなく数が在るかどうか**で見ているので、名前を変えても通らない。

`baseline_totals` は残してある。あれは今の値ではなく **P01 の固定点**で、
動かさないことに意味がある。動く値（検査が測る）と動かない値（基準）を分けた。

### 上限を超えたいとき

**画面側に超える理由を書く。** 理由の無い超過は違反として数える。
検査そのものを緩めない（`LEAD_MAX` を上げない）。上限は検出器であって
数合わせの目標ではなく、上げた瞬間に何も検出しなくなる。

金銭・秘密・公開に関わる注意は**消さない**（`never_drop`）。
2 個の枠に収まらないなら、消すのではなく**押す物の隣へ移す**。

### 何を「常時表示」と数えるか

**初期表示に出ているかどうか**で判定する。DOM から消えているかは問わない。
折りたたみの中に入れたものは常時表示ではない。この判定は
`information-priority-map.json` の `rules.measurement` が正本。

## 3. サイドバーの構成

### いまの形

- 項目 **19 件**（`ADMIN_NAV`）
- 分類 **6 つ**（`ADMIN_NAV_GROUPS`）: 素材 / 書く / 出す / 稼ぐ / 見る / 整える
- 分類の外 **1 件**（ホーム。先頭に単独で置く）

分類は機能名からではなく、**誰がどの場面で開くか**から導いている。
各画面の `lead` が根拠。機能名で括ると「設定」の中に性質の違うものが集まる。

### 項目に必須のもの

| 欄 | 必須 | 破ったとき |
|---|---|---|
| `icon` | **必須**（型） | 型検査で止まる |
| `requires` | 必須（`null` 可） | 型検査で止まる |

- **アイコンは項目ごとに違うものにする。** 畳んだ状態で残るのはアイコンだけなので、
  重なった 2 項目は畳んだ時点で見分けが付かない。検査が重複を落とす。
- **アイコンに意味を持たせない。** 意味は `label` が持ち、アイコンは読み上げから隠す。
  絵に意味を載せると、その絵を知らない人に何も伝わらない画面になる。
- `requires` は名前を書くだけで、誰が持つかの判定は domain 側が決める。
  **見せない判断を画面ごとに書かない。** 1 画面でも書き忘れると、
  押しても必ず断られるリンクが残る。

### 畳んだときに保たれること

| 保たれるもの | 理由 |
|---|---|
| 19 項目すべての名前 | 見えないだけで、読み上げには残る |
| 19 項目すべてへの経路 | 畳むのは幅の話で、行けなくなってはいけない |
| 19 項目すべてが Tab の順路に残る | 順路から外すと、キーボードだけの人に画面が消える |
| 移動の順番を手で決めていない | `tabindex` を振ると、項目を足した日に順路が狂う |

折りたたみの操作点は `button`。開閉の状態は操作点自身が持つ。

### route metadataからの導出

`ADMIN_ROUTE_METADATA` の各ナビ項目が自分の `group` を持つ。
`ADMIN_NAV` と `ADMIN_NAV_GROUPS`、パンくず、描画検査のroute表はそこから導出する。
画面追加時に別々の表へ同じrouteを書き写さない。

実URL (`actualRoutePath`) とサイドバーの現在地 (`navContextPath`) も同じmetadataから
別々に解決する。子画面の実URLを親routeへ潰して計測しない。

## 4. 情報の優先度

各画面について、項目を 3 つに分ける。正本は
[`information-priority-map.json`](./information-priority-map.json) の `screens`。

| 区分 | 意味 | 落とし方 |
|---|---|---|
| `keep` | 主タスクの判断材料そのもの | — |
| `drop` | この画面の主タスクに要らない | `remove` / `collapse` / `on-demand` |
| `transform` | 残すが形を変える | — |

順位は **task 頻度 × 失敗コスト**で決める。`task_frequency` と `failure_cost` を
各画面が持っている。頻度が高く失敗コストが低い画面（例: `/admin`）は
迷わせない方を優先し、失敗コストが高い画面は確認材料を残す。

**画面を足したら、この表にも行を足す。** 表に無い画面は照合されない。
P07 で実際にこれが起きた — 分割で生まれた 17 画面が表に無く、
検査は残る 32 件を全部緑にして「満たした」と報告していた。

| 規則 | 止まる場所 | 止まり方 |
|---|---|---|
| カード内 padding が `--space-5` でない | `tests/ui/uiux-spacing-and-copy.test.ts` | 赤 |
| `padding` / `gap` に生値 | 同上 | 赤 |
| 行送りに当たり判定の値を流用 | `tests/ui/layout-density.test.ts` | 赤 |
| 分類の線が隣り合わせ規則以外 | 同上 | 赤 |
| `lead` が 40 字超 | `tests/ui/uiux-spacing-and-copy.test.ts` | 赤（画面ごとに 1 件） |
| `Callout` が 3 個以上 | 同上 | 赤（画面ごとに 1 件） |
| アイコンの重複 | `tests/ui/uiux-sidebar-icons.test.tsx` | 赤 |
| アイコン未設定 | `tsc` | 型エラー |
| 畳んだ状態で項目が消える | `tests/ui/uiux-sidebar-icons.test.tsx` | 赤 |
| 優先度の表に無い画面がある | `tests/ui/uiux-spacing-and-copy.test.ts` A10 §2 | 赤 |

**どれも「上限を上げる」で緑にしない。** 上限は検出器であり、
上げると検出をやめるだけで、規則が満たされたわけではない。

## 7. 読ませる文の書式は画面側の CSS に置かない（2026-08-22 / `ah-jbj`）

見出しを伴わない説明文には **`Prose`** を使う。
画面側の CSS Module（`admin.module.css`）に同じ書式を書かない。

**元の形。** `.sectionLead`（`admin.module.css`）と `.lead`（`screen-parts.module.css`）は
**1 行も違わない同じ宣言**だった。css の置き場所が 2 つに分かれていたのが問題に見えるが、
実体はそこではない——**見出しを伴わない文を置く口が無かった**ので、
画面が自前で書式を書いていた。口は `Prose` として既に在ったので、
見本帳の 4 箇所を `Prose` へ寄せて `.sectionLead` を消した。

**併せて見本帳の写しも消した。** 見本帳には `.densityProseFixed`（「直したあと」の見た目を
写したもの）が置かれていたが、これも削除して**実物の `Prose`** を置いた。
見本が写しだと、`Prose` を直した日に見本だけが古くなる。

**破ったときどこで止まるか**: `tests/ui/layout-density.test.ts`。
検査は「どの css にあるか」ではなく
**「画面側の css が読ませる文の書式を持たないこと」**を見る——
`admin.module.css` のどれかの class に `--readable-max-width` が現れたら赤くなる。
名前を `.sectionLead` から変えて書き戻す逃げ道は、これで塞がっている。
