# 運用手順 — ブログトップページ構成 MVP

## 日常確認

1. 公開トップで、おすすめ → 最新/人気 → カテゴリー → 全記事の順になっていることを確認する。
2. `?sort=popular` へ直接移動し、JavaScript に依存せず人気側を選べることを確認する。
3. 記事0件・カテゴリー0件・おすすめ0件で、無言の空白ではなく理由が表示されることを確認する。
4. 検索導線が通常のリンクとしても機能し、JSON-LD の検索URLと一致することを確認する。

## 障害時の切り分け

| 症状 | 最初に見る場所 | 対応 |
|---|---|---|
| おすすめが出ない | 公開可能記事と推薦関係 | 非公開記事を無理に表示せず、選定と公開可否を分けて確認する |
| 最新/人気が同じ | URL の `sort` と reader projection | クライアント状態だけで切り替えず、URL入力を再現する |
| カテゴリーが空 | blueprint のカテゴリー正本 | 記事カードの再掲で埋めず、索引の空状態を保つ |
| JSON-LD順が画面と違う | 可視記事列と ItemList の生成入力 | 同じ並びから派生しているか確認する |
| 版面がずれる | thumbnail URL と width/height | fallback生成は `feat-thumbnail-visual-system` 側で確認する |

## rollback

表示の不具合では、推薦区画の投影を外して既存の canonical 記事区画を残す。
推薦関係や migration を逆向きに削除しない。DB変更を戻す必要がある場合は、バックアップを伴う
forward migration を別タスクとして作る。
