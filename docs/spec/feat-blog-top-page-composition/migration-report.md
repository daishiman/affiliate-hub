# ブログトップ P08 移行レポート

- 対象: `SYS-BLOG-TOP-PAGE-COMPOSITION-P08`
- Beads: `ah-zjvz`
- 実施日: 2026-09-05
- 移行方式: 表示契約を先に固定する段階移行（RED → GREEN → REFACTOR）

## 目的と境界

既存のブログトップで、canonical な記事・カテゴリーと旧 `BlogTopBands` が同じ内容を
別々に描いていた状態を解消し、仕様の4区画目である「おすすめ記事」を実データで表す。
表示の重複解消は P08、公開記事との関係・保存・管理操作は Blog Ops P05、公開面の
投影・URL・JSON-LD はトップ P05 とし、境界を port でつないだ。

思考リセットは成果物の削除ではなく、既存実装を正解と仮定しない再評価として行った。
論理・構造、メタ・発想、システム・戦略・問題解決の3系統へ分け、指定された30思考法を
省略せず適用した。3系統は独立に、次の同じ根因へ収束した。

- トップの情報構造を `SiteHomeContent` と `BlogTopBands` の2箇所が所有していた。
- 記事区画とカテゴリー区画が、旧帯とcanonical区画で重複していた。
- 「公開中の記事をすべて見る」が記事一覧ではなく検索へ向いていた。
- カテゴリー索引が記事カードを再掲し、区画ごとの役割が混ざっていた。
- 「おすすめ」と名乗れる選定データが無く、最新記事の言い換えになる恐れがあった。
- 公開ページが投影と別経路で記事を読み、取得時点のずれと読み取りの重複があった。
- 既存テストが移行前の重複を契約として固定していた。

## 変更内容

| 変更前 | 変更後 | 根拠 |
|---|---|---|
| `latest_posts` と記事区画を両方表示 | 記事区画をcanonicalとし、旧帯から `latest_posts` を除外 | 同じ記事導線の二重表示をなくす |
| `category_hub` とカテゴリー区画を両方表示 | `CategoryDirectory` をcanonicalとし、旧帯から `category_hub` を除外 | カテゴリーを記事再掲ではなく索引へ戻す |
| 姉妹サイト・作り手ナビも主動線より前 | canonical区画の後に補助帯として表示 | 旧設定を保ちながら主動線を一意にする |
| 全記事導線が `/search` | route registry の `blog` を使い `/blog` | 表示文言と遷移先を一致させる |
| カテゴリー0件が空の一覧 | 理由を示す `EmptyView` | 無言の空白をなくす |
| 記事0件でも空の一覧へ誘導 | 記事区画の空理由だけを示し、一覧出口を隠す | 行き止まりへの誘導をなくす |
| 推薦の正本が無い | `blog_home_featured_article` にURL identityと順序を最大3件保存 | 最新記事を「おすすめ」と偽装しない |
| 非公開化で選定intentが消える可能性 | soft relationで保持し、同URLの再公開で自動復帰 | 運営者の意図と現在表示可能かを分離する |
| 投影後に記事を別取得 | `PublicSiteProjection` の公開記事と推薦だけで描画 | 同じ画面の読み取り正本を1つにする |
| 可視順とJSON-LD順が独立 | 推薦→最新/人気の可視順から `ItemList` を組み立てる | 人と機械の観測を一致させる |

新しい汎用コンポーネントは追加せず、既存の `CategoryDirectory`、`ArticleList`、`EmptyView`、
`SiteSection`、`ToolForm`、route registry を再利用した。管理画面の選択・上下移動・解除は
ブラウザ内の下書きとし、保存は1回のatomicな全置換にまとめた。
`BlogTopBands.categories` は既存呼び出しとの後方互換のため入力口だけを残し、
カテゴリー描画の責務は持たせていない。

## 後方互換と非適用

- `sister_sites` と `navigator` は、保存順、任意見出し、空状態、自己サイト除外、
  brand tag 絞り込み、`itemLimit` を維持した。
- `latest_posts` と `category_hub` の設定値は削除・移行しない。公開面でのみcanonical区画と
  重複させない。設定データを残すためrollback時にも再作成は不要である。
- sticky header と footer の部品実装は `feat-blog-ui-builder` 所有のため P08 では N/A。
  P08から別実装を足すと同じ責務が再び二重化する。
- 推薦関係は `published_articles.source_article_id` に依存させない。AI公開などで
  source ID が無い記事も公開URLとして正規だからである。
- 一時非公開の関係行は保持するが公開面からは除外する。`selectedCount` と現在表示可能な
  `articles` を分け、未選定と一時非公開を同じ空状態にしない。

## rollback

次のいずれかが観測された場合に、このP08変更単位をrollbackする。

- 姉妹サイトまたは作り手ナビの保存済み設定が表示されない。
- canonical な記事、カテゴリー、記事一覧への導線が欠ける。
- `/blog`、カテゴリーページ、タグ検索への既存URLが変わる。

rollbackではまず推薦区画の読み取りと管理操作を無効化し、従来のcanonical区画を継続する。
適用済みの `0047` は展開後に逆向き削除せず、未参照の関係表として残す。データ削除が必要な場合は
別のforward migrationとバックアップを用意し、この表示rollbackと混ぜない。
