## 転用禁止ゲートの注記 — 「PASS」の一語に畳まないこと

```
検査したファイル: 49 件
構造で見る検査: 実行
名前で見る検査: 見送り (.reference-ban.local がありません)
転用の疑いは 0 件です。
```

**2 つある検査のうち、走ったのは 1 つである。** 禁止したい固有名そのものを
リポジトリに書けない (書いた時点で転用になる) ため、名前の一覧は追跡されない
`.reference-ban.local` に置く設計になっている。**その file が無い環境では、
名前側は一度も照合されないまま「疑い 0 件」が出る。**

exit 0 は「構造の 49 件に疑いが無かった」であって「名前も確かめた」ではない。
CI でここを本当に効かせるには、名前の一覧を秘匿のまま渡す経路が要る。

## この回で直した「検査そのものの欠陥」

**赤が、コードではなく機械の混み具合で決まっていた。**

全走行を 3 回して、3 回とも 1 件だけ落ちた。**落ちたのは毎回違う検査**だった:

| 回 | 落ちた検査 | 症状 |
|---|---|---|
| 1 | `tests/ui/page-degraded` / `page-empty` の `admin/tools` | 30 秒で時間切れ |
| 2 | `tests/ui/route-branch-reached` | 20 秒で時間切れ |
| 3 | (無し) | — |

同じ検査が、空いている機械では 1 秒未満で終わる。実測 (2026-08-26):
`route-branch-reached.test.ts` は 104 件を 93 秒で走り切っており、1 件あたり約 0.9 秒。
**その中の 1 件だけが 20 秒を超えた。** 画面が重かったのではなく、279 ファイルが
同じ機械を取り合って取り込みが詰まっただけである。

**放置してはいけない理由は、赤が 1 件増えることではない。** 「また例のやつだ」と
読まれる赤が常設されると、**次に本物の赤が出た日も同じように読まれる。**
検査が飾りになる経路はここである。

### 直し方

待ち時間の数字が 3 か所に散らばっていた (検査ファイルの 20 秒・設定の 30 秒・
まとめ描きの 120 秒)。**散らばっている間、直せるのはいつも「今日落ちた 1 か所」だけ**で、
実際に 1 回目を直した後で 2 回目が別の場所から出た。

- 正本を `quality-gates.config.mjs` の `SCREEN_RENDER_BUDGET_MS` / `SCREEN_SWEEP_BUDGET_MS` に
  1 本化し、検査ファイルと `vitest.config.mts` の両方がそこから引くようにした。
- **散らばりの再発を検査で止めた** — `tests/architecture/screen-budget-single-source.test.ts`。
  `tests/ui/` に待ち時間を直に書くと赤になる。母集団の床を同じ `it` の中に置いてある
  (REQ-TS17 の形)。

### 判定は 1 つも緩めていない

待ち時間は**主張ではない。**「断りに置き換わっていない」「空の案内が描かれる」といった
判定は 1 つも動かしていない。ここは違反件数の上限やカバレッジの下限とは性質が違う
——あちらは主張そのものなので、緩めれば守っているものが減る。

**代わりに失われたもの**: 「異常に遅い」を掴む力。ただし**それはもともと掴めていなかった**
(0.9 秒と 20 秒が同じ緑だったのだから)。描画の費用を見張るものは、いまどこにも無い。
時計で測る判定は取り合いの山を拾うので、そこに足すのは誤り。この穴は
`quality-gates.config.mjs` の説明にそのまま書いてある。
