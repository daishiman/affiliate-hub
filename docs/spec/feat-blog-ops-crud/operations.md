# feat-blog-ops-crud — 運用手順

対象: 管理画面からブログ 1 つを立ち上げ、記事を出し、出したものが本当に
出ているかを確かめるまで。読む人は**運営者**であって開発者ではない。

正本は実装 (`src/app/admin/**`) で、この文書は**順番**を持つ。
画面の一覧そのものは `screen-inventory.md`、口の形は `api-contract.md`、
表の形は `data-model.md` が持つ。ここで重複させない。

## 0. 前提 — 誰が何をできるか

| することの種類 | 要る権限 |
|---|---|
| 一覧を見る・記事を読む | `content.read` |
| 記事・タグを書く | `content.write` |
| サイト網・版面・固定ページ・配信部品を触る | `site.manage` |
| 読者が評価を送る | 権限不要 (読者経路) |

**「見える」と「触れる」を分けてある。**権限が無い人には、
できない操作が**灰色で残る**のではなく、断りとして返る
(`FORBIDDEN` + `suggestedAction` に必要な権限の名前)。
灰色で残すと、押せない理由を運営者が推測することになる。

## 1. ブログを 1 つ立ち上げる

1. `/admin/sites/new` — サイトを作る。合言葉 (slug) は後から変えない前提で決める。
   公開面の住所 (`/s/<slug>/...`) がこれで決まる。
2. `/admin/site-network/new` で節点と親子を決め、
   `/admin/site-network/[node]` で変更する。子サイトは親を指す。
   **親を消す前に子を移す。**参照中の子が 1 件でもあると、
   親の削除は全体を断る。子を宙に浮かせた成功は返さない。
3. `/admin/blog/layout` — 版面。脇の枠 (通常 8 + 追従 2) と、トップの帯を並べる。
   **既定の並びは無い。**入にしたものだけが公開面に出る。
   ここで消した枠は公開面から消える (画面側に既定を持たせていないため)。
4. `/admin/blog/pages` — 固定ページ 8 種。運営者情報・お問い合わせ・
   プライバシー・広告表記など。**広告表記は先に作る** — 記事を出してから
   足すと、出した記事に表記が無い期間ができる。
5. `/admin/blog/tags` — タグ。**種類 (`brand` / `topic`) を選ぶ。**
   既定は `topic`。ブランド枠に出るのは `brand` だけで、
   一覧は総数と別に**ブランドの件数**を出す。総数だけ見ていると
   「タグは 20 件あるのに枠は空」を、読者の画面を開くまで気づけない。

## 2. 記事を出す

1. `/admin/blog/articles/new` — 記事型 (T1〜T4) を選んで作る。
   **型を選ぶと必要な部品が決まる。**後から型を変えると足りない部品が出る。
2. `/admin/blog/articles/[article]` — 本文の部品を入れる。
   - **「足りない」と「並びが違う」は別の枠で出る。**直し方が違うため
     (足す / 動かす)。並びのずれで公開は止まらない。
   - 動かす手段は「1 つ上へ / 1 つ下へ」。**保存を待たずに数え直す**ので、
     動かした結果はその場で分かる。
   - 商品カードは記事型ごとに決まった位置へ**自動で再掲される**。
     3 回入れる必要はない (入れると 3 回ぶん重なる)。
   - 目次は部品から**自動で組む**。番号を手で打たない。
3. 公開する。公開していない記事は sitemap にも RSS にも出ない。

## 3. 出したものが本当に出ているかを確かめる

`/admin/blog/delivery`

**上の「経路」は設定** — 何を出す / 出さないか。
**下の「点検」は結果** — 実際に出せたかどうか。**この 2 つは別のもの**で、
入にしたまま材料が欠けていても、設定の一覧は何も言わない。

1. 「いま点検する」を押す。9 種を組み立て直し、結果が表に残る。
2. 表の日時は**その結果がいつのものか**を表す。設定を変えても日時は動かない。
3. 状態は 4 通り。

   | 状態 | 意味 | すること |
   |---|---|---|
   | 出せています | 通った | 無し |
   | 材料が足りません | 入だが通らない | 「見たこと」の文を読んで直す |
   | まだ点検していません | 一度も押していない | 押す |
   | 出さない設定です | 切ってある | 出したいなら経路を入にする |

**「まだ点検していない」を「問題なし」と読まない。**見ていないことは、
良いことでも悪いことでもなく、見ていないとしか言えない。

点検の深さは部品で違う。sitemap と robots は**本当に組み立てて**
結果を数える。残り 7 種は**材料が揃っているかを見る**。
どちらで見たかは各行の「見たこと」に書いてある。

**点検は保存と別の口。**保存のついでに点検すると「保存したから緑」になる。
押した時刻の結果が 1 件ずつ残ることに意味がある。

## 4. 読者の評価を見る・伏せる

- `/admin/blog/evaluate` — 記事ごとの平均と件数。
  **票が 5 件に満たないうちは目安を出さない。**1 件の 5 点で
  「評判が良い」と読める表示にしない。
- `/admin/blog/evaluate/[article]` — 1 件ずつ。
- **伏せるのは消すことではない。**行は残して印だけを付け替える。
  消す形にすると「伏せた」と「最初から無かった」が同じ姿になり、
  伏せた判断そのものを後から確かめられない。
  **理由が要る** — 監査に `blog_rating.hidden` として理由ごと残る。
- 伏せたものは公開面の平均と件数から外れる。運営側の画面には出続ける。

## 5. 消す

記事・固定ページ・サイト網の節点を消すときは**理由が要る**。
監査に `blog_article.deleted` / `blog_page.deleted` / `site_network.deleted` として理由ごと残る。
3 種とも行を物理削除せず、所有者が削除済み一覧から元の ID・URL・本文へ戻せる。
固定ページは通常の保存で暗黙に戻さず、必ず「元の内容で戻す」を使う。
サイト網は `/admin/site-network/deleted`、記事は
`/admin/blog/articles/deleted`、固定ページは同じ `/admin/blog/pages` で戻す。

**消す順序**: 子 → 親。参照中の子がある親の削除は全体を拒否する。

## 6. 何かがおかしいときに見る場所

| 症状 | 見る場所 |
|---|---|
| 公開面に枠が出ない | `/admin/blog/layout` で入になっているか |
| ブランド枠が空 | `/admin/blog/tags` の**ブランドの件数** (総数ではない) |
| sitemap に記事が無い | その記事が公開済みか。`/admin/blog/delivery` で点検 |
| 記事の警告が消えない | 「足りない」か「並びが違う」か。枠が別なので読み分ける |
| 誰かの操作を追いたい | 監査記録。理由つきで残っている |

## 7. この手順が守っていること

- **設定と観測を混ぜない** (3 章)。混ぜると「設定したから大丈夫」になる。
- **消さずに伏せる** (4 章)。判断を後から確かめられる状態を残す。
- **規則は 1 か所** — 部品の並び・目次の段・カードの再掲位置は
  `src/domain/blogops/article-outline.ts` の表が正本で、画面は結果を描くだけ。
  画面に書くと、記事の画面が増えた日に対応が枝分かれする。
