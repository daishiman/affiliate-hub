# 断りと注意書きの設計 — ブログごとの管理画面 (feat-blog-scoped-admin-console)

P02 の成果物。読めない・足りない・失敗したをどう出すか。

## 上限がある

`tests/ui/uiux-spacing-and-copy.test.ts`:

```ts
const LEAD_MAX = 40;
const CALLOUT_MAX = 2;
```

| 何 | 上限 |
|---|---|
| 画面の説明文 | 40 字 |
| 常時表示の注意書き（`<Callout>`） | 1 画面 2 個 |

### なぜ上限を置くか

```
上限は「読む量を減らす」ためだけに置いているのではない。**画面ごとに違う書き方が
混ざること自体**が負荷になる。同じ意味の余白が画面ごとに違うと、目は毎回
「これは同じ塊か、別の塊か」を数え直す。
```

**揃っていることが目的で、短いことは手段。**

## 上限のある画面で 3 つ目を出したいとき

`/admin/sites/[site]` は既に 2 個使っている。

配色が解けなかったことを伝えたいが、`Callout` は使えない。

```tsx
{appearance.resolved ? null : (
  <Prose>
    保存された配色をまだ読めていません（保存先につながっていないか、このブログの配色を
    1 度も保存していない）。下の値は設計図の既定で、保存先のある実行では別の色が出ます。
  </Prose>
)}
```

**地の文（`Prose`）で断る。**

### 上限を上げる選択をしなかった

`CALLOUT_MAX` を 3 にすれば `Callout` で出せた。

そうしなかったのは、
**上限を上げる理由が「この画面で 3 つ目が要る」だけ**だから。

上限は全画面の揃いのために置いてある。
1 画面の都合で動かすと、次の画面も同じ理由で動かせる。

### 何が `Callout` に残るか

```
3 で落とした断り書きのうち、金銭・秘密・公開に関わるものは消さず、
**押す物の隣へ移す**。4 の枠には数えない。「画面のどこかに書いてある」より
「押す物の隣に書いてある」ほうが、押す前に読まれる。
```

| 種類 | 置き場所 |
|---|---|
| 金銭・秘密・公開に関わる | 押す物の隣（枠に数えない） |
| 常に効いている前提 | `Callout`（2 個まで） |
| いま解けなかった | 地の文 |

**「押す物の隣」が最も読まれる。**

画面の上に書いた注意は、
押す瞬間には視界の外にある。

## 断りの出し場所

`blog-ops-console-forms.test.tsx`:

- 「住所の形が違うという断りは、住所の欄に出る」
- 「欄の名前が付かない断りは、フォームの結果として出る」
- 「構えの断りは、その欄（名乗る名前）に出る」

**原因になった入力欄に出す。**

| 断り | 出る場所 |
|---|---|
| 住所の形が違う | 住所の入力欄 |
| 名乗る名前が空 | 名乗る名前の欄 |
| 権限が無い | フォームの結果 |
| 保存先につながっていない | フォームの結果 |

欄を特定できない断りだけがフォーム全体に出る。

### 全部フォーム全体に出さない理由

3 つの欄があって 1 つが不正なとき、
フォームの上に「入力に誤りがあります」と出しても、
**どの欄かを目で探すことになる**。

欄に出せば探さなくてよい。

## 空の表を出さない

`blog-metrics-pages.test.tsx`:

- 「読者の行動: なぜ空なのかを本文で言う」
- 「記事ごとの成果: なぜ空なのかを本文で言う」
- 「記録はあるが成果の付いた記事が 1 本も無いときは、表を空で出さない」

**空の表は「0 件」と「読めなかった」を区別できない。**

| 状態 | 出すもの |
|---|---|
| 保存先につながっていない | その旨を本文で |
| 記録が 1 件も無い | まだ記録が無い旨 |
| 記録はあるが該当 0 件 | 該当が無い旨（表を出さない） |
| 該当あり | 表 |

3 つ目が特に間違えやすい。
記録はあるのに表が空だと、
「集計が壊れた」と読まれる。

## 根拠が足りないとき

```ts
export const MIN_EVIDENCE_SAMPLES = 30;
```

30 件未満は、**数字は出して読み方だけ伏せる**。

```
足切り未満だと、読み方の代わりに理由が出る
```

「クリック率 50%」が 2 件中 1 件なら、
数字は正しいが読み方が付けられない。

数字ごと隠すと「記録が無い」に見える。
読み方だけ伏せれば「まだ判断できない」が伝わる。

## 失敗の履歴

`blog-ops-console-forms.test.tsx`
「直近の失敗があれば、その文言を行に出す」。

住所の登録は非同期で進む。
証明書の発行が失敗したことは、
**次に画面を開いたときに行へ出る**。

その場のフォーム結果として出すと、
画面を閉じた時点で消える。

失敗の理由は保存して、行に持たせる。

## 押せないものを押せる形にしない

`blog-ops-console-forms.test.tsx`:

- 「配信できていない住所は『読者へ見せる』を選べない」
- 「いま見せている住所には、もう一度見せる操作を出さない」
- 「取り下げ済みの住所には、取り下げの欄も押しボタンも出さない」
- 「いま見ている幅は、押せる案内にしない」

**押せない操作を出して、押した後に断らない。**

出さないのが第一で、
`disabled` で出すのが第二。

いま見ている幅を押せるリンクにすると、
押しても何も変わらない。
リンクに見えて反応しないものは、壊れて見える。

## 押せない要素に `onclick` を付けない

`blog-ops-console-forms.test.tsx`
「操作は button であって、押せない要素に onclick を付けていない」。

`<div onClick={...}>` はマウスでは押せるが、
キーボードでは辿り着けない。

読み上げソフトは「押せるもの」として読まない。

**押せるものは `<button>` か `<a>`。**
