## 品質ゲート

この feature が原因ではない。上限は上げていない。

## この feature の中心

**`analytics` の下に置かなかったこと。**

コードとしては 1 行の判断:

```ts
"sites/[site]/audience": child("sites/[site]", "読者の行動"),
```

`analytics` の下に置いても動く。
テストも通る。画面の中身も同じ。

違うのは、
**選択欄で切り替える形になるかどうか**だけ。

選択欄があると、
選び忘れたまま別のブログの数字を読める。

URL に `site` が入っていれば、それが起きない。

この判断はコード内のコメントに残してある。
消さないこと。

## 残る弱点

### 1. `actions` の足し忘れを機械が検出しない

`design-review-findings.md` F-01。

P05 で実際に起きた失敗と同じ形が、
再び起こりうる。

防御はコメント 1 行のみ。

### 2. `required-test-types` が上限ちょうど

未宣言 5 / 上限 5。

次に要件を 1 件足して
宣言を書き忘れると赤になる。

**余裕が無いことを緑が隠している。**

### 3. `port-wiring` が赤のまま

隣の feature 由来。

`docs/product/port-wiring.md` の注記
「（現在 5 件。上限も 5。）」が
表の 6 行と食い違ったままにしてある。

**食い違いが、赤である印。**

### 4. `sites/[site]` に節が 5 つ

説明文 40 字では中身を説明しきれない。

上限が守れているのは、
説明文が中身を説明していないから。

`design-review-findings.md` F-03。

### 5. `sites` 一覧に数字が無い

どのブログを見るか決めるのに、
全部開かないと分からない。

F-07。合算画面との境界の判断が要る。

### 6. `Callout` の数え方が正規表現

別名を付ければ上限を超えても検出されない。

F-02。書き方を揃えることで担保している。
