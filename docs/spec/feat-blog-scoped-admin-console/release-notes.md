# リリースの説明 — ブログごとの管理画面 (feat-blog-scoped-admin-console)

P12 の成果物。

---

## 中学生にもわかる説明

### 何が困っていたか

ブログを何本も運営していると、
管理画面で「今どのブログの話をしているか」が
分からなくなる。

前は画面の中に**切り替えの選択欄**があった。

A のブログの数字を見た後、
B のブログの画面を開いても、
選択欄が A のままだと A の数字が出る。

**画面はどちらでも同じ顔をしている。**

B の数字だと思って A の数字を読んで、
「B は調子がいいな」と間違える。

### 何をしたか

**住所（URL）にブログの名前を入れた。**

```
/admin/sites/コンパクト台所用品/audience
             ^^^^^^^^^^^^^^^^^^
```

ここに名前が入っていれば、
**取り違えようがない。**

選択欄は無くした。
ブログを変えるには URL ごと変える。

### ブログ 1 本の下に並ぶもの

```
このブログ
 ├ 住所（独自ドメイン）    読者に届く住所があるか
 ├ 読者の行動              誰がどこを読んでいるか
 ├ 記事ごとの成果          どの記事が稼いでいるか
 ├ SEO 診断                検索から届かない原因
 └ AEO                     AI の回答に引用される形か
```

**5 つとも、そのブログのものしか出ない。**

### 大事な約束 3 つ

#### 1. 数字が少ないときは、読み方を言わない

30 回しか記録が無いのに
「クリック率 50%」と言うと、
たまたま 1 回押されただけかもしれない。

**数字は出す。でも「だから良い/悪い」は言わない。**

隠すと「記録が無い」と思われるので、
数字自体は見せる。

#### 2. 空っぽの表を出さない

表が空っぽだと、
「0 件だった」のか
「読めなかった」のか分からない。

だから空の表の代わりに、
**なぜ空なのかを文章で書く**。

- 保存先につながっていない
- まだ記録が無い
- 記録はあるけど当てはまるものが無い

この 3 つは全部違う話なので、全部書き分ける。

#### 3. 「読者のこと」と「お金のこと」を同じ画面に出さない

読者の行動を見る画面には、
売上を出さない。

見づらいからではない。
**見ていい人が違うから。**

読者の見え方だけを見せたい人がいて、
その人に売上まで渡さないようにしている。

同じ画面に混ぜると、片方だけ隠せない。

## 専門的な説明

### 変更の性質

これは**提示層の再編**である。

新しい表を作らず、新しいユースケースも追加していない。
既存の口を、住所の階層に沿って並べ直した。

### 1. route を単一の表から派生させる

`src/presentation/ui/admin-route-metadata.ts` を正本とし、
5 つの射影（画面ファイル・実 URL・パンくず・
サイドバー・分類）を導出する。

```ts
const nav = (label, group, requires, icon) =>
  ({ label, parent: "", nav: { group, requires, icon } });
const child = (parent, label) =>
  ({ label, parent, nav: null });
```

`nav` が `null` かどうかが
「サイドバーに出るか」の唯一の判定。
別のフラグを持たない。

93 のファイルと 93 の定義が一致することを
`app-shell-nav.test.tsx` が検査する。

**書き写す形にすると、片方だけ増えた状態が作れる。**

### 2. 4 層をブログの下に置く

`architecture/arch-blog-operations-console.md` の
住所層・観測層・改善層を
`sites/[site]` の子として配置した。

`analytics`（横断分析）の下ではない。

横断の下に置くと、
scope の選択が**画面内の状態**になる。
状態は前回の値を保持し、URL に現れない。

住所の下なら scope が URL の一部になり、
共有・ブックマーク・戻るボタンすべてで一貫する。

### 3. 意味と置き場所を分離する

`admin-screen-task-manifest.ts` が
`screen task`（意味）と `runtime edge`（置き場所）を
別のフィールドで持つ。

```ts
readonly uiEntry: SourceEdge;   // 置き場所
readonly action: SourceEdge;    // 置き場所
readonly ownerTaskId: AdminScreenTaskId | null;  // 意味
```

component を別ファイルへ移しても
screen/mutation の ID 集合は変わらない。

`uiux-screen-single-purpose.test.ts`
「runtime edge の module だけを移しても
screen/mutation ID 集合は同じ」で固定。

### 4. 台帳を 4 つ持ち、件数で突き合わせる

| 表 | 内容 |
|---|---|
| 実在 route | `page.tsx` |
| route metadata | ラベル・親・ナビ |
| task manifest | 目的・分類・runtime edge |
| priority map | 情報の優先度 |

**86 件で 1 対 1。**

母集団は実在ファイルの側から数える。
表の側から数えると、
表に無い画面が母集団に入らない。

過去に 49 画面中 32 件しか照合しておらず、
全部緑で「満たした」と言っていた記録がある。

### 5. 読み取りの契約

| 規則 | 実装 |
|---|---|
| 画面で計算しない | 読み口が集計済みの値を返す |
| 失敗したら次を読まない | `result.ok ? await ... : null` |
| `null` と `{ok:false}` を区別 | 「読まなかった」と「読んで失敗」 |
| 知らない値は絞らない | `VIEWPORT_BANDS.find(...)` → `undefined` |
| 根拠不足は読み方を伏せる | `MIN_EVIDENCE_SAMPLES = 30` |

### 6. 権限の境界

`BlogAudiencePort`（`Editorial`）と
`BlogRevenuePort`（`Commercial`）を
別画面に分けた。

`audience/page.tsx` は
`blogRevenueEntry` を import していない。

**import できない状態が、この分離の実体。**

同一画面で両方を呼ぶと、
片方の権限しか無い役割に空の領域が生まれ、
「壊れている」と読まれる。

### 7. 断りの設計

| 種類 | 出す場所 |
|---|---|
| 欄が特定できる | その入力欄 |
| 欄が特定できない | フォームの結果 |
| 金銭・秘密・公開 | 押す物の隣（上限の枠外） |
| 常に効く前提 | `<Callout>`（2 個まで） |
| いま解けなかった | 地の文（`Prose`） |

上限（説明文 40 字 / 注意書き 2 個）は
**揃いのために置いてあり、短さは手段**。

上限の判定そのものを境界 3 点で検査するので、
定数を書き換えると落ちる。
