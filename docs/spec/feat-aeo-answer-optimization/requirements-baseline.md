# 要件の基準 — 回答エンジン最適化 (feat-aeo-answer-optimization)

P01 の成果物。

## 何を作るのか

読者が検索結果の一覧を経由せず、
**AI の回答だけを受け取って帰る**経路が増えた。

一覧で選ばれるための対策（SEO）と、
**回答そのものとして引用される**ための対策（AEO）は別物である。

この feature は後者を扱う。

## SEO との違い

| | SEO | AEO |
|---|---|---|
| 何を competing するか | 一覧の中の順位 | 引用されるかどうか |
| 単位 | 記事 1 本 | 記事の中の**塊** |
| 読者の動き | 一覧 → 記事 | 回答だけ受け取る |
| 直す場所 | タイトル・説明・構造 | 問いと答えの対 |

**単位が違うことが設計の出発点である。**

記事 1 本を 1 つの回答として扱うと、
どの部分が引かれたのか分からず、直す場所を決められない。

## 受入条件

1. 公開記事から、引用されうる単位を機械が切り出せる
2. 切り出した単位に、それが答えている**問い**が必ず付く
3. 引用されやすさを損なう点を、機械が真偽を判定できる形で挙げる
4. ブログ全体の「何に答える場所か」を運用者が宣言できる
5. 抽出は置き換えで、記事から消えた問いは表からも消える
6. 抽出 0 件は失敗ではなく「引用できる形になっていない」という結果である
7. AI クローラを明示的に許可し、その事実が robots.txt に残る
8. AI が読むための一覧（llms.txt）をブログごとに出せる
9. 構造化データで問答の構造を機械に渡せる
10. 改善層は公開面へ書けない（AD-3）

## 作らないもの

| | 理由 |
|---|---|
| 回答エンジンへの登録・申請 | 相手側にそういう口が無い |
| 引用されたかの計測 | 引用元を返さないエンジンがある。測れないものを測ったことにしない |
| 回答文の自動生成 | LLM で答えを作ると、記事に書いていないことを配ることになる |
| AI クローラの遮断 | このプロダクトは読ませたい側に立つ（`crawler-policy.md`） |
| 引用単位の自動公開 | AD-3 |

### 「引用されたか」を測らない判断

一番聞かれる要望だが、**測る手段が無い**。

回答エンジンによっては引用元を示さず、
示す場合も User-Agent が読者のものになる。

測れないものに数字を出すと、
その数字を根拠に判断が行われる。
それは測っていないより悪い。

### 回答文を LLM に書かせない判断

「引用されやすい答え」を LLM に生成させるのは技術的には簡単である。

しかしそれは**記事に書いていないことを、記事の答えとして配る**ことになる。

この feature が切り出すのは、
すでに記事の中にある問いと答えの対だけである。
無ければ「無い」と言う。

## 前提とする層

`architecture/arch-blog-operations-console.md` の改善層。

- AD-1: 住所層・観測層に依存しない
- AD-2: 隙間の判定は応用層で行い、画面で数えない
- AD-3: 公開面へ書けない
- AD-5: `site_slug` が唯一の結合キー

## SEO との関係

`feat-seo-assessment-reflection` と同じ層に住み、
同じ `blog-improvement.ts` のポート群に属する。

**表は別**（`article_seo_assessment` と `article_answer_unit`）。

同じ表に混ぜないのは、
SEO の指摘が「直すべきこと」なのに対し、
AEO の単位は「記事から取り出した現物」だからである。
寿命も更新の仕方も違う。
