# 機械への配り方 — 回答エンジン最適化 (feat-aeo-answer-optimization)

P02 の成果物。受入条件 8。
正本は `src/application/seo/feeds.ts` と `src/app/s/[site]/llms.txt/route.ts`。

## 4 つの口

| 口 | 誰が読むか | 形 |
|---|---|---|
| `robots.txt` | クローラ全般 | text |
| `sitemap.xml` | 検索エンジン | XML |
| `rss.xml` | 購読者・一部の収集器 | XML |
| `llms.txt` | AI クローラ・回答エンジン | Markdown |

## `llms.txt` の形

```ts
return [`# ${site.siteName}`, ``, `> ${site.purpose}`, ``, `## 記事一覧`, ``, links, ``].join("\n");
```

```markdown
# ブログ名

> このブログが何のためにあるか

## 記事一覧

- [記事タイトル](https://example.com/s/blog/articles/slug): 要約
- [記事タイトル](...): 要約
```

### なぜ Markdown なのか

LLM が読むことを前提にした形式である。

XML の sitemap は URL しか渡せない。
`llms.txt` は**題名・要約・目的**を一緒に渡せる。

「このブログは何に答える場所か」を
1 ファイルの先頭 1 行（`> purpose`）で伝えられるのが要点で、
これは `SiteAeoProfile.topicScope` と同じ役割を公開面で果たす。

### エスケープを持ち込まない

```
Markdown なので、題の < > をエスケープしない（XML の逃がしを持ち込まない）
```

`buildSitemap` と `buildRss` は XML なので `&` や `<` を逃がす。
`buildLlmsTxt` は Markdown なので逃がさない。

同じファイルに 4 つのビルダーが並んでいるので、
**うっかり同じ処理を通したくなる**。
テストで分けて固定してある。

## 空でも骨組みを残す

| 口 | 0 件のとき |
|---|---|
| sitemap | 空の `<urlset>`（壊れた XML にしない） |
| RSS | item なしで channel を閉じる |
| llms.txt | 見出しの骨組みは残る |

**壊れた出力より、空の正しい出力。**

クローラは壊れた XML を「このサイトは壊れている」と学習する。
空の正しい XML は「今は記事が無い」と読む。

## 新着 20 件で切るのは RSS だけ

```
新着 20 件に切らず、21 件目の公開記事も列挙する   ← sitemap
RSS だけは明示した新着 20 件の policy で配る
50,000 件を超える公開記事を黙って切らず 503 で返す ← sitemap / llms.txt
```

| 口 | 件数 |
|---|---|
| sitemap | 全件（50,000 超は 503） |
| llms.txt | 全件（50,000 超は 503） |
| RSS | 新着 20 件 |

**RSS は購読の仕組みなので新着だけでよい。**
sitemap と llms.txt は「このサイトの全体」を渡すものなので切らない。

50,000 は sitemap の規格上の上限で、
超えたら分割が要る。分割を実装していないので
**黙って切らずに 503 を返す**。

## 「空文字 200」を返さない

`seo-route-handlers.test.ts` に 3 件ある:

- 記事の読み取り失敗を空の sitemap にせず 503 で返す
- 無いブログを空文字 200 にせず 404 で返す
- 設計図で無効な場合は空文字 200 にせず 404 で返す

**壊れているのに 200 を返すと、クローラは
「このサイトには記事が無い」と学習して帰る。**

503 なら後で来直す。404 なら存在しないと分かる。
200 + 空は、正常に空だという嘘になる。

これが AEO で一番効く配慮である。
引用されるには、まず読まれなければならない。

## 記事を読まずに配れるもの

```
記事を読まずにクローラー方針と sitemap を配る
```

`robots.txt` は記事の内容に依らない。
記事の読み取りが失敗しても robots.txt は配れる。

これを分けておくと、
記事側が壊れている間もクローラは方針を読める。

## 道の組み立て

```
ホスト・ブログ基底パス・サイト内の道を、この順でつなぐ
道を渡さなければブログのトップになる（末尾に余計な / を足さない）
```

`canonicalSiteUrl(site, path)` が 1 か所で組み立てる。

4 つの口が別々に組み立てると、
片方だけ末尾スラッシュが付くような食い違いが生まれる。
同じ記事が別 URL として数えられる。
