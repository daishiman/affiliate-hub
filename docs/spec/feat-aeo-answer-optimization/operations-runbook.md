# 運用の手引き — 回答エンジン最適化 (feat-aeo-answer-optimization)

P10 の成果物。

## 日々やること

### 1. ブログの構えを決める（最初に 1 回）

`/admin/sites/<slug>/aeo` の構えの入力欄。

| 欄 | 例 |
|---|---|
| 扱う話題 | 在宅ワーク用のデスク環境 |
| 想定読者 | はじめて自宅に仕事机を作る人 |
| 発行元の名前 | （実在する主体の名前） |
| 構造化データを出す | オンにする |

**3 つ揃うまで意味を持たない**（`author-profile-design.md`）。
1 つでも空だと、機械はこのブログをどの文脈に置くか決められない。

権限は `site.manage`。記事を書く人には変えられない。

### 2. 記事を公開したら抽出する

`/admin/sites/<slug>/aeo` の「引用単位を抽出」。

**自動では回らない。**
記事を公開しても抽出は動かない（`design-review-findings.md` F-06）。

公開のたびに押す運用が要る。

権限は `content.write`。

### 3. 隙間を見る

抽出後、単位ごとに隙間が付く。

| 隙間 | 直し方 |
|---|---|
| 答えが長すぎる | 300 文字以内の一文にまとめ直す |
| 答えが埋もれている | 記事の前半へ移す、または FAQ に書き直す |
| 根拠が無い断定 | 出典を足す（URL でなくてもよい） |
| 主語が曖昧 | 指示語で始めない |

**指摘であって禁止ではない。**
運用者が見て「これは大丈夫」と判断してよい。

## 気をつけること

### 抽出は置き換えである

抽出を押すと、その記事の単位は**全部作り直される**。

記事から消えた問いは表からも消える。
これは意図した動作だが、
**前にあった問いが消えたことは行の差分に残らない**。

監査に件数だけが残る（`aeo_answer_units.extracted`）。

### 記事を取り下げると 0 件になる

取り下げた記事・未公開の記事からは 1 件も取れない。

次に抽出を押すと、その記事の単位が全部消える。

**再公開しても自動では戻らない。** もう一度抽出を押す。

### 0 件は失敗ではない

「抽出 0 件」は
「この記事は引用できる形になっていない」という結果である。

エラーとして扱わない。
記事に一文の結論も FAQ も問いの形の見出しも無い、ということ。

### 指示語の指摘は当たり外れがある

「これから説明します」のような文も指摘される（偽陽性）。
「同社は」で始まる文は指摘されない（偽陰性）。

**判定は荒い。** 一覧を鵜呑みにしない。

### `llms.txt` を出すかどうか

ブログ設定の `emitLlmsTxt`。

出すと `robots.txt` に在り処の注記が付く。
出さないと注記が付かない。

**`AI_CRAWLERS` への許可はこれとは無関係**で、
全ブログ共通に出る。切り替えられない。

### 遮断は用意していない

`buildRobotsTxt` は `Disallow` を 1 行も書かない。

「AI に読ませたくない」という要望が来ても、
この画面からは応えられない（`crawler-policy.md`）。

## 困ったとき

### 構造化データが出ない

1. ブログの構えで「構造化データを出す」がオンか
2. 記事に FAQ があるか（0 件なら `FAQPage` は `null`）
3. 著者が設定されているか

`FAQPage` が出ないのは、FAQ が 0 件のときの正しい動作である。
空の `FAQPage` は出さない。

### `llms.txt` が 503 を返す

公開記事が 50,000 件を超えている。

分割を実装していないので、黙って切らずに 503 を返す
（`delivery-design.md`）。

現状の規模では起きない。

### `llms.txt` が 404 を返す

- ブログが存在しない
- ブログの設計図が無効

**空文字の 200 は返さない。**
クローラに「記事が無い」と学習させないため。

### 単位が重複して見える

同じ問いは 1 行しか保存されない（一意索引）。

見えているのは別の問いである。
問いの文字列が 1 文字でも違えば別の行になる。

### FAQ をタイトルと同じ問いにしたら消えた

一文の結論（記事タイトルを問いとする）が先に取られ、
同じ問いの FAQ が捨てられている
（`design-review-findings.md` F-08）。

FAQ の問いをタイトルと変える。
