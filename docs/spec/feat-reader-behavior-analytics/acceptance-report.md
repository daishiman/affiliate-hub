# 受入の判定 — 読者行動の観測 (feat-reader-behavior-analytics)

P08 の成果物。受入条件 10 件に対する判定。

| # | 条件 | 判定 | 根拠 |
|---|---|---|---|
| 1 | 同意が無い読者の行から `reader_key` が常に null で、個人へ戻せる列が他に無い | **満たす（より強い形で）** | 行を作らない。probe の早期 return + intake の `decideConsent` |
| 2 | 保存される位置が比率で、絶対座標の列が存在しない | **満たす（範囲を縮小）** | `position_ratio`（0〜1）1 列のみ。`x_ratio` は**持たない** |
| 3 | ポインタは全軌跡でなくクリックと間隔標本だけ | **一部変更** | クリックのみ。**間隔標本は作らない** |
| 4 | 単一の鍵の再生経路が UI にもクエリにも存在しない | **満たす** | `BlogAudiencePort` に生の行を返す関数が無い（型で担保） |
| 5 | 幅を切り替えると同じ記事で別の分布が描かれる | **満たす** | d1 の 10 / blog-metrics-pages の 13 |
| 6 | 離脱時にも欠落せず `sendBeacon` で送出される | **満たす** | probe の 13（`sendBeacon` が無い環境も） |
| 7 | 同じ束を二度受け取っても件数が二重にならない | **満たす** | 送信側採番の `id` が主キー |
| 8 | 生イベントが 90 日で削除され、集計側は残る | **満たす** | d1 の 11 |
| 9 | `reader_key` を指定した抽出・削除が Owner だけで実行でき `audit_logs` に残る | **満たさない（設計として持たない）** | `subject-request-design.md` |
| 10 | 計測 script の失敗が読者面の描画を壊さない | **満たす** | probe の 12 + `useEffect` 全体の try/catch |

## 条件 1 — 条件より強い

条件は「`reader_key` が常に null」を求めていた。
実装は**行そのものを作らない**。

null の行が積まれると、行数からその日の非同意の読者数が読める。
作らなければ、それも残らない。

## 条件 2 — 列の数を減らした

条件は `element_ref + x_ratio/y_ratio` を求めていた。
実装は `element_key` + `position_ratio`（縦のみ）である。

横位置は運営判断にほとんど効かず、画面幅と組み合わさると
画面構成を復元できる（F-02）。**条件が禁じた絶対座標が無い**という
趣旨は満たしており、持つ列はより少ない。

結果、画面は canvas の重ね描画ではなく棒グラフになった。
**仕様の見た目とは違う。**

## 条件 3 — 間隔標本を作らなかった

条件は「クリックと間隔標本」を許していた。実装はクリックだけである。

一定間隔のポインタ位置は、速度・停止位置・震えという
使い捨てにならない特徴を持つ（F-03）。
条件 1・4 の趣旨と衝突するので、狭いほうへ倒した。

**条件の文言そのものは満たしていない。** 記録の範囲を条件より狭めた。

## 条件 9 — 満たさない

条件 1 と論理的に両立しない。

照合できない鍵に対する請求は実行できず、
照合できる形にすると条件 1 が崩れる。

決着は「請求に応える対象そのものを持たない」で、
根拠と、法域によっては通らない可能性は `subject-request-design.md` に書いた。

**この判断は実装側では決められない。** 判断が要る点として残す。

## 確かめていないこと

| 対象 | 状態 |
|---|---|
| 定時起動が毎日走ること | **未検証**。cron は実環境でしか回らない |
| 実ブラウザでのスクロール到達率 | **未検証**。jsdom は実レイアウトを持たない |
| 90 日の実経過 | 発生時刻を過去に置いて代替した |

条件 8 は「90 日を超えた行が消える」ことを、
過去の発生時刻を差し込んで確かめている。
**実際に 90 日待った検証ではない。**
