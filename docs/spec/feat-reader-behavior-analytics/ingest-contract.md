# 受け口の契約 — 読者行動の観測 (feat-reader-behavior-analytics)

P02 の成果物。`POST /api/reader-events` が何を受け、何を落とすか。
正本は `src/application/usecases/blog-ops/record-reader-interactions.ts`。

## 権限の検査が無い

読者は誰でもない。`requireCapability` を置くと、記録できるのは
管理画面に入れる人だけになり、**観測したいものがまるごと落ちる**。

代わりにこの口が守るのは「何を受け取るか」であって、送り主の資格ではない。

これは repo の他の書き込み口とは違う形なので、
`docs/product/port-wiring.md` の除外表へ理由付きで登録した。

## 守っているもの

### 1. 同意（`decideConsent`）

| 状態 | 扱い |
|---|---|
| 未回答（`unset`） | 受け取らない |
| 拒否（`denied`） | 受け取らない |
| ブラウザの追跡拒否（GPC） | **本人の許可より強い**。受け取らない |
| 自動巡回（bot） | 数字に混ぜない |
| 許可（`granted`）かつ GPC 無し | 受け取る |

GPC を本人の許可より強くしているのは、GPC が
**端末全体の意思表示**だからである。個々のサイトで「はい」を押した
記憶より、端末に設定された拒否のほうが新しい意思とみなす。

同意が無いときの `rejected` は **0** を返す。
「落とした」ではなく「そもそも見ていない」ため。
ここを落とした件数に数えると、送信側が壊れているのか
同意が無いだけなのかが区別できなくなる。

### 2. 値の形

| 検査 | 落とすもの |
|---|---|
| `kind` | 列挙にない種別 |
| `segment` / `viewportBand` | 列挙にない値 |
| `positionRatio` | 0〜1 の外 |
| `dwellSeconds` | 上限超えは**落とさず頭打ち** |
| `elementKey` | 長すぎる鍵は切り詰め。押下でない件に付いていたら**捨てる** |
| `sessionKey` | 長すぎる鍵は切り詰め |
| `siteSlug` | **束の中で別のブログを名乗る件は落とす** |

最後の 1 つが重要で、1 回の POST は 1 ブログぶんである。
束の中に別のブログの件が混ざっていたら、その件だけを落とす。
混ぜて通すと、あるブログの観測が別のブログの数字に乗る。

### 3. 時刻

端末が名乗る発生時刻は信じきらない。

| 状況 | 扱い |
|---|---|
| 未来の時刻 | 受信時刻へ寄せる |
| 許した日数（2 日）より古い | 受信時刻へ寄せる。**捨てない** |
| 読めない形式 | 受信時刻へ寄せる |
| 範囲内 | そのまま使う |

古い時刻を捨てないのは、時計がずれた端末の観測を全部失うより、
**日がずれた状態で数えるほうがまし**だからである。
捨てると、その端末の読者は存在しなかったことになる。

`rollup_day` は寄せた後の時刻から**受け取り側が**決める。
端末に決めさせない。時計は簡単にずれるし、意図的にずらすこともできる。

## 1 件の不正で束ごと落とさない

壊れた 1 件で束全体を捨てると、**古い版の JS を掴んだままの読者が
1 人いるだけで、その日の観測が全部消える**。

だから不正な件だけを落とす。ただし**落とした数は返す**。

```ts
{ accepted: number, rejected: number }
```

黙って捨てると、送信側が壊れていることを誰も観測できなくなり、
数字が減ったことにも気づけない。

## 積む先は actor の作業場所

件の中身が名乗る作業場所ではなく、**呼び出した actor の作業場所**へ積む。

件に `workspaceId` を書かせると、そこを書き換えるだけで
他人の作業場所へ観測を注入できる。

## 二重受信

`sendBeacon` は届いたかどうかを送信側に返さない。
ネットワークが不安定なとき、同じ束が 2 回届くことがある。

行の `id` は**送信側が生成**し、受け口はそれを主キーとして書く。
同じ束が二度届けば `id` が衝突し、2 回目は行を増やさない。

送信側で採番する形にしたのは、受け口で採番すると
2 回目の束が全部新しい行になるためである。

## 空の束

`events` が空なら保存先を呼ばない。
呼ぶと、書き込みが 0 件の `batch` が毎回走る。

## 1 回の上限

受け口が 1 回に受けるのは 50 件。送信側の束ねる上限は 40 件で、
**受け口より下に置いてある**。

同じ値にすると、送信側が 1 件でも多く詰めた瞬間に全部弾かれる。
