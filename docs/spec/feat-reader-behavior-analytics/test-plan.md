# テストの方針 — 読者行動の観測 (feat-reader-behavior-analytics)

P05 の成果物。何をどの層で確かめるか。

## 層の割り当て

| 層 | ファイル | 確かめること |
|---|---|---|
| 送信側（ブラウザ） | `tests/ui/reader-behavior-probe.test.tsx` | 何を送り、何を送らないか |
| 受け口（純関数） | `tests/application/reader-interaction-intake.test.ts` | 何を受け、何を落とすか |
| 保存と読み口（実 D1） | `tests/integration/d1-reader-metrics.test.ts` | 集計・保持期限・分布 |
| 画面 | `tests/ui/blog-metrics-pages.test.tsx` | 根拠不足の伏せ方・幅の切替 |

**受け口を integration ではなく application で確かめる。**
落とす判断は D1 に触らない純関数なので、
DB を立てずに 14 通りの入力を回せる。

逆に、集計の二重化・保持期限・分布は **実 D1 でしか確かめられない**。
`upsert` の衝突挙動と索引の使われ方が絡むため、
偽物の保存先では「通ったつもり」になる。

## 送信側で「送らない」を確かめる難しさ

同意が無いときにイベントが 1 件も作られないことは、
**何も起きないことの確認**である。

`fetch` と `navigator.sendBeacon` の両方を差し替えて、
呼び出し回数が 0 であることを見る。片方だけだと、
もう片方の経路で漏れていても緑になる。

## 時間を進める

滞在秒数は経過時間に依存する。実時間を待つと遅く、不安定になる。

`vi.useFakeTimers()` で時計を進め、
`Date.now()` の差から滞在を作る。

## 受入条件との対応

| 条件 | どこで確かめるか |
|---|---|
| 1 同意が無ければ個人へ戻せない | probe（送らない）+ intake（受けない） |
| 2 絶対座標の列が無い | 表定義 + `data-model.md`。**縦 1 次元へ縮小**したので座標そのものが無い |
| 3 全軌跡でなくクリックのみ | probe（間隔標本を作らない） |
| 4 単一の鍵の再生経路が無い | **型で保証**（`BlogAudiencePort` に生の行を返す関数が無い） |
| 5 幅を切り替えると別の分布 | d1（読み口）+ blog-metrics-pages（画面） |
| 6 離脱時にも欠落しない | probe（`sendBeacon` 無し環境も含む） |
| 7 同じ束を二度受けても二重にならない | d1（`id` の衝突） |
| 8 90 日で生イベントだけ消える | d1 |
| 9 本人の請求 | **テストしない。** 受け口を持たない設計（`subject-request-design.md`） |
| 10 計測の失敗が読者面を壊さない | probe（送信が例外を投げても漏らさない） |

条件 4 は**テストで確かめる対象ではない**。
生の行を返す関数を書こうとするとコンパイルが通らないので、
テストを書くこと自体ができない。これが最も強い形である。

## 確かめないもの

| 対象 | 理由 |
|---|---|
| 定時起動が実際に毎日走ること | Workers の cron は実環境でしか回らない |
| 本物のブラウザでのスクロール | jsdom は実レイアウトを持たない。刻みの判定は数値で確かめる |
| 90 日の実経過 | 発生時刻を過去に置いて確かめる |

jsdom は `scrollHeight` / `innerHeight` を実測しないので、
テストは値を直接注入する。**実ブラウザでの到達率は未検証**である。
`acceptance-report.md` に申告する。
