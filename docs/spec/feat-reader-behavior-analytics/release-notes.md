# できるようになったこと — 読者行動の観測 (feat-reader-behavior-analytics)

P13 の成果物。

## 一言で

**読者が記事のどこまで読んで、どこで押したかが分かるようになった。
ただし「誰が」は一切分からない。**

## 何が見えるか

`/admin/sites/<ブログ>/audience` で、記事を選ぶと:

| 見えるもの | 例 |
|---|---|
| どこまで届いたか | 「4 分の 1 まで 92%、半分まで 61%、最後まで 18%」 |
| どこで時間を使ったか | 区間ごとの平均滞在秒数 |
| どこが押されたか | 「本文中のボタン 4.2%、末尾のリンク 1.1%」 |
| どんな読者が来たか | 検索 / SNS / 直接 / 他サイト / 自サイト内の 5 区分 |
| どの画面幅で読んだか | 狭い / 中くらい / 広いの 3 区分 |

画面幅を切り替えると、**同じ記事でも違う分布**が出る。
スマホでは半分で止まるが PC では最後まで読まれている、
といったことが分かる。

## 「誰が」が分からない仕組み

集めているのは次の 5 つだけである。

- タブを閉じると消える使い捨ての番号
- どこから来たかを 5 つに畳んだ区分（URL そのものは持たない）
- 画面幅を 3 つに畳んだ区分（実寸は持たない）
- 記事の上から何割の位置か（横位置は持たない）
- 押された部品の名前

IP も、端末の種類も、位置情報も持っていない。

読者が同意していなければ、**そもそも 1 件も送らない**。
ブラウザの追跡拒否（GPC）が立っていれば、
本人が「はい」を押していても送らない。

生の記録は 90 日で消える。畳んだ数字だけが残る。

## 読者ができること

| したいこと | 方法 |
|---|---|
| 観測を止める | 同意を「拒否」にする |
| 端末全体で止める | ブラウザの追跡拒否（GPC）を立てる |
| 番号をリセットする | タブを閉じる |

## 分かっている制限

### 1. 「誰の記録を消して」に応えられない

使い捨ての番号は、読者本人も運営者も値を知らない。
照合できないので、消す対象を特定できない。

代わりに、上の 3 つの方法で読者が自分の側で止められるようにしてある。
詳しくは `subject-request-design.md`。

### 2. 同意していない読者の数が分からない

送らないので、数えるものが無い。

**「数字が減った」が「読者が減った」なのか
「同意率が下がった」なのか区別できない。**
同意の画面を変えた日は記録しておくこと。

### 3. ネットワークが切れた瞬間の記録は落ちる

送り直さない。後からまとめて送ると、
発生時刻が古すぎて別の日に計上されるためである。

### 4. 3 日以上止まると自動では戻らない

集計が止まったとき、自動でやり直すのは直近 2 日ぶんまで。
それより古いぶんは手で範囲を広げる（`operations-runbook.md`）。

### 5. 実ブラウザでの到達率は未検証

テストは実レイアウトを持たない環境で回している。
固定ヘッダや遅延読み込みの画像があると、
読んでいる最中に記事の高さが変わり、区切りの位置がずれうる。

## 仕様から変えたところ

| 仕様 | 実装 |
|---|---|
| 縦横 2 方向の位置を記録し、canvas に重ねて描く | 縦方向だけ。棒グラフで描く |
| マウスの動きを一定間隔で記録 | 記録しない。押した瞬間だけ |
| 同意が無いときは番号を空にして保存 | 保存そのものをしない |

いずれも「持つ情報を減らす」方向の変更である。
理由は `design-review-findings.md`。
