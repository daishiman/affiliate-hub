# 分布の作り方 — 読者行動の観測 (feat-reader-behavior-analytics)

P02 の成果物。生の観測を、どうやって「1 人が見えない形」へ畳むか。

## 集計しか返さない型

読み口（`BlogAudiencePort`）が返せるのは 4 つだけ。

```ts
siteDaily(...)    // 日ごとの数字
articleDaily(...) // 記事ごとの日ごとの数字
breakdown(...)    // 区分ごとの件数
engagement(...)   // 区間ごとの到達率と平均滞在 + 要素別クリック率
```

**生の行を返す関数が無い。**

条件 4（単一 `reader_key` の再生経路が UI にもクエリにも存在しない）を、
注意書きではなく型で守る。画面が「1 件ずつ並べる」を実装しようとしても、
渡すデータが存在しない。

## `breakdown` — 区分ごとの件数

```ts
{
  bySegment:  Record<"search"|"social"|"direct"|"referral"|"internal", number>,
  byViewport: Record<"narrow"|"medium"|"wide", number>,
}
```

**来ていない区分も 0 で埋める。** 埋めないと、画面が
`Object.entries` で回したときに区分が消え、
「今日は検索から誰も来なかった」が「検索という区分が無い」に見える。

区分が 5 つと 3 つに固定されているので、
どの読者も必ず誰かと同じ値になる。1 人だけの区分ができない。

## `engagement` — 到達の分布

記事を 0〜1 で等分した区間ごとに:

| 値 | 意味 |
|---|---|
| `from` / `to` | 区間の上端と下端（0〜1） |
| `reachRatio` | この区間まで読み進んだ人の割合（0〜1） |
| `averageDwellSeconds` | 平均滞在秒数 |

**区間数は保存側が決める。** 画面に決めさせない。
画面が変えられると、同じ記事の到達率が画面ごとに別の値になる。

位置を比率で持つのは、**画面幅の違う観測どうしを足せるようにするため**。
px で持つと、狭い画面の「50%」と広い画面の「50%」が別の数になり、
足せない。

### なぜ 2 次元にしなかったか

仕様は `x_ratio` / `y_ratio` の 2 次元ヒートマップを求めていた。
実装は縦方向だけの 1 次元である。

| 案 | 判断 |
|---|---|
| 2 次元（x, y） | **採らない**。横位置は情報量に対して指紋性が高く、運営判断に効かない |
| 1 次元（縦のみ） | **採った** |

記事は縦にスクロールして読むもので、運営者が知りたいのは
「どこで離脱したか」である。横のどこを見ていたかは、
段組みが 1 列である限り情報を持たない。

一方で、横位置は画面幅と組み合わさると**画面構成を復元できる**。
指紋になりうる値を、使い道の無いまま持つことになる。

結果、描かれるのは canvas の重ね描画ではなく**棒グラフ**である。
仕様の「canvas 重ね描画」から形が変わった。

## 画面幅での絞り込みは保存側でやる

`viewportBand` を指定すると、その幅で読んだ観測だけから
分布を作り直す。

**画面側で後から間引かない。** 間引くと到達率の分母が変わり、
別の意味の値になる。「narrow で読んだ人のうち何割が到達したか」が
「全体のうち narrow で到達した人の割合」に化ける。

### 絞り込まないもの

**`breakdown`（どんな読者が来ているか）は絞らない。**

`byViewport` を `viewportBand` で絞ると、指定した幅だけが
非 0 になって残り 2 つが 0 になる。それは内訳ではない。

この分離はテストで固定してある:

> 画面幅で絞っても、どんな読者が来ているかの内訳は絞らない

## 0 除算

| 値 | `views = 0` のとき |
|---|---|
| `clickThroughByElement` | 0 |
| `reachRatio` | 0 |

`null` にしない理由は並べ替えである。`null` が混ざると、
表の並べ替えで「まだ誰も見ていない記事」が最上位にも最下位にも来うる。

**ただし 0 の率と「率が計算できない」は意味が違う。**
この区別は `sample_count` と `views` を画面が併記することで担保し、
提示層の責務として引き渡した。

## ブログ全体では位置を返さない

`engagement` は記事を 1 本指定したときだけ返る。
ブログ全体では `null` になる。

記事ごとに長さが違うので、混ぜた「50% の位置」に意味が無い。
返さないことを型と実装の両方で守っている。

## 記事に紐づかない観測

`article_slug` が null の行（トップ・一覧・タグページ）は、
記事側の集計に乗らない。ブログ全体の数字にだけ乗る。

したがって:

```
Σ 記事の PV  ≤  ブログの PV
```

差の意味は「記事以外の場所が読まれた回数」で、
feat-blog-metrics-rollup が同じ関係を扱っている。
