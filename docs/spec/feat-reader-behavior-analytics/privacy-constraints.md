# 持たないもの — 読者行動の観測 (feat-reader-behavior-analytics)

P01 の成果物。持たない列・作らない画面・作らないクエリの列挙。

## 考え方

「個人を追跡しません」と書くのは約束にすぎない。約束は破れる。

**持っていない列は使えない。** だから制約を列の不在として表す。
後から誰かが「1 人の動きを追いたい」と思っても、
必要な値がどこにも無ければ、実装のしようがない。

## 持たない列

| 持たないもの | 持つとどうなるか |
|---|---|
| IP アドレス | それだけで世帯が特定できる。保存した瞬間に個人データになる |
| User-Agent 全文 | 拡張・フォント・版の組み合わせが指紋になる |
| 画面の実寸（px） | 珍しい幅は 1 人しかいない。区分 3 つなら必ず誰かと同じ値になる |
| 参照元 URL 全体 | 前に見ていたページが分かる。検索語が付いていることもある |
| 絶対座標（x, y px） | 実寸と組み合わせると画面構成が復元でき、指紋になる |
| 横方向の位置 | 縦の到達だけで運営判断はできる。横は情報量に対して指紋性が高い |
| 恒久的な読者 id | 定義そのものが追跡である |
| ログイン中の利用者 id | 読者の観測と身元を結ぶ唯一の経路になる |

## 実際に持っている列と、その粗さ

| 列 | 値域 | なぜこの粗さか |
|---|---|---|
| `segment` | `search` / `social` / `direct` / `referral` / `internal` の 5 種 | 参照元のホスト名を 5 つに畳む。URL は捨てる |
| `viewport_band` | `narrow` / `medium` / `wide` の 3 種 | 640 / 1024 で切る。実寸は送らない |
| `position_ratio` | 0〜1 の実数 | 記事の上から何割か。px ではない |
| `element_key` | `<種類>:<id>` の文字列 | 印を付けた部品だけ。DOM の道筋は持たない |
| `session_key` | 使い捨て UUID または null | `sessionStorage`。タブを閉じれば消える |
| `dwell_seconds` | 0〜3600 の整数 | 上限で頭打ちにする。開きっぱなしの端末で外れ値にならない |

## 到達を刻む理由

スクロール位置は連続値だが、記録するのは `0.25 / 0.5 / 0.75 / 1` の
4 つの刻みを**越えた瞬間**だけである。

連続値を送ると、1 人の細かい上下で件数が膨らむ。件数が膨らむと、
**その人の読み方の癖が行の並びとして残る**。刻みなら、
同じ記事を読み切った人はみな同じ 4 行になる。

## 同意が無いときは、行を作らない

条件 1 は「`reader_key` が常に null」を求めるが、実装は**それより強い**。

```ts
if (suppressAll || !allowBehaviour) return;
```

同意が無ければ計測そのものを始めない。イベントを 1 件も作らない。

「作ってからサーバーで捨てる」形にしなかったのは、
**通信だけが起きる**からである。読者の端末から何かが送られている、
という事実そのものが残ると、捨てていることを外から確かめられない。

受け口の側も二重に守る（`decideConsent`）:

- 未回答（`unset`）は受け取らない
- ブラウザの追跡拒否（GPC）は本人の許可より**強い**
- 自動巡回（bot）は数字に混ぜない

送信側だけの防御にしないのは、古い版の JS を掴んだ端末が
いつまでも送り続けうるため。

## `session_key` は仮名ではなく使い捨て

`sessionStorage` に置く `crypto.randomUUID()`。

- タブを閉じると消える
- 別のタブでは別の値になる
- 端末の情報からは作らない（端末から作ると、それは指紋であって仮名ではない）
- ストレージが使えない設定なら **null のまま送る**（回数としては数える）

だから「同じ人が 2 日にわたって何をしたか」は原理的に追えない。
訪問者数（`count(distinct session_key)`）は**タブの数**に近く、
人数の下限でも上限でもない近似値である。これは
`measurement-inventory.md` に明記した。

## 作らない画面

| 作らないもの | 理由 |
|---|---|
| 1 人の読者の動きを時系列で並べる画面 | 定義そのものが追跡 |
| `session_key` を入力して引く画面 | 上と同じものを間接的に作ることになる |
| クリックを 1 件ずつ並べる一覧 | 並べれば時系列になる |

## 作らないクエリ

読み口（`BlogAudiencePort`）は**集計済みの分布しか返さない**型になっている。

```ts
breakdown(...)   // 区分ごとの件数
engagement(...)  // 区間ごとの到達率と平均滞在
```

生の行を返す関数が無い。だから画面が「1 件ずつ並べる」を
実装しようとしても、渡すデータが無い。

**型で塞ぐのは、レビューで塞ぐより強い。**
レビューは人が変われば通るが、型は通らない。

## 90 日で消す

生の観測は 90 日で削除する（`RAW_EVENT_RETENTION_DAYS = 90`）。
畳んだ日次の数字は残る。

消すのは `occurred_at` を基準にする。`rollup_day` は
受け取り側の都合で決まる派生値なので、削除の基準にしない。
