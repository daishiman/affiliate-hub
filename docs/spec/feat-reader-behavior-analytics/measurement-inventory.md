# 観測項目の一覧 — 読者行動の観測 (feat-reader-behavior-analytics)

P01 の成果物。何をいつ数えるか。正本は
`src/presentation/reader/behavior-probe.tsx`。

## 5 つの種別

| `kind` | いつ 1 件出るか | 何が分かるか |
|---|---|---|
| `view` | 記事を開いたとき 1 回 | 母数 |
| `scroll` | 到達の刻みを越えたとき | **どこで読むのをやめたか** |
| `dwell` | 離れるとき 1 回 | 見えていた時間 |
| `click` | 印の付いた部品を押したとき | どこが押されているか |
| `exit` | 離れるとき 1 回 | `view` との差が「開いたが何もしなかった」 |

仕様の `scroll_depth` / `element_click` / `pointer_sample` から
名前と構成を変えた。理由は下記。

## `view` と `exit` を分けた理由

仕様には無い 2 種を足した。

`view` だけだと「開いたが本文を見ずに閉じた」が数えられない。
`exit` を別に持つと、`view - exit` が
**「開いたが離脱の合図すら届かなかった」**件数になる。

これは計測の取りこぼし量そのもので、他の数字を信じてよいかの判断材料になる。
差が大きい日は、`sendBeacon` が届いていない可能性がある。

## `pointer_sample` を作らなかった

仕様は「間隔標本のポインタ位置」を求めていたが、**実装していない**。

| 案 | 判断 |
|---|---|
| 一定間隔でポインタ位置を送る | **採らない**。1 分の滞在で数十件、記事あたりの行数が桁で増える |
| クリックだけ | **採った** |

理由は 2 つ。

1. **指紋性**。間隔標本は動きの癖（速度・停止位置・震え）を含む。
   点の列を並べれば、同じ人が別の記事で残した列と照合できる。
   `session_key` が使い捨てでも、動きの癖は使い捨てにならない。
2. **使い道が無い**。運営者が知りたいのは「どこが押されているか」で、
   ポインタがどこを通ったかではない。分布を描くには
   クリックと到達で足りる。

条件 3 の文面は「全軌跡ではなくクリックと間隔標本だけ」だったが、
その趣旨（全軌跡を残さない）は**より強く**満たしている。

## 到達（`scroll`）

刻みは 4 つだけ。

```ts
const SCROLL_MARKS = [0.25, 0.5, 0.75, 1] as const;
```

- 越えた瞬間に 1 件。**同じ刻みは 2 度送らない**（`passed` の Set）
- 上へ戻ってまた下がっても増えない
- **短い記事は開いた時点で下端が見えている**ので、
  最初に 1 回 `onScroll()` を呼び、読み切ったと数える

最後の点を忘れると、画面に収まる記事の到達率が常に 0 になる。

## 滞在（`dwell`）

`visibilitychange` で見えている時間だけを足す。裏のタブは数えない。

```ts
const seconds = Math.min(MAX_DWELL_SECONDS, Math.round(visibleMs / 1000));
```

上限は 3600 秒。開きっぱなしの端末が 1 件で平均を壊さないため。

**上限に当てても捨てない。** 捨てると、長く読んだ人がまるごと
消えて平均が下がる。頭打ちなら方向は正しいまま歪みが有限になる。

## 離脱を 2 度送らない

裏に回った後そのまま閉じると `visibilitychange` と `pagehide` が
続けて来る。

```ts
const finish = (): void => {
  if (done) return;
  done = true;
  ...
};
```

`done` を見ないと滞在も離脱も 2 件になり、**平均滞在が半分に見える**。
2 倍ではなく半分になるのは、2 件目の滞在が 0 秒で入るためである。

## クリック（`click`）

印の付いた部品だけを数える。

```ts
const marked = target.closest(`[${TELEMETRY_ATTR.kind}]`);
```

- 印が無い場所を押しても増えない
- 印の付いた親の中を押しても、**親の名前で**数える
- `capture` で拾う。途中で伝播を止める部品があっても数えるため

印が無いものまで拾うと、`div` の入れ子の深さが変わっただけで
別の名前になり、日をまたいだ比較ができなくなる。

**結果として、印を振っていない場所のクリックは要素別の内訳から落ちる。**
ブログ全体のクリック数には入るので、内訳の合計は全体より小さくなる。

## 訪問者数の意味（正確でない近似であることの申告）

`unique_sessions` は `count(distinct session_key)`。

`session_key` は `sessionStorage` の使い捨て UUID なので:

- 同じ人が別タブで開けば 2
- 同じ人が翌日また来れば 2
- ストレージが使えない端末は null で、`distinct` に 1 つしか立たない

**したがって人数ではない。** タブの数に近い。
人数の上限でも下限でもない。

それでも持っているのは、**同じ日の中での相対比較**には使えるからである。
記事 A が 100、記事 B が 10 なら、A のほうが多く読まれている。

画面はこれを「訪問者数」と呼ぶが、
提示層（feat-blog-scoped-admin-console）が
何の近似かを併記する責務を持つ。

## 送信

| 状況 | 手段 |
|---|---|
| 溜まった（40 件） | `fetch` + `keepalive` |
| 離脱時 | `sendBeacon` |
| `sendBeacon` が無い環境 | `fetch` + `keepalive` に落ちる |

再送はしない。**壊れているときほど負荷が上がる**ため。

送信が例外を投げても外へ漏らさない。計測の準備全体が
`try/catch` で包まれており、落ちても本文は描かれる（条件 10）。
