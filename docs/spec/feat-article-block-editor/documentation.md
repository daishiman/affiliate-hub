# 記事エディターの使い方 (P12)

- feature: `feat-article-block-editor`
- 対象読者: 記事を書く人

現在のローカル実装の操作説明です。リモートへの公開状況と画像転送方式の確認状況は[release.md](./release.md)を参照してください。

## 1. 記事は「節」と「断片」の 2 層でできている

```
記事
├── 節 (見出しは必ず大きい見出し)
│   ├── 断片: 段落
│   ├── 断片: 小見出し
│   └── 断片: 画像
└── 節
    └── 断片: 表
```

- **節** = 記事の章。見出しの大きさは常に同じ (`h2`)
- **断片** = 節の中身。小見出しは `h3` か `h4` だけ

**見出しの大きさは自分で選べません。** これは制限ではなく、
記事の骨組みを守るためです。目次も、検索エンジンも、AI も、
この骨組みを読んで「何について書かれた記事か」を判断します。
編集中に見出しの大きさが動くと、記事の意味が勝手に変わってしまいます。

断片を上下に動かしても、消しても、貼り付けても、大きさは変わりません。

## 2. 断片の入れ方

空の行で **`/`** を打つと、入れられる部品の一覧が出ます。
続けて文字を打つと絞り込めます。名前でも読みでも当たります。

一覧は 5 つの群に分かれています。

| 群 | 入っているもの |
| --- | --- |
| **文章** | 段落 / 小見出し / 引用 / 注意書き / プログラム |
| **一覧** | 箇条書き / 番号付き / やることリスト / 折りたたみ |
| **見せ方** | 画像 / 画像の横並び / 2 段組み / 区切り線 |
| **データ** | 表 / 比較表 |
| **差し込み** | 商品カード / リンクカード / ボタン / 埋め込み |

全部で 19 種類あります。

## 3. 記号は打たなくていい

`**太字**` や `` ```コード``` `` のような記号を覚える必要はありません。
「本文プレビュー」で読者向けの見た目を確認できます。編集時の入力欄や操作ボタンは公開されません。

たとえばプログラムを載せるときは、言語を選ぶ欄と本文の欄が別々に出ます。
` ``` ` を自分で打つことはありません。

表も同じです。`|` を打つのではなく、行と列を足すボタンで作ります。

## 4. 商品カードは「探して選ぶ」

商品カードを入れると、検索の欄が出ます。
商品名を打つと候補が出るので、そこから選びます。

**商品の id を打ち込む欄はありません。** わざとです。
id は人が覚えて打つ値ではないので、打てるようにすると打ち間違えます。
打ち間違えた記事は、公開して初めて壊れているのが分かります。

もし商品を探す仕組みが動いていない画面では、
「id を打ってください」とは言わず、**「今は挿せません」**と出ます。

## 5. 画像はファイルを選ぶだけ

画像を入れると、ファイルを選ぶ欄が出ます。選ぶと送信され、
保存の完了を確認できた画像が記事に入ります。送信エラーが出た場合は再度選び直してください。

**画像の URL を打ち込む欄はありません。**

| 決まり | 値 |
| --- | --- |
| 使える形式 | PNG / JPEG / WebP / GIF |
| 大きさの上限 | 8 MiB（8 × 1024 × 1024バイト） |

SVG は使えません。SVG は見た目は画像ですが、中身はプログラムを書ける文書なので、
記事の挿絵としては受け取らない決まりにしてあります。

**代替文 (alt) は必ず書いてください。** 目が見えない読者には、
これが画像の中身そのものになります。

### 入れた画像を消したとき

記事から外した画像は直ちには消しません。一度も保存記事に使われなかった画像は送信から24時間、使った画像は外した保存時刻などの最終参照記録から30日の猶予があります。
他の記事や復元用本文などに参照が残っていれば回収しません。日次処理のため、猶予が過ぎた瞬間に必ず消えるわけではありません。

回収が始まった画像は同じIDで戻せません。古い端末下書きの画像が保存時に拒否された場合は、画像を選び直してください。
公開記事から参照されない画像は、ログインなしでは取得できません。

## 6. リンクの行き先

埋め込み・ボタン・リンクカード・文中のリンクには、行き先の URL を打つ欄があります。
これは画像の話とは別で、行き先そのものが断片の中身だからです。

行き先が通らない書き方のときは、保存する前にその場で教えます。

埋め込みに使えるのは次のホストだけです。

- YouTube / Vimeo / Spotify / Google マップ

他のホストは埋め込めません。埋め込みは、そのホストに
読者の画面の一区画を明け渡す操作なので、相手を選んでいます。

## 7. 昔書いた記事はどうなるか

記事本文を一括変換する移行は行いません。既存形式の読み取りと、収集済みの保存例の往復を検証しています。
ただし、全既存記事を開いて保存し直した確認ではありません。重要な記事は本文プレビューで内容を確認してから保存してください。
互換性の検証範囲は[要求ベースラインのA7](./requirements-baseline.md)に記録しています。

## 8. 編集と保存の操作

「章を1つ足す」は記事の骨組みを追加します。章の中の「追加」または空段落の`/`で本文ブロックを選びます。検索欄で絞り込み、上下キーで選び、Enterで挿入、Escapeで閉じます。

文章のEnterは前後へ分割します。日本語変換中のEnterでブロックを分けません。「複製」「元に戻す」「やり直す」で本文操作を調整できます。

記事の公開状態と保存状態は画面下部に表示します。端末下書きはサーバー保存とは別です。保存競合が出た場合は内容を確認してから再読込してください。公開権限がない人は下書きを編集でき、公開中の記事の変更は公開担当者が行います。

構造化された結論・FAQ・仕様などは専用欄で編集します。内部のJSONを入力する必要はありません。

## 9. 商品の掲載位置を変えるとき

配置の保存・削除は記事本文と公開表示も一緒に更新します。公開中の記事には公開権限が必要です。
別画面で本文が先に保存されていた場合は競合になり、古い本文で上書きしません。最新版を確認してやり直してください。
削除済みの記事の配置を変える場合は、先に記事を復元します。台帳の変更後に監査記録だけ失敗した案内が出たときは、まず保存後の一覧を確認してください。
