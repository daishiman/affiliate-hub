# 最終レビュー — ブログ独自ドメイン

## 判定

**条件付きで受け入れる。** 住所層としての設計・保存・操作・権限・監査は成立しており、
既定住所を壊さない性質が試験で固定されている。ただし**公開経路への配線が残っている**
ため、この feature 単独では「独自ドメインでブログが開く」に到達しない。

## 良い点

1. **正本の割れ方を型で表している。** 「使う意思」(D1) と「検証の事実」(外部) を
   別のポートに分け、写しを保存する側だけが遷移表を通る。片方だけが遷移表を持つ
   設計だと、定期同期が運用者の取り下げを上書きする。
2. **止めることを外部の可用性に依存させていない。** 取り下げは D1 を先に落とす。
   外部 API が落ちている間も配信は止まる。この順序に試験が付いている。
3. **既定住所を行にしなかった。** 行が無いことが既定住所であるため、住所表を丸ごと
   落としてもブログは読める。移行を戻す手順が「表を落とす」だけで済むのはこの帰結。
4. **`revoked` を終端にし、部分ユニーク索引でそれを支えている。** 取り下げを
   「行の復活」ではなく「新しい行」で表す形が、両方の場所で一貫している。

## 残っている問題

| id | 内容 | 引き継ぎ先 |
|---|---|---|
| — | 失敗理由を掲出する画面の試験が無い (A9) | `test-cases.md` 覆えていないもの |
| — | HTTP を投げて 200 を確かめる試験が無い (A3 の端から端まで) | `tests/e2e/` |

FIND-1 (入口未配線) と FIND-2 (公開 canonical) はこの feature の中で解決した。
経緯は `design-review-findings.md` に残してある。**FIND-2 は当初「FIND-1 に従属する」
と判断したが、これは誤りだった**ことも併せて書いた — FIND-1 だけを解くと、公開ページが
`/s/<URL名>` を canonical に配り、それは配線後には 404 になる。

## 引き受けた代償

| 代償 | 上限 | なぜ受け入れたか |
|---|---|---|
| 取り下げてから配信が止まるまでの遅れ | 60 秒 | 短くするほど edge から D1 への往復が増える。取り下げの理由はたいてい「間違えて繋いだ」で、1 分の遅れは許容できる |
| canonical を降ろしてから宣言が変わるまでの遅れ | 60 秒 | 読者の転送ではなく検索エンジンへの宣言なので、遅れの害はさらに小さい |
| 入口が住所表を引けないときの倒し方 | — | 「引けない＝本体の画面」。通行証とは**逆向き**。揃えると D1 の一瞬の不調で管理画面まで 404 になる |

## 要求との意図的な差

- 切断の確認は「ブログ名の一致入力」ではなく「理由の記入必須」(FIND-3)。
- 権限は要求より厳しい (`publisher` 役も実行不可、FIND-4)。

いずれも `acceptance-report.md` A7 に判定として記録済み。差を黙って埋めていない。
