# リリースノート — ブログごとの住所（独自ドメイン）

## できるようになったこと

- ブログ 1 本ごとに、自分で取ったドメインを繋げるようになりました。
  `/admin/sites/<ブログ>/domains` から登録し、DNS に置く設定を画面で受け取り、
  所有権が確認できるまでの進み具合をその場で見られます。
- 登録した住所のうち 1 つを「正規の住所」に指定できます。
- 止めたいときは理由を書いて取り下げます。行は消えず、いつ・なぜ止めたかが残ります。
- 同じドメインを 2 つのブログへ同時に繋ぐことはできません。取り下げた後なら
  同じドメインをもう一度登録できます。
- 接続・確認・切替・取り下げは、すべて監査記録に残ります。

## 変わらないこと

**既定の住所 `/s/<URL名>` は取り上げられません。** 独自ドメインが証明書待ちでも、
検証に失敗しても、取り下げても、読者はこれまでどおりブログを読めます。
独自ドメインは既定住所の**置き換えではなく上乗せ**です。

## 反映に最大 1 分かかります

住所を切り替えたり取り下げたりしたあと、**実際に反映されるまで最大 1 分**かかります。

これは不具合ではなく、決めて受け入れた仕組みです。読者が 1 ページ開くたびに住所表を
引きにいくと、表示が遅くなります。そこで「1 分の間は前に引いた答えを使い回す」ように
してあります。裏返すと、取り下げた住所は 1 分だけまだ生きています。

**止まったことを確かめるときは、1 分待ってからにしてください。**

## まだできないこと

- 住所の状態を定期に見張って期限切れを知らせる仕組みは、別の feature の担当です。
  当面は管理画面を人が開いて確かめます。
- 検証に失敗した理由の文言そのものは Cloudflare が返す言葉です。日本語に置き換えて
  はいません (置き換えると原因が分からなくなるため)。

## 権限

住所を変えられるのは `site.manage` を持つ役 (owner / workspace_admin / brand_manager) です。
記事を書く人は**一覧を見ることはできます** — 自分の記事がどの住所で読まれるかは
知る必要があるためです。

## 移行

新しい表を 1 つ足すだけです (`drizzle/0044_funny_groot.sql`)。既存のデータは変わりません。
戻すときは表を落とすだけで、ブログは既定住所で読めたままです。
