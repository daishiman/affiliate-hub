# 運用手順 — ブログ独自ドメイン

## 平常時

### 住所を繋ぐ

1. `/admin/sites/<ブログ>/domains` を開く。
2. 「住所を追加する」にドメイン名を入れる (`https://` やパスは付けない)。
3. 「DNS に置く設定」に出た行を、ドメインの DNS へ置く。**置くまで読者は開けない。**
4. 行の「状態を取り直す」を押す。`所有権を確認中` → `配信中` へ進む。
5. `配信中` になったら「これを読者へ見せる」を押す (正規の住所になる)。

DNS の反映には時間がかかる。`所有権を確認中` のまま進まないときは、置いたレコードの
名前と値が画面の表と 1 文字ずつ一致しているかを確かめる。

### 住所を止める

行の「取り下げる」に**理由を書いて**実行する。理由は行に残り監査記録にも入る。
取り下げた住所を踏んだ読者はどこにも着かない。読者は既定住所 `/s/<URL名>` で
引き続き読める。

## 困ったとき

| 症状 | 見るところ | 対処 |
|---|---|---|
| 「外部への申し込みができていません」と出た | Cloudflare の鍵が実行環境に入っているか | 鍵を入れてから行の「状態を取り直す」。登録は消えていない |
| 「このドメインはすでに登録されています」 | 他のブログが同じ hostname を生きたまま持っている | 先にそちらを取り下げる。取り下げ済みなら再登録できる |
| `確認できませんでした` になった | 行の「直近の失敗」の文言 | DNS を直してから「状態を取り直す」。`pending` へ戻って再試行できる |
| 取り下げたのに課金が続く | `notice` に「外部側の登録が残っています」と出ていないか | 時間をおいて再度取り下げを実行する。読者への配信はすでに止まっている |
| 独自ドメインで開いてもブログが出ない | `配信中` になっているか / 切り替えてから 1 分経ったか | 下記「切り離しと切り替えの反映」。1 分待っても出ないなら DNS と証明書を疑う |

## 切り離しと切り替えの反映 — **最大 1 分かかる**

入口は住所表の写しを**60 秒**持つ。これは意図した設計で、edge から D1 への往復を
要求ごとに増やさないための代償である (`host-resolution-design.md`)。

- **取り下げたあと、最大 1 分は読者がまだブログに着く。** 「止まったこと」を確かめるのは
  1 分待ってから。すぐに確かめて「止まっていない」と判断しないこと。
- **新しく `配信中` にしたあと、最大 1 分は開かないことがある。** ただしこれは
  「見つからなかったことも写す」ためで、そのホストへ一度も要求が来ていなければ
  すぐ開く。開かないときは 1 分おいて試す。
- **canonical の切り替えも同じ 1 分。** こちらは検索エンジンへの宣言なので、
  読者から見た挙動は変わらない。
- 急いで反映させたいときの確実な手段は無い。写しはワーカーの隔離ごとに持つため、
  配置し直す (deploy) と空になるが、**それを運用手順にしない** — deploy を
  キャッシュ削除の道具にすると、急ぎの取り下げのたびに本番を触ることになる。

### 独自ドメインで開かないときの見分け方

| 症状 | 疑うところ |
|---|---|
| 1 分待っても 404 | 住所の状態が `配信中` か。`確認中` `失敗` では配信しない (仕様) |
| 1 分待っても本体の画面 (管理画面) が出る | DNS がこの Worker に向いていない。届いていないので入口も判断できない |
| ブログは出るが `/admin` が 404 | **正しい動作**。ブログの住所から管理画面は開かせない |
| 管理画面まで 404 になった | D1 が落ちている疑い。住所は「引けない＝本体の画面」に倒すので、住所層は原因ではない |

## 監視

住所の状態を定期に見張る仕組みはこの feature に無い (`feat-blog-scoped-admin-console` の
責務)。当面は `/admin/sites/<ブログ>/domains` を人が開いて確かめる。
証明書の期限切れは `active → failed` として写し取られるので、`確認できませんでした` の
行が現れたら失効を疑う。
