# テストケース — 日次集計 (feat-blog-metrics-rollup)

P04 の成果物。実際に書かれたケースの一覧。名前は実装のまま。

## `tests/application/rebuild-daily-metrics.test.ts`（再実行の入口・18 件）

### 権限

- 運営できる人は、指定した日をやり直せる
- 数字を見るだけの人（analyst）は、やり直せない

`requireCapability(actor, "site.manage", ...)`。画面に出る数字を作り直す操作なので、
記事を書く権限では足りない。

### やり直してよい日の線引き

- 今日はやり直せる
- まだ来ていない日は断る
- 保持期限の内側の、いちばん古い日はやり直せる
- **保持期限より前の日は断る（ここが 0 上書きの入口になる）**
- 日付の形が違えば、集計を呼びに行かない

境界（90 日ちょうど）を両側から挟んである。片側だけだと off-by-one が通る。

### 巻き込み防止

- どのブログか言われなければ断る
- 同じ日の別のブログを巻き込まない
- 他の作業場所の同名ブログを巻き込まない
- 数え上げに渡す日が、指定した 1 日だけである

### 観測が無い日

- その日に観測が無ければ、0 件として返し、書きに行かない

`missing-data-policy.md` の「0 の行を書かない」の検証。

### 記録

- 1 回の操作につき、記録は 1 行
- 記録を書けなければ、成功として返さない
- 集計に失敗した回も記録に残したうえで、失敗として返す

記録が書けなかったのに成功を返すと、「誰が数字を作り直したか」が
追えない状態が黙って生まれる。

## `tests/integration/d1-reader-metrics.test.ts`（実 D1・15 件）

### 冪等（受入条件 1）

- **2 回集計しても数字が二重にならない（足し込みではなく置き換え）**
- **再集計しても売上と成約は消えない（読者側と成果側で書き手が違う）**

2 件目が F-02 の対処の検証。`set` から `revenue_minor` / `conversions` を
外していることを、実 D1 の upsert で確かめる。

### 合算（受入条件 3・4）

- 記事ごとの内訳と全体の合計が食い違わない

**このケースは「一致」ではなく「食い違わない」と名付けてある。**
記事外の閲覧がある日には `Σ記事 < ブログ` になり、それは食い違いではない。
検証しているのは不等号と、記事に紐づく分の一致である。

### 保持期限（受入条件 5）

- 期限を過ぎた生イベントは捨て、集計は残す

### 数え上げ

- 集計し直す組は、生イベントの側から数え上げる
- 窓の外の日は数え上げない
- 上限を超えたぶんは返さない（次の回で拾う）
- 他の workspace の観測は混ざらない

### その他

- 何件の観測から作った数字かを、集計の行が持って出る（`sample_count`）
- まとめて受け取り、件数を返す
- 集計日は受け取り側が発生時刻から決める（端末の時計を信用しない）

最後の 1 件が重要で、`rollup_day` をクライアントに決めさせない。
端末の時計は簡単にずれるし、意図的にずらすこともできる。

## `tests/application/read-blog-metrics.test.ts`（読み口の分離・10 件）

### §12.3 の口の分離

- **audience の行は revenueMinor という鍵を持たない**
- 分析担当は読者も売上も見られる
- 記事を書く人は、読者も売上も見られない
- 問い合わせる作業場所は、頼んだ人の作業場所である

1 件目が型だけでなく実行時にも売上が漏れないことの検証。
`Omit<>` は型の話なので、実際の返り値にキーが残っていても型検査は通る。

### 画面幅での絞り込み

- 画面幅で絞ると、同じ記事でも別の分布になる
- 画面幅を指定すると、その幅が保存先まで届く
- 画面幅を指定しなければ、絞らずに引く
- **画面幅で絞っても、どんな読者が来ているかの内訳は絞らない**

3 件目・4 件目が「絞り込みが保存側で行われる」ことの検証。
画面側で後から間引くと、到達率の分母が変わって別の意味の値になる。

### 0 除算と欠損

- 読者の内訳は、来ていない区分も 0 で埋まる
- 要素別のクリック率は、表示が 0 の日を 0 として畳む
- まだ誰も見ていない期間のクリック率は 0 で、null にしない
- 日ごとの行を足し、クリック率まで含めて返す

### 責務の境界

- ブログ全体では、どこを見ているかを返さない
- 記事を指定したときだけ、どこに時間をかけているかを返す

ブログ全体の「読まれている位置」は意味を持たない（記事ごとに長さが違う）。
返さないことを型と実装の両方で守る。
