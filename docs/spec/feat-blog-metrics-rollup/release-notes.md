# リリースノート — 日次集計 (feat-blog-metrics-rollup)

P13 の成果物。何が使えるようになったか。

## できるようになったこと

ブログごと・記事ごとに、**日単位の数字が毎日たまる**。

| 見えるもの | どこで |
|---|---|
| ブログの PV・クリック・訪問者数・平均滞在・平均スクロール | `/admin/sites/[site]/audience` |
| 記事ごとの同じ数字 | 同上（記事を選ぶ） |
| ブログの売上・成約 | `/admin/sites/[site]/revenue` |
| 記事の売上順の並び | 同上 |
| その数字が何件の観測から出たか | 各画面（`sample_count`） |
| いつ計算した数字か | 各画面（`computed_at`） |

## 数字の性質について

### 記事の合計はブログの合計より小さい

トップページ・記事一覧・タグページの閲覧は、どの記事にも紐づかない。
それらはブログ全体の数字にだけ乗る。

```
Σ 記事の PV  ≤  ブログの PV
```

**この差は不具合ではなく、意味のある情報である。**
差が大きければ「入口には来ているが記事へ流れていない」ことになる。

### 観測が少ない日は数字だけ出る

観測が 30 件に満たない期間は、数字は出るが**解釈は出ない**。

> 観測が 12 件しかありません（示唆を出すには 30 件が要ります）。

件数を文面に入れてあるので、「あと少し待てば見える」のか
「そもそも人が来ていない」のかが分かる。

数字ごと隠さないのは、隠すと**計測が壊れていることに気づけない**ため。

### 生の観測は 90 日で消える

誰がいつ何を見たか、という細かい記録は 90 日で捨てる。
**日ごとに畳んだ数字はずっと残る。**

なので 90 日より前に戻って集計し直すことはできない。
逆に言えば、90 日以内なら何度でもやり直せる。

## 運営者ができる操作

`/admin/sites/[site]/audience` の「この日をやり直す」で、
指定した 1 日ぶんを計算し直せる。

- 権限は `site.manage`。数字を見るだけの人は押せない
- 1 回 1 日。まとめて範囲指定はできない
- **やり直しても売上は消えない**（読者側の数字と売上は書き手が違う）
- 押したことは操作の記録に残る

## 内部の変更

| 種類 | 内容 |
|---|---|
| 表 | `reader_interaction_event` / `site_daily_metric` / `article_daily_metric` |
| migration | `0044_funny_groot.sql` / `0045_keen_mysterio.sql` |
| 定時実行 | UTC 17 時。集計 → 掃除の順（順序は固定） |
| 読み口 | `BlogAudiencePort`（売上抜き） / `BlogRevenuePort`（売上つき） |

**読み口を 2 つに分けた**ので、記事を書く担当の画面には
売上が型の上でも実行時にも渡らない。

## 既知の制限

1. migration 0045 より前に作られた集計行は `sample_count` が 0 で、
   「観測 0 件」と区別できない。その日をやり直せば直る
2. 要素の識別子を振っていない場所のクリックは、要素別の内訳に出ない
   （ブログ全体のクリック数には入る）
3. 3 日以上続けて集計が失敗すると自動では戻らない。手でやり直す
4. cron が定時に起動することは、こちらのテストでは確かめていない。
   `computed_at` を見て気づく運用にしてある
