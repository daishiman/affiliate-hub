# 共通UI

管理画面と公開ブログが共有する、見た目・操作・画面骨格の公開入口。
画面からは `@/presentation/ui` (`index.ts`) を読み、内部ファイルを直接読まない。

## 入っているもの

| 公開面 | 役割 | 正本 |
|---|---|---|
| tokens / themes | 色・余白・文字・明暗・配色 | `tokens.css` → `tokens/` (`themes.css`を含む) |
| primitives | Button、Field、Select、状態表示など単体部品 | `primitives/` |
| patterns | フォーム結果、絞り込み、比較、配信状態など複合部品 | `patterns/` |
| templates | 管理画面・公開ブログ・記事の骨格 | `templates/` |
| 管理route | 49画面の実URL、親子、ナビ、分類、パンくず | `admin-route-metadata.ts` |
| 文言・計測属性 | 共通文言、telemetry属性 | `copy.ts` / `telemetry-attrs.ts` |

## 決めてある作法（全画面で同じ）

1. **空欄は「未入力」。** 0 とは区別する。空欄を 0 と読み替える処理を書かない。
2. **自動計算値は欄の中に初期値として入れる。** 由来を 1 行添える。書き換えたら「自動計算に戻す」が出る。
3. **Enter は次の欄へ進む。** 送信はしない。送信は主操作のボタンだけ。
4. **「必須」ではなく「任意」に印を付ける。** ほとんどが必須なので、少ない方を目立たせる。
5. **主操作は 1 画面に 1 つ**（`tone="primary"`）。取り消せない操作は `tone="danger"`。
6. **実行中は部品が自分で押せなくする。** 二重送信を画面ごとに気をつけない。

## 4つの状態と理由表示

一覧・詳細・検索結果は必ず次を持つ。

- 読み込み中 → `LoadingView`
- 空 → `EmptyView`（**なぜ空か** + 次にできること）
- 失敗 → `ErrorView`（**何が起きたか** + 復帰の導線）
- 操作できない → `Callout`（**なぜできないか** + 解決画面への導線）

`EmptyView` / `ErrorView` の `title` と `body`、`Callout` の `reason` はすべて必須にしてある。
理由の条件式が成立せず画面が無言になる不具合が起きやすいため、
書き忘れを型検査の時点で止める。

## 現在地と退避先

`AppShell` が左の案内（現在地を太字 + `aria-current`）と、右上に固定した退避先（保存・戻る・次へ）を持つ。
**画面側でヘッダーを組み直さない。** 適用しない画面は次の 2 つだけで、理由もそこにある。

| 適用しない画面 | 理由 |
|---|---|
| ログイン画面 | 作業の途中が無く、退避先の概念が要らない |
| 公開ブログの読者向けページ | 管理画面ではない。読者向けの案内を別に持つ |

管理画面を増やすときは `admin-route-metadata.ts` に1件だけ足す。
`ADMIN_NAV`、`ADMIN_NAV_GROUPS`、パンくず、描画テストのroute表はそこから派生する。
各画面は `AdminShell` に `routeId` と動的パラメータだけを渡し、実URLや親ナビを
書き写さない。`actualRoutePath` は計測・改善要望の出所、`navContextPath` は
サイドバーの現在地だけに使い、同じ値で二つの責務を兼ねない。

## 動きの決まり

- 動きは因果の説明だけに使う（何がどこから来たか）。装飾の動きは付けない。
- 入場は最大 6 要素・全体 300ms 以内。
- `prefers-reduced-motion` で動きを消す指定は `tokens.css` に入っている。部品側で上書きしない。
- hover が無い端末（タッチ）でも全操作が届く。hover だけで出る情報を作らない。
- 触れる的は 44px 以上（`--tap-target-min`）。
