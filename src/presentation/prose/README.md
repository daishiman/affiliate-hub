# 記事本文の層 (`src/presentation/prose`)

記事の**本文**を、公開面と管理画面で同じ規則のまま描く・書くための部品を置く。

## なぜ `ui/` の中ではないのか

`src/presentation/ui` は「渡されたものを出すだけ」の層で、`@/domain` を読まない。
`tests/ui/ui-layers.test.ts` がそれを機械で見ている。

本文の断片 (`ProseNode` / `parseProse`) は `@/domain/blogops` にある。
描く側は必ずそれを知る必要があるので、共通UIの決まりとは両立しない。

**決まりを緩めるのではなく、置き場所を分けた。**緩めると、次に業務のきまりを
持ち込みたくなった部品が同じ言い訳で入ってくる。共通UIが業務を知り始めると、
ブログを 1 本足すたびに共通部品を触ることになる。

## なぜ `site/` にも `admin/` にも置かないのか

同じ断片を**同じ規則で**描くのが公開面と管理画面の両方だからである。
描き方が 2 か所にあると、編集中に見えていたものと読者が見るものがずれる。
ずれた側は誰も気づかない——運営者は自分の画面しか見ない。

## 依存の向き

```
site / admin / app  ──▶  presentation/prose  ──▶  presentation/ui
                                  │
                                  └──▶ domain/blogops
```

`presentation/ui` からこの層へ向かう線は引かない。引いた時点で、
共通UIが本文の断片を知ってしまう（`ui-layers` の検査は `@/domain` の直の
読み込みしか見ないので、間に 1 枚挟むと素通りする）。

## 置いてあるもの

| ファイル | 何を持っているか |
| --- | --- |
| `prose-body.tsx` | 断片を**読む形**で描く（公開面と編集中のプレビューが同じ結果になる） |
| `prose-editor.tsx` | 断片を**書く形**で描く。`/` のメニューはここ |
| `prose-section.tsx` | 節（見出し + 本文）1 つぶん |
| `prose-table-frame.tsx` | 比較表の枠。中身の描き方だけを読む側／書く側から渡す |
| `prose-outline.tsx` | 目次と、節に打つ錨の名前 (`blockAnchor`) |
| `prose.module.css` | 上の見た目 |

**枠と名前を 1 か所にしてあるのは、直す場所を 1 つにするため。**
比較表の骨組みを読む側と書く側の両方に書くと、横に流す包みを片方だけ直した日に
「記事によって挙動が違う」ことになる。目次のリンク先と節の `id` も同じで、
片方だけ書き方を変えるとリンクは無い場所を指し、気づくのは読者だけになる。
