##### 接地根拠 qa-uiux-web-top-composition-v6 (対応セル: web)

- 本文: 「確定内容 (質疑録)」の `qa-uiux-web-top-composition-v6` を参照
- 設計解釈の記録経路: `dialogue`
- 原則: 束ねる順は、その面で読み手が果たそうとしている用事の頻度と、外したときの損の大きさで決める (`ref-system-design-knowledge:information-design`)
  - 採否: `applied`
  - 章固有の根拠: トップページで読者が果たそうとする用事は 3 つに束ねられる — 『何のブログか掴む』『今読むべき記事を選ぶ』『目当ての話題へ移る』。頻度は 2 番目が最も高く、外したときの損は 1 番目が最も大きい (何のサイトか分からなければ他の全てが無意味になる) ため、面の上端から この順で置く。サムネイルは 2 番目の束に属する部品であり、記事の内容を想像させて選択を助ける役割を負う。よってトップの一覧ではサムネイルを大きく扱い、題名と対等な重みで置く。一方で 3 番目の束 (カテゴリへの移動) にサムネイルは要らない — カテゴリは概念であって記事ではないため、画像を与えると記事と見分けがつかなくなる。利用者の『各画面』という語は表示場所を機能の水準で述べたものであり、どの部品にどの大きさで置くかまでは述べていないため、その具体化はここで行う
  - トレードオフ:
    - サムネイルを大きく扱うと 1 画面に収まる記事数が減り、3 番目の束へ到達するまでの距離が伸びる。カテゴリへの導線は追従ヘッダーの側に置き、一覧の長さに影響されない位置から届くようにする
    - 3 つの束の順を上から固定すると、再訪の読者にとっては毎回 1 番目を読み飛ばすことになる。1 番目は高さを抑え、スクロールの負担にしない
- 原則: 常に画面に留まる部品は、留まることで隠す面積の対価に見合う働きを持たせる (`ref-system-design-knowledge:usability-accessibility`)
  - 採否: `applied`
  - 章固有の根拠: 利用者はスクロール中もヘッダーが見えることを求めたが、追従するヘッダーは画面の上端を恒久的に占有し、その面積のぶん本文が読めなくなる。よってヘッダーに置くのは、どの記事を読んでいる最中でも要る機能に限る — サイト名 (今どこにいるか)、検索、カテゴリへの移動の 3 つ。記事内でしか使わない機能 (目次・共有・関連記事) はヘッダーへ置かず本文の流れの中に置く。加えて追従ヘッダーは、記事内の見出しへ移動したとき移動先の見出しをヘッダーの下へ隠す — この自己遮蔽は追従配置に固有の副作用なので、見出しの上余白をヘッダーの高さぶん確保して接地させる
  - トレードオフ:
    - ヘッダーに 3 機能しか置かないと、それ以外の機能への入口が本文の中に散る。散った入口を見つけられるよう、記事の面では入口の位置を記事をまたいで同じ場所に固定する
    - 小さい画面ではヘッダーの占有面積の比率が大きくなるため、下方向へのスクロール中は畳み、上方向へ動かしたときに戻す
- 原則: 機械が黙って変えたものは、変えられた側が後から必ず見つけられるようにする (`ref-system-design-knowledge:information-design`)
  - 採否: `applied`
  - 章固有の根拠: 反映方法が自動反映へ変わったことで、運営画面に要る面が『提案を承認する画面』から『機械が何をしたかを後から辿る画面』へ変わった。承認画面は運営者が来ないと先へ進まない面だったが、変更履歴の面は運営者が来なくても先へ進むため、来たときに何が起きていたかを取り戻せることだけが要件になる。よってこの面が備えるのは 3 つ — いつ何の記事のどこが変わったかの一覧、変更前と変更後の差分、そして 1 操作での取り消し。事後通知は見逃される前提で設計し、通知を見なかった運営者もこの面から全ての変更へ到達できるようにする。通知そのものを可逆性の担保にしない
  - トレードオフ:
    - 変更履歴の面は運営者が能動的に見に行かないと機能しないため、放置されると自動反映が野放しになる。直近の変更件数を運営画面の入口へ常に出し、見に行く契機を作る
    - 全ての変更を差分として保つと記録が増え続ける。取り消せる期間を定め、期間を過ぎた記録は要約へ畳む
